## 任务一:接线表的 X-14 条目 `gap` → `no-contract`

**为什么必须做**:门禁脚本的判据表里有一行 ——
「| 已实现 | gap | — | ✘ **自相矛盾**(gap 行的状态不可能是「已实现」)|」。
规范侧已把 X-14 翻成「已实现」,而接线表里它还是 `expect: "gap"` ⇒ **门禁会立刻红**。

**文件**:`script/conformance_registry_map.json`(仓库根)

**现**:

```json
"X-14": {
  "package": "wlwl-eval",
  "tests": ["x14_alias_in_loop_cost_contract"],
  "expect": "gap",
  "probe": "x14_the_write_sequence_must_reach_the_sequence_level_bound",
  "note": "别名**在写序列内部每轮重建** ⇒ 每轮写必须产出新值 ⇒ 总拷贝二次。目标测试 #[ignore]（红 ⇒ 缺口仍在）"
}
```

**改**成(照本表里 **X-08 / X-23** 两条 `no-contract` 的体例 —— 那两条**只有 `expect` + `reason`
两个字段**,没有 package / tests / probe / note):

```json
"X-14": {
  "expect": "no-contract",
  "reason": "消解行(文档类):该形态由语言核心册 §19.1 的值语义决定(每轮的快照都让旧值可观察 ⇒ 写必须产出新值 ⇒ 每轮拷贝整份)⇒ 与语言核心册 §18.3.1 第 2 条自相矛盾 ⇒ 依一致性册 §3.4 例外 2(规范缺陷修复)已把该形态排除在摊还承诺之外(规范仓总纲 §0.9 的 D-20)⇒ 规范侧 §5.4 的 X-14 行转「已消解」(类别「—」/ 状态「已实现」)。仓内无可挂的机器判据:该形态不是「实现没做到」,是值语义的内在推论"
}
```

`reason` 的措辞由你定,上面只是草稿;**要点**是写清「为什么没有可挂的契约判据」。

**验收**:

「有实现、待取证」**。规范侧要的就是这三条读数。

**要交回的三条可观察行为**(并发册 §17.0 的「宿主挂起」段 + 附录 H.3.10):

| # | 行为 | 怎么看见它 |
|---|---|---|
| ① | 恢复时从**当前段首重跑**(宿主挂起归**不切段**格 ⇒ 与阻塞型通道操作**同一格**) | 挂起点**之前**的代码被**重放** ⇒ 「挂起一次、执行两遍」的那句可观察(计数 / `PRINT` 的出现次数) |
