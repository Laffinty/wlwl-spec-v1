# WLWL v1.0 演进蓝图

> **本册是非规范的。** 它记录方向、已否决的方向与尚未立项的候选,**不构成**任何一致性要求。
>
> 本册描述的候选**均未进入 v1.0**。任何实现**不得**依据本册实现任何行为;用户**不得**依赖本册的任何承诺。
>
> 规范性内容唯一住在 L-规范层的 11 册里(层级定义见[总纲 §0.8](../spec/wlwl-v1.0-overview.md))。

## 1 v1.0 冻结了什么

v1.0 冻结的是**行为**,不是**可能性**。具体清单见[一致性册 §4.1](../spec/wlwl-v1.0-conformance.md)。三条边界值得写明:

1. **v1.0 冻结的是语义,不是实现。** §18 承诺的复杂度上界是**语义**(用户可依赖),§19 的资源释放责任是**语义**,但"用哈希表还是平衡树实现 `DICT`"不是 —— 那是实现注。
2. **v1.0 冻结的是公共面,不是全部文本。** 解释性说明、实现注、示例、路线图册随时可变(一致性册 §4.2)。
3. **v1.0 冻结的是"当前能被验证的行为"。** 一条只有规范、没有实现的条款,在 v1.0 发布前必须变成"有实现的条款"(一致性册 §3.5 第 1 条)。

## 2 已裁定的设计选择

本节记录**已经决定不做**的方向,以及决定做的理由。已裁定的方向不在后续版本重开 —— 重开需要走一致性册 §7.2 的裁决流程并留下记录。

### 2.1 模块别名 —— 不引入

**决定**:v1.0 **不**引入模块别名(命名空间级别的短名绑定)。

**理由**:WLWL 按设计**没有命名空间限定调用表达式** —— 文法里不存在 `ns.MEMBER(...)`,冒号只出现在 `IMPORT` 的路径字符串与改名处(语言核心册 §10.6)。命名冲突的正规解法已经存在:`IMPORT(path, ["orig": "alias"])` 的改名形态。少了限定调用,一个"模块别名"能提供的东西就只剩"缩短导入路径",而那恰恰是**可以由 `IMPORT` 直接取裸名**做到的。

**推论**:在 WLWL 的语法里,"模块别名"没有对应的概念空间。引入它等于引入限定调用,那是**语法层面的重设计**,不是 v1.0 的补丁。

### 2.2 续体(continuation)保存 —— 不进入 v1.0

**决定**:v1.0 **不**保存续体。挂起模型维持现状:**让出控制再回来,恢复从挂起点之后继续**。

**理由**:v1.0 的职责是**把已有行为说准**,不是引入新行为。把"保存续体"写进 v1.0 等于宣布一个尚未实现的语义 —— 那会让规范第一次对实现说谎。

**v1.0 实际做的事**:把现有的挂起/恢复规则形式化(并发册 §17.0.1、附录 H),包括那条最容易被误读的区分 —— `YIELD` **切段**(恢复从下一段开始),阻塞型通道操作**不切段**(恢复从段首重跑,挂起点之前的代码会重放)。这两条在 v0.11 里以散文形式存在,交叉引用容易断;形式化之后它们才真正成为可核验的条款。

### 2.3 性能注解 —— 不进入语言表面

**决定**:v1.0 **不**引入 `@complexity(O(n))` 之类的注解。

**理由**:注解若不强制,实现可以忽略它,用户不能依赖它 —— 那它是一段注释;注解若强制,实现必须能在编译期判定函数体的实际复杂度 —— 那是可执行复杂度检查,是一项独立的大工程,不是 v1.0 的补丁。

**v1.0 实际做的事**:承诺**可兑现的复杂度上界**(语言核心册 §18),并给出高成本操作的推荐写法。凡写不出的上界,宁可标为实现定义,也不写一个兑现不了的数字。

### 2.4 字符串构建器 —— 不进入语言表面

**决定**:v1.0 **不**引入字符串构建器**构造**。

**理由**:它是标准库成员,不是语言构造。语言册为它开一条,等于让语言表面替标准库背书。

**归属**:是否提供、以什么形态提供,属标准库范畴,见 §3.3。

### 2.5 内存管理策略 —— 单一策略成文,不提供可选项

**决定**:v1.0 规定**一套**内存与资源模型(语言核心册 §19),**不**提供编译期可选策略(引用计数 / 追踪式 / 手动)。

**理由**:提供选项意味着每种组合都要被规范覆盖,规范规模按组合数增长,而不按语言规模增长。v1.0 选"少而准"。

**归属**:多种策略是**未来的**语言级决策,见 §3.2。

### 2.6 附录 A —— 从活镜像改为冻结快照

**决定**:标准库·注册镜像册的附录 A 在 v1.0 冻结为**快照**,不再由生成器从实现清单实时产出。

**理由**:活镜像意味着规范文本随实现漂移 —— 这与"规范即法律"直接冲突,且让规范版本号失去意义(内容会自己变)。冻结快照 + 一致性册 §3.5 第 3 条的逐项对拍要求,能在"规范稳定"与"实现跟上"之间保住可核验的连接。

## 3 尚未立项的候选

本节列出**可能**进入 v2 或更后的方向。它们**不是**承诺,连时间表都没有。

### 3.1 语言级候选

| 候选 | 内容 | 前置条件 |
|---|---|---|
| **续体保存** | `YIELD` 保存续体,恢复从挂起点**之内**继续;消除阻塞型通道操作的段首重放 | 需要先裁定"续体的数据形态"(是快照还是真状态机);实现侧的工作量远超规范侧 |
| **可执行复杂度合同** | 把复杂度上界编码进类型或注解,实现不符即编译失败 | 需要一门能判定函数体复杂度的分析器;§18 的静态上界只是它的弱化前提 |
| **多种内存策略** | 编译期在引用计数 / 追踪式 / 手动之间选择 | 需要先定义"策略选择"本身的语义与诊断 |
| **命名空间限定调用** | 引入 `ns.MEMBER(...)`,从而使"模块别名"重新有概念空间 | 语法级重设计,牵动 §9 模块系统与全部标准库册的成员表 |

### 3.2 错误模型候选

| 候选 | 内容 | 前置条件 |
|---|---|---|
| **容器内义务追踪** | v1.0 的 `E0103` 只追踪绑定持有的 `ERR`;把 `ERR` 装进数组/字典后再丢弃容器,本版不报 | 需要定义"容器吸收义务"后的拷贝语义(§2.1 的理由:值是深拷贝) |
| **未消费 `ERR` 的静态检查** | 在编译期就报出"可能未处理",而不是运行期 | 需要一个对动态语言的流敏感分析;会产生误报,得先定误报容忍度 |
| **错误上下文的自动补全** | 传播路径自动携带调用栈与来源 | 属 `WRAP` 的现有能力(语言核心册 §8.3)的自动化推广 |

### 3.3 标准库候选

| 候选 | 内容 | 归属理由 |
|---|---|---|
| **字符串构建器** | 大量拼接的推荐写法与高效实现 | 标准库成员,非语言构造(§2.4) |
| **惰性视图** | `WINDOW` / `MAP` 等的惰性形态,消除 §18 里"定义本身产出 Θ(n·k) 个元素"的成本 | 标准库成员 |
| **`DICT` 的键类型扩展** | 当前键限 `STRING` / `INTEGER` / `INSTANCE`;放宽会牵动相等与哈希语义 | 语言核心册 §2.1 的值域表,属语言级 |

### 3.4 工程化候选

| 候选 | 内容 |
|---|---|
| **规范—实现对拍自动化** | 把一致性册 §6.1 的七条检查做成 CI 门禁,规范仓与实现仓共用 |
| **条款级测试追溯** | 每条规范条款挂一个测试用例,测试即条款的可执行形式 |
| **多实现一致性测试套件** | 一套不依赖任何具体实现的合规性测试,任何实现都可跑 |
| **未消费 `ERR` 令牌的表示收敛** | 一致性册 §5.4 的 X-06 / X-07:一个绑定只持有一个布尔令牌 ⇒ 容器里多个未消费 `ERR` 只记得住一个;标准库回调的实参通道不带令牌 ⇒ 回调内未消费的 `ERR` 漏报。两者都只产生**假阴性**(漏报),不产生假阳性 |
| **破坏性变更的测试迁移工具** | v1.0 的 `E0103` 一次性让 22 个既有测试函数变红。逐条归因(依赖旧行为 / 需改写)是人做的;工具化的部分 —— 识别「只观察未消费 `ERR`」的惯用法并给出改写建议 —— 可以自动化 |

v1.0 的规范文本与实现的追赶计划**分属两处**,不在同一册里混写:
