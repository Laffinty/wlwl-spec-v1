# WLWL 对象与行为类型规范 v1.0

本册定义 WLWL 的**对象模型**、**行为类型(会话类型协议)**与**线性 capability**,以及对象与并发的交互规则。

- **类是值**。`CLASS` 产生类对象,`NEW` 产生实例;两者都按引用共享(语言核心册 §19.6)。
- **协议约束次序**。类**可以**声明一个会话类型协议,约束其实例上方法调用的合法次序(§14)。
- **`THIS` 是线性的**。每次方法调用内至多消费一次,**不得**逃出该次调用的动态范围(§15)。

词法、类型与值、错误模型与诊断码表见[语言核心册](wlwl-v1.0-language.md);并发见[并发册](wlwl-v1.0-concurrency.md);标准库成员的签名与语义见[标准库册](../stdlib/)。

> **上游基线**:`Laffinty/wlwl` 提交 `56b9fb6`(2026-10-22,含 v1.0 语义第一批:`D-01`/`E0103`、`X-05` 与 `X-09` 收敛)。
> 核实日期:2026-10-22。核实方法与要求见[一致性册 §6.3](wlwl-v1.0-conformance.md)。

## 0 导言

本册定义 WLWL 的对象模型(§13)、行为类型与会话类型协议(§14)、`THIS` 与线性 capability(§15),以及 OOP 与并发的交互(§16)。

### 0.3 规范性用语

本册中的关键词 **必须**(MUST)、**不得**(MUST NOT)、**应当**(SHOULD)、**可以**(MAY)按以下含义使用:

- **必须 / 不得**:实现的硬性约束。违反时实现必须产生一个诊断(语言核心册 §11)并按语言核心册 §11.4 终止或报告。
- **应当**:强烈推荐的行为;实现可以偏离,但偏离必须在本册或实现文档中说明。
- **可以**:真正的实现自由度。

标注为**非规范**(non-normative)的段落、注释与附录不构成一致性要求。

### 0.4 一致性

一个 WLWL 程序是符合本规范的,当且仅当它只使用本册与其它规范册定义的语法形式与语义,且不依赖任何标注为未定义、保留或实现定义的行为。一个实现是一致的,当且仅当它接受所有一致的程序并产生本规范规定的结果。完整判据见[一致性册 §1](wlwl-v1.0-conformance.md)。

### 0.5 记法

## 13 OOP 关键字与对象模型

`CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` 是完整定义的构造。本章定义对象模型;会话类型协议见 §14;`THIS` 的线性纪律见 §15;与并发的交互见 §16。

### 13.1 构造一览

| 构造 | 签名 | 类别 | 语义摘要 |
|------|------|------|----------|
| `CLASS(name, parent, members)` | `-> CLASS` | 关键字调用 | 构造类对象(§13.2) |
| `NEW(cls, args...)` | `-> INSTANCE` | 关键字调用 | 实例化并运行 `init`(§13.3) |
| `THIS()` | `-> INSTANCE` | 关键字调用 | 当前方法的接收者(§15) |
| `GET_PROP(obj, key)` | `-> v` | 全局内建 | 读属性(§13.4) |
| `SET_PROP(obj, key, value)` | `-> NULL` | 全局内建 | 写实例字段(§13.4) |
| `CALL_METHOD(obj, method, args...)` | `-> v` | 全局内建 | 调方法并走协议状态机(§13.5 / §14) |

上述构造**均不得**被当作 `ERR` 消费者(语言核心册 §8.3);实参为 `ERR` 时按语言核心册 §8.2 透明传播。

**不提供**:类继承以外的动态特性(多重继承、混入)、抽象类、静态方法、构造重载、字段级生命周期注解、运行时派生协议。外部选择 `&`、命名协议、并行协议分支见 §14.1。

### 13.2 CLASS

```
CLASS(name, parent, members) -> CLASS
```

`CLASS` **必须**恰取 3 个实参;元数不符产生 `E0022`。

**name**:`name` **必须**是 `STRING` 或 `NULL`。`NULL` 表示匿名类;其它类型产生 `E0030`。名字仅供诊断显示(语言核心册 §2.5),不影响相等(语言核心册 §2.4)或查找。

**parent**:`parent` **必须**取下列形态之一:

| 形态 | 含义 |
|------|------|
| `NULL` | 无父类、无协议 |
| `CLASS` 值 | **单继承**父类;成员查找沿父链向上(§13.5) |
| 会话协议表达式(`DICT` / `ARRAY` / `STRING`,§14.1) | 声明会话类型协议;此时无继承父类 |
| 其它 | `E0030` |

父类链**不得**含环,深度**不得**超过 64;违者产生 `E0050`。协议表达式畸形产生 `E0050`。

**members**:`members` **必须**是 `ARRAY`,每个元素是恰含两个元素的 `[STRING, value]` 数组;键**必须**是 `STRING`。其它形态产生 `E0030`。成员按键名分类:

| 键 | 值形态 | 角色 |
|----|--------|------|
| `"init"` | 函数 | 构造器(§13.3);一个类至多生效一个 `init`,`members` 中重复的 `init` 键由后者覆盖前者 |
| 其它键,且值是**第一个形参名为 `self`** 的闭包 | 函数 | 实例方法 |
| 其它键,其余值 | 任意 | **类字段** |

类字段对实例是**只读**的(§13.4)。方法经 `CALL_METHOD` 或 `a.m(...)` 调用时按语言核心册 §4.6 注入接收者。

```wlwl
LET(Base, CLASS("Base", NULL, [["hello", FUN((self), "hi")]]));
LET(D, CLASS("D", Base, []));
LET(o, NEW(D));
o.hello();   // "hi" — 沿父链找到方法,接收者注入 self
```

```wlwl
LET(C, CLASS("C", NULL, [
    ["count", 0],                                  // 类字段,只读
    ["init", FUN((self), SET_PROP(self, "n", 1))], // 构造器
    ["get", FUN((self), GET_PROP(self, "n"))]      // 方法
]));
LET(o, NEW(C));
CALL_METHOD(o, "get");   // 1
```

### 13.3 NEW

```
NEW(cls, args...) -> INSTANCE
```

`NEW` 按下列顺序求值:

1. `cls` **必须**是 `CLASS` 值,否则产生 `E0030`。
2. 分配新实例:实例字段表初始为空;协议状态机按 `cls` 的协议初始化(§14.3);线性 `THIS` 记号置为未消费(§15.2)。
3. 若 `cls` 有 `init` 成员:
   - `init` 不是函数值 → `E0050`;
   - 元数:实参个数(`cls` 占一位,加上 `args...`)**必须**等于 `init` 的形参个数(含 `self`),不符 → `E0050`;
   - 若类声明了协议,先按协议状态机消费 `init` 步(§14.4);不匹配 → `E0050`;
   - 以实例为 `self` 调用 `init`,并把 `args...` 传给其余形参(语言核心册 §4.6 注入规则)。
4. 若 `cls` 没有 `init`,直接返回空字段的新实例。
5. 表达式的结果是该实例。

```wlwl
LET(C, CLASS("C", NULL, [["init", FUN((self), SET_PROP(self, "x", 1))]]));
LET(o, NEW(C));
GET_PROP(o, "x");   // 1
```

本册**不**提供构造重载:`init` 的形参数**必须**与 `NEW` 的实参数精确匹配。

### 13.4 GET_PROP / SET_PROP

```
GET_PROP(obj, key) -> v
SET_PROP(obj, key, value) -> NULL
```

`key` **必须**是 `STRING`,否则产生 `E0030`。

**GET_PROP**

| `obj` | 行为 |
|-------|------|
| `DICT` | 按语言核心册 §4.5 字典取值;键不存在 → `E0037` |
| `INSTANCE` | 先查实例字段表;未命中则沿类父链查类字段;再未命中 → `E0037`。父链成环 / 超深 → `E0050`。类字段与实例字段均可读 |
| 其它 | `E0030` |

**SET_PROP**

| `obj` | 行为 |
|-------|------|
| `DICT` | 与 `INDEX_SET` 同族的值语义:返回**插入或更新后的新字典**,接收者不变 |
| `INSTANCE` | 见下 |
| 其它 | `E0030` |

对 `INSTANCE` 的 `SET_PROP` 按下列顺序校验,命中即报:

1. `value` 是当前线性 `THIS` → `E0032`(§15.3);键为线性 `THIS` 同样 → `E0032`;
2. 当前不在"该实例的 self 方法体"内(§15.1)→ `E0032`;
3. `key` 是类字段(含沿父链命中)→ `E0032`(类字段只读);
4. `key` 已是实例字段 → 原位更新,返回 `NULL`;
5. 否则 → 新建实例字段 `(key, value)`,返回 `NULL`。

```wlwl
LET(C, CLASS("C", NULL, [
    ["m", FUN((self), SET_PROP(self, "n", 7); GET_PROP(self, "n"))]
]));
CALL_METHOD(NEW(C), "m");   // 7 — n 是新建的实例字段
```

**说明**:上例中的 `n` 不是类成员,因此写入的是实例字段。类字段的写入按下表报 `E0032`:

| 失败形态 | 预期诊断 |
|----------|----------|
| 在 `self` 方法体内 `SET_PROP(self, "k", 1)`,而 `k` 是类字段(含沿父链命中) | `E0032` |
| `SET_PROP(self, "k", THIS())` 或以 `THIS()` 为键 | `E0032` |
| 在该实例的 self 方法体之外写 `SET_PROP` | `E0032` |

**字段可变性**由声明位置决定:类字段(§13.2 `members` 中非 `init`、非 self 闭包者)只读;实例字段可写。该标志在类构造时即确定,**不**因持有引用而改变(语言核心册 §3.3 同源原则)。

### 13.5 CALL_METHOD

```
CALL_METHOD(obj, method, args...) -> v
```

`method` **必须**是 `STRING`,否则产生 `E0030`;元数至少 2(`obj`、`method`)。

1. **接收者**:`obj` **必须**是 `DICT` 或 `INSTANCE`;其它 → `E0030`。
2. **线性检查**:`THIS` 越界形态先于协议校验(语言核心册 §11.2 的校验顺序)。
3. **方法查找**:
   - `DICT`:按键查字典成员;缺失 → `E0037`;
   - `INSTANCE`:先查该类 `members`,再沿父链向上;全未命中 → `E0037`;父链成环 / 超深 → `E0050`。实例字段不参与方法查找。
4. **协议校验**(仅当类声明了协议):按 §14.3 推进状态机;违规 → `E0050` / `E0051`。
5. **调用**:按语言核心册 §4.6 注入规则调用成员。成员是闭包且首形参名为 `self` 时注入接收者;成员是内建时不注入。成员存在但不可调用 → `E0030`。

属性 / 方法语法糖 `obj.method(args)` 与 `CALL_METHOD(obj, "method", args...)` 等价。

### 13.6 类型、相等与显示

`TYPE(cls)` 为 `"CLASS"`;`TYPE(obj)` 为 `"INSTANCE"`。相等按语言核心册 §2.4 的对象身份;显示按语言核心册 §2.5。

### 13.7 与错误模型的关系

- `CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` **均不得**被当作语言核心册 §8.3 的 `ERR` 消费者(语言核心册 §8.2 适用)。
- 本章的失败**不**产生 `ERR` 载荷,而是原生诊断码:`E0030` / `E0032` / `E0037` / `E0050` / `E0051`。程序如需把它们转为 `RESULT`,**应当**在调用前自行校验,或捕获为宿主诊断(并发册 §17.1 `AWAIT` 的宿主诊断重抛规则)。
- 方法体内部产生的用户 `ERR` 仍按语言核心册 §8.2 传播,不受本章影响;该 `ERR` 若在传播途中被丢弃,按语言核心册 §8.6 的丢弃规则处理。

## 14 行为类型与会话类型协议

每个 `CLASS` **可以**声明一个**会话类型协议**,约束其实例上方法调用的合法次序。协议在 `CLASS` 的第二实参位以**普通 WLWL 值**书写,经运行时解析为协议状态机;`CALL_METHOD` / `NEW` 在调用时按状态机校验。

### 14.1 协议表达式

协议表达式是 `STRING` / `ARRAY` / `DICT` 形态的值。合法形态如下(`T` 为载荷类型名,`X` 为 μ 变量):

| 形态 | 含义 |
|------|------|
| `"end"` | 终止 |
| `["end"]` | 同上 |
| `["then", "m", next]` 或 `["seq", "m", next]` | 先调 `m`,再继续 `next` |
| `["recv", T, next]` | 载荷类型注解 `T`(如 `"int"`),然后继续 `next`;作为 `then` 的续段使用 |
| `["seq", "a", "b", "c"]` | 平坦序列 `a → b → c → end` |
| `["choice", {m1: c1, m2: c2}]` 或 `["choice", [[m1, c1], [m2, c2]]]` | **内部选择 `⊕`**:调用方在 `m1` / `m2` 中恰选一个 |
| `["mu", "X", body]` | 递归绑定 `μX. body` |
| `["var", "X"]` | 递归变量 `X`(**必须**由外层 `mu` 绑定) |
| `{m1: v1, m2: v2, ...}` | **顺序序列** `m1 → m2 → …`;值是载荷类型名(`"end"` 表示无载荷)或嵌套续段 |

顺序字典形态 `{a: "end", b: "end", c: "end"}` 等价于 `a` 然后 `b` 然后 `c` 然后 `end`。若字典中某个值是非字符串的复合形态,则该值是该方法之后的**续段**,其后的键被忽略(显式链接请用 `then`)。

```wlwl
// 顺序协议:a → b → c
LET(C, CLASS("C", ["a": "end", "b": "end", "c": "end"], [
    ["a", FUN((self), 1)],
    ["b", FUN((self), 2)],
    ["c", FUN((self), 3)]
]));
LET(o, NEW(C));
CALL_METHOD(o, "a");
CALL_METHOD(o, "b");
CALL_METHOD(o, "c");   // 3
```

```wlwl
// 内部选择 ⊕:open 或 close 二选一
LET(C, CLASS("C", ["choice", ["open": "end", "close": "end"]], [
    ["open", FUN((self), "opened")],
    ["close", FUN((self), "closed")]
]));
CALL_METHOD(NEW(C), "close");   // "closed"
```

```wlwl
// μ 递归:get 可重复,close 终止
LET(C, CLASS("C",
    ["mu", "X", ["choice", [
        ["get", ["recv", "int", ["var", "X"]]],
        ["close", "end"]
    ]]],
    [
        ["get", FUN((self), 7)],
        ["close", FUN((self), "done")]
    ]
));
LET(o, NEW(C));
CALL_METHOD(o, "get");
CALL_METHOD(o, "get");
CALL_METHOD(o, "close");   // "done"
```

顺序、内部选择 `⊕`、μ 递归骨架受支持。下列形态**不支持**:

| 形态 | 状态 |
|------|------|
| 外部选择 `&` | 不支持 |
| 命名协议 / `typealias` | 不支持 |
| 并行分支 `par` | 不支持 |

不支持的形态若出现在协议表达式中,按协议畸形处理(`E0050`)。

### 14.2 协议状态机

每个实例持有一个协议状态:

| 状态 | 含义 |
|------|------|
| **Unrestricted** | 类未声明协议;任意方法、任意次序均可调用 |
| **Live(remaining)** | 协议进行中;`remaining` 是剩余协议 |
| **Done** | 协议已到达 `end` |

μ 递归的展开有预算;超出预算的展开按协议违规处理(`E0051`)。

**实现注(非规范)**:`Laffinty/wlwl`(基线 `56b9fb6`)的 μ 展开预算为 64 次。

### 14.3 CALL_METHOD 校验

对声明了协议的类,`CALL_METHOD(obj, method, args...)` 在找到方法之后、调用之前推进状态机:

1. 状态为 **Done** → `E0050`(协议已终止;任何方法都不可再调)。
2. 状态为 **Unrestricted** → 不校验,直接调用。
3. 状态为 **Live**:
   - `method` 不在当前 `remaining` 提供的方法集合中 → `E0051`(顺序错位、未选中的 `⊕` 分支、μ 展开后的不匹配);
   - 命中顺序步 → `remaining` 前进到续段;
   - 命中 `⊕` 的某个分支 → `remaining` 前进到该分支的续段;
   - 续段是 μ 变量 → 展开到 μ 体(消耗 1 点预算);
   - 续段是 `end` → 状态转为 **Done**。

**校验优先级**:状态错位(`Done`)优先于步骤不匹配。协议表达式畸形在 `CLASS` 求值期即报 `E0050`,不进入运行时状态机。

| 失败形态 | 预期诊断 |
|----------|----------|
| 协议已到达 `end` 之后再调该实例的方法 | `E0050` |
| 协议当前步是 `a`,却先调 `b` | `E0051` |
| 协议表达式畸形(如含不支持的形态) | `E0050`(在 `CLASS` 求值期) |

### 14.4 NEW 与 init 步

若类声明了协议且 `members` 含 `init`,`NEW` 在调用 `init` 之前按状态机消费名为 `init` 的一步:协议当前不提供 `init` → `E0050`(构造期协议错配)。无 `init` 成员时,`NEW` 不消费协议步,实例停留在协议的起始状态。

### 14.5 与并发的关系

协议状态机是**每实例**的,不跨任务共享(§16.1)。`AWAIT` / `YIELD` / 通道操作不推进协议状态机;任务挂起期间协议位置保持不变。

## 15 `THIS` 与线性 capability

`THIS` 是当前方法接收者的**线性 capability**:每次方法调用内至多消费一次,**不得**逃出该次调用的动态范围。

### 15.1 THIS 求值

`THIS()`(或零参引用 `THIS`)求值为当前活跃的 `INSTANCE` 接收者。

- 元数**必须**为 0,否则产生 `E0022`。
- 当前没有活跃方法接收者(方法体之外)→ `E0032`。
- 当前接收者不是 `INSTANCE` → `E0032`。

**方法体**指:经 `CALL_METHOD` / `NEW`(init)调用、且接收者作为 `self` 注入(语言核心册 §4.6)的闭包体。嵌套方法调用各自建立自己的接收者;内层返回后恢复外层接收者。

```wlwl
LET(C, CLASS("C", NULL, [["m", FUN((self), THIS())]]));
```

`THIS` 在 `m` 内是 `self`;在顶层求值 `THIS()` 是 `E0032`。

### 15.2 线性消费

在同一次方法调用内,`THIS()` 的求值**消费**该能力:

1. 第一次求值成功,返回接收者,并标记为已消费;
2. 同一次调用内的再次求值 → `E0032`;
3. 调用返回时,本次消费记号复位;下一次方法调用重新获得一次消费机会。

| 失败形态 | 预期诊断 |
|----------|----------|
| 同一次方法调用内第二次求值 `THIS()` | `E0032` |

### 15.3 逃逸边界

`THIS` 的值**不得**离开当前方法体。下列形态均产生 `E0032`:

| 边界 | 示例 |
|------|------|
| 数组字面量 | `LET(a, [THIS()])` |
| 字典字面量(键或值) | `LET(d, ["this": THIS()])` |
| 闭包捕获 | `LET(f, FUN((), THIS()))` |
| 方法返回值 | `FUN((self), THIS())` 作为方法体;或 `FUN((self), LET(x, THIS()); x)` |
| `SPAWN` 的任务体或捕获环境 | `SPAWN(FUN((), THIS()))` |
| `AWAIT` 实参 | `AWAIT(THIS())` |
| `SET_PROP` 的值或键 | `SET_PROP(o, "k", THIS())` |

逃逸检查在**构造该形态时**执行(闭包在捕获时、字面量在构造时、返回在离开方法帧时),而非延后到使用点。

### 15.4 SET_PROP 与 self 上下文

对 `INSTANCE` 的 `SET_PROP` 只在"该实例的 self 方法体"内合法(§13.4):外部引用、他实例的 self 方法内、或无活跃方法时写入 → `E0032`。`GET_PROP` 不受此限。

## 16 OOP 与并发的交互

### 16.1 挂起与协议状态机

`CALL_METHOD` 执行期间,方法体**同步直落**:它不获得 step context,因此方法体里的 `YIELD` 与阻塞型通道操作**不得**挂起。

在**不含**挂起的前提下,方法体执行期间的协议与 `THIS` 状态:

- 实例的协议状态机位置在方法体**执行期间不推进也不回退**;
- 协议状态机是每实例私有(§14.5),其它任务**不得**经由该实例推进协议;
- `THIS` 的消费记号在方法体执行期间保持,方法体返回后仍按 §15.2 规则。

### 16.2 `THIS` 与 `SPAWN` / `AWAIT`

§15.3 的逃逸边界覆盖任务构造与等待:把 `THIS` 放进 `SPAWN` 的任务体或捕获环境、或作为 `AWAIT` 的实参,均产生 `E0032`。子任务中不存在 self 上下文;在子任务里求值 `THIS()` 同样是 `E0032`。

### 16.3 实例字段共享

实例字段的可见性不引入新规则:同一实例可被多个任务持有,`SET_PROP` 的写入对共享该实例的引用可见(§13.4)。跨任务协调**应当**经由通道(并发册 §17.2)显式编排;`SET_PROP` 不提供同步保证。

**说明**:这与语言核心册 §19.2 的别名规则是同一条 —— 实例字段同属"共享 + 可变",同样不提供同步保证。

### 16.4 取消与方法体

任务取消(并发册 §17.3)在检查点生效。方法体内的取消观察与普通任务体一致:`TASK_IS_CANCELLED()`、`YIELD`、阻塞型通道操作。取消**不**直接改写协议状态机;实例的协议位置在任务终止后保持其最后推进到的状态。

**`CALL_METHOD` 的控制流形态(规范性)**:方法调用是**同步直落**的 —— 它在调用点完成求值,不进入并发册 §17.4 的挂起模型。协议顺序违规以 `E0051`、协议已结束仍被调用以 `E0050` **当场**报告(两者都在语言核心册 §11.2 的校验顺序里),不经由效果处理器。`MethodCall` / `ProtocolViolation` 两个 tag 属于为代数效果后端迁移预留的 tag 面(见并发册 §17.4 末段),**不由运行期产生**。
