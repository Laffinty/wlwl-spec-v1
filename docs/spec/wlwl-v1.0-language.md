# WLWL 语言核心规范 v1.0

本册定义 WLWL 语言的**核心**:词法、类型与值、绑定与作用域、表达式、函数、控制流、模式匹配、错误模型、模块与程序、标准库机制面、诊断、复杂度保证与内存模型。

- **一切都是表达式**。没有语句与表达式的二分;每个构造求值后产生一个值。
- **一切运算皆调用**。没有中缀运算符;算术、比较、逻辑都是具名函数,按 `name(arg, ...)` 前缀形式调用。
- **默认不可变**。绑定一旦建立即指向固定值;容器操作返回新容器而非修改原容器;状态突变只能经由 `LET MUT` 显式声明的单元格进行(对象字段的突变规则见对象册 §13.4)。
- **错误即值**。可恢复错误是 `RESULT` 值,沿调用链透明传播,由显式的消费者函数处理(§8)。

对象模型、行为类型与 `THIS` 见[对象与行为类型册](wlwl-v1.0-objects.md);并发见[并发册](wlwl-v1.0-concurrency.md);标准库成员契约见[标准库册](../stdlib/)。

本册面向三类读者:WLWL 程序员、语言工具(格式化器、静态检查器、编辑器)的实现者,以及参考实现本身的维护者。完整的四类读者路径见[一致性册 §7.1](wlwl-v1.0-conformance.md)。

### 0.3 规范性用语

本册中的关键词 **必须**(MUST)、**不得**(MUST NOT)、**应当**(SHOULD)、**可以**(MAY)按以下含义使用:

- **必须 / 不得**:实现的硬性约束。违反时实现必须产生一个诊断(§11)并按 §11.4 终止或报告。
- **应当**:强烈推荐的行为;实现可以偏离,但偏离必须在本册或实现文档中说明。
- **可以**:真正的实现自由度。

标注为**非规范**(non-normative)的段落、注释与附录不构成一致性要求。

### 0.4 一致性

一个 WLWL 程序是符合本规范的,当且仅当它只使用本册与其它规范册定义的语法形式与语义,且不依赖任何标注为未定义、保留或实现定义的行为。一个实现是一致的,当且仅当它接受所有一致的程序并产生本规范规定的结果。完整判据见[一致性册 §1](wlwl-v1.0-conformance.md)。

### 0.5 记法

语法用扩展巴科斯范式(EBNF)书写,记法约定见附录 A。正文中 `code` 样式表示词法记号、字面代码或诊断码;`name` 斜体表示文法产生式。示例代码以 `//` 注释标出其求值结果。

**围栏约定**:文法块用**无标记**围栏;示例代码块用 **`wlwl`** 标记的围栏。示例块**必须**能在参考实现上运行且退出码为 0 —— 这是[一致性册 §6.1](wlwl-v1.0-conformance.md)第 7 项检查的内容,由 `script/check_spec.py` 自动核验。

**标点约定**:逗号 `,`、冒号 `:`、分号 `;`、圆括号 `()`、方括号 `[]` 一律用**半角**;句号 `。`、顿号 `、`、引号 `「」`、破折号 `——` 用**全角**。

**引用**:同册内写 `(§8.2)`;跨册写册名加节号,例:"语言核心册 §8.2"、"并发册 §17.3"、"一致性册 §3"。

## 1 词法结构

### 1.1 源文件

一个 WLWL 源文件是一个 **必须** 为 UTF-8 编码(带或不带 BOM)的字节序列。换行**可以**是 `\n`、`\r\n` 或 `\r`,三者等价。源文件是一个模块(§9)。

**说明**:三种换行在词法上等价,故同一份源码在任何平台上的词法结果相同。

旁路签名文件 `.wll.sig`(§9.6)的编码要求**本版不规定**,按实现定义处理 —— 它是语言设施而非工具选择,这一空白**应当**在下一次规范修订前补上。清单文件 `wlwl.toml` 与锁文件 `wlwl.lock` 属包管理器职责,不在本册范围内(§9.4)。

### 1.2 注释

- `//` 开始一个**行注释**,延伸到行尾。
- `/*` 与 `*/` 界定一个**块注释**。块注释**必须**正确嵌套。
- `///` 开始一个**文档注释**,延伸到行尾。文档注释只在词法上与行注释相区别,**不得**影响程序语义。

注释中出现的任何字符序列(除上述定界规则外)都是注释的一部分。

### 1.3 标识符

```
identifier = letter { letter | decimal_digit | "_" } .
```

`letter` 含 Unicode 字母类别(含中文)。标识符区分大小写。非 ASCII 标识符是合法的;工具**应当**在诊断中如实回显。

以 `_` 单独出现的标识符是**通配符**,见 §3.1 与 §7.2。

### 1.4 关键字

```
TRUE    FALSE   NULL    LET     FUN     RETURN
IF      WHILE   FOR     BREAK   CONTINUE
CLASS   NEW     THIS    NOT
```

关键字**不得**用作标识符。`CLASS`、`NEW`、`THIS` 的语义见对象册 §13 与 §15:它们出现在调用形式 `CLASS(...)`、`NEW(...)`、`THIS()`(或零参引用 `THIS`)中,分别构造类、实例化对象、引用当前实例。

`MUT` 是**上下文关键字**:仅在 `LET` 之后的位置具有特殊含义(§3.1);其他位置可作普通标识符使用,不与关键字冲突。

**`SEALED` 不是关键字**(§9.1)。它以**前缀调用 / 模块头声明**形式书写,与 `CLASS(...)` / `NEW(...)` 同形,因此本节的关键词表不含 `SEALED`,§12 的保留集合相应为空。

### 1.5 运算符记号

以下记号是内建运算函数名,可用前缀调用形式书写(§4.3、§4.6):

```
+   -   *   /   %   ==  =   !=  <   >   <=  >=  &&  ||  !
```

`=` 的角色由**文法位置**唯一决定:

1. 出现在 `OpToken` 位置(`=` 后紧跟 `(`)→ 相等函数调用 `=(a, b)`,与 `==` 同义(注册表 `Eq => "=="` desugar,见 §4.3)。
2. 出现在 `Postfix` 形式的 `=` 位置(`... [ Expression ] "=" Expression`)→ `INDEX_SET` 语法糖(见 §4.5)。
3. 出现在形参表 `Param` 内(`name = Expression`)→ 默认值分隔符(见 §5.2)。

三者互不重叠,无需词法前瞻。

`=` 与 `==` 在调用位置同义(都指相等函数);`!` 与 `NOT` 关键字(§1.4)同义,两种形式均无警告。

### 1.6 整数字面量

```
int_lit        = decimal_digit { decimal_digit } .
int_literal   = [ "+" | "-" ] int_lit .
```

整数值是有符号 64 位整数。运算结果超出该范围的规则见 §2.2。

**实现注(非规范)**:前导符号字面量 `+x` / `-x` 在语法分析阶段被改写为 `+(0, x)` / `-(0, x)`,与二元运算同路径;`NEG` 是独立的 1 元内建,只能按名调用。可观察行为与「前导符号字面量」等价:同 `INTEGER` 下界、同 §2.2 溢出语义。

### 1.7 浮点字面量

```
float_lit      = digits "." digits | digits exponent | digits "." digits exponent .
exponent       = ( "e" | "E" ) [ "+" | "-" ] digits .
```

浮点值是 IEEE 754 双精度数。整数与浮点字面量统称**数字字面量**。

### 1.8 字符串字面量

```
string_lit     = '"' { string_element | interpolation } '"' .
string_element = any_char_except_quote_backslash_newline_dollar | escape .
interpolation  = "${" Expression "}" .
escape         = "\" ( "n" | "t" | "r" | "\" | '"' | "/" | "0" | "b" | "f" | "$" ) .
```

字符串是 Unicode 码点的不可变序列。承认的转义:`\n` 换行、`\t` 水平制表、`\r` 回车、`\\` 反斜杠、`\"` 引号、`\/` 斜杠、`\0` 空、`\b` 退格、`\f` 换页、`\$` 字面 `$`。其他转义**不得**出现(`E0001` 或 `E0002`)。

**字符串插值**:`"Hello, ${name}!"` 中 `${...}` 内的表达式按完整表达式语法求值;求值结果以 `STR`(§10.3)渲染后嵌入字符串;求值若产生 `ERR` 则按 §8.2 透传,整个字符串字面量表达式的结果为该 `ERR`。

### 1.9 布尔与空字面量

`TRUE`、`FALSE` 产生布尔值;`NULL` 产生空值。

### 1.10 分号

处于"语句位置"的表达式**必须**以 `;` 结束。在括号序列(§4.4)内部,最后一个表达式的 `;` **可以**省略;该表达式的值即括号序列的值。省略必需的 `;` 产生 `E0013`。

## 2 类型与值

### 2.1 值域

WLWL 是动态类型语言:类型属于值而非名字。值的论域由以下**类型**构成:

| 类型 | 含义 |
|------|------|
| `NULL` | 空值,唯一成员 `NULL` |
| `BOOLEAN` | `TRUE` 或 `FALSE` |
| `INTEGER` | 有符号 64 位整数 |
| `FLOAT` | IEEE 754 双精度浮点数 |
| `STRING` | Unicode 码点的不可变序列 |
| `ARRAY` | 值的不可变有序序列 |
| `DICT` | 从键(STRING、INTEGER 或 INSTANCE)到值的插入序映射,不可变 |
| `FUNCTION` | 闭包(§5.4) |
| `RESULT` | `OK(v)` 或 `ERR(e)` 变体(§8) |
| `TASK` | 任务句柄;`SPAWN` / `TASK_CURRENT` 返回(并发册 §17.1) |
| `CHANNEL` | 通道句柄;`CHANNEL_NEW` 返回(并发册 §17.2) |
| `CLASS` | 类对象;`CLASS` 构造器返回(对象册 §13.2) |
| `INSTANCE` | 类实例;`NEW` 返回(对象册 §13.3) |

数组与字典字面量见 §4.8;`TYPE(x)` 返回上表名称的字符串(`RESULT` 两个变体都报 `"RESULT"`)。

类型名(`NULL`/`BOOLEAN`/`INTEGER`/`FLOAT`/`STRING`/`ARRAY`/`DICT`/`FUNCTION`/`RESULT`/`TASK`/`CHANNEL`/`CLASS`/`INSTANCE`)是 `TYPE` 返回的字符串,**不**构成标识符绑定。命名空间成员**可以**与类型名同名(如官方包 `agent` 的 `TASK`),二者在各自作用域中独立解析。`TYPE` 的参数位置不做名字解析 —— 它取运行时值,返回字符串,过程中不查任何名字表。

`TYPE` 对句柄报 `"TASK"` / `"CHANNEL"`,对类对象报 `"CLASS"`,对实例报 `"INSTANCE"`。句柄的真值按 §2.3「其余一切值为真」;相等按 §2.4;显示形态见 §2.5。

**键的约束**:字典的键**必须**是 `STRING`、`INTEGER` 或 `INSTANCE`。`INSTANCE` 作键按**对象身份**判定(§2.4):同一实例命中,异实例不命中。其它类型作键**类型不符**,产生 `E0031`。NaN(§2.2)**不得**作键(`E0031`)。

### 2.2 算术性质

- 整数运算按二进制补码语义进行;`+`、`-`、`*` 溢出时**抛错** `E0035`(`INTEGER` 与 `FLOAT` 越界共用此码)。`NEG` 于 `INTEGER` 下界取负产生 `E0034`。
- `/(a, b)` 当两操作数为整数时是**截断除法**(商向零取整):`/(7, 2)` 为 `3`,`/(-7, 2)` 为 `-3`。两操作数为浮点时是浮点除法,可产生 `Inf`/`NaN`。
- `b` 为零时 `/(a, b)` 产生 `E1003`(整数、浮点皆然,即使 IEEE 754 允许 `Inf`)。
- `%(a, b)` 只接受整数:`a - /(a, b) * b`,符号与被除数一致;`b` 为零产生 `E1003`。任一实参是 `FLOAT` 时产生 `E0030`(类型错)。

**说明**:整数溢出抛错而非回绕,是本语言"失败可见"原则(§2.2、§8)在算术层的体现。

### 2.3 真值

**假值**恰为八个:`FALSE`、`NULL`、`0`、`0.0`、`""`、空数组、空字典、`NaN`。**其余一切值为真**,包括非空数字、非空字符串、非空容器、`OK(FALSE)` 之类的 `RESULT` 值、以及 `CLASS` / `INSTANCE` 值。

真值仅由 §6.1 的 `IF`、§6.2 的 `WHILE`、`&&`、`||`、`NOT`、`BOOL` 以及模式匹配以外的谓词位置消费。

### 2.4 相等

`==(a, b)`(别名 `=`,§1.5)与 `!=(a, b)`:

- 数字跨类型比较:`==(1, 1.0)` 为 `TRUE`。
- 字符串按码点逐位比较;布尔、空按恒等。
- 数组按长度与逐元素深度相等;字典按键集与逐键值深度相等(受上一条 NaN 规则影响:含 NaN 的容器与任何值都不等)。
- 函数按闭包实例引用相等。
- `RESULT`:`OK(a) = OK(b)` 当且仅当 `a = b`;`ERR(e1) = ERR(e2)` 当且仅当 `e1 = e2`;`OK` 与 `ERR` 永不相等。
- 任一操作数为 `ERR` 变体时,比较函数**不**求布尔,而是透明传播该 `ERR`(§8.2)。
- `TASK` / `CHANNEL` 句柄按句柄身份恒等:同一句柄与自身相等,不同句柄不相等。
- `CLASS` / `INSTANCE` 按**对象身份**恒等:同一类对象与自身相等,两次 `CLASS(...)` 调用产生的类对象不相等,即使成员相同;同一实例与其别名相等,两次 `NEW(...)` 产生的实例不相等,即使字段值相同。该规则比照句柄的身份相等,不改变上列既有类型规则。

### 2.5 显示

`PRINT`(§10.2)与 `STR`(§10.3)将值渲染为文本:布尔为 `TRUE`/`FALSE`,空为 `NULL`,数组为 `[e1, e2, ...]`,字典为 `[k: v, ...]`,函数为 `<fun(params)>`。`STR` 对字符串恒等;对浮点保留小数表示(整数产生的浮点显示一位小数,如 `2.0`)。

句柄显示为 `<task handle id=N gen=M>` / `<channel handle id=N gen=M>`。

类对象显示为 `<class Name>`(匿名类为 `<class>`);实例显示为 `<Name instance>[N fields]`(匿名类实例为 `<instance>[N fields]`),其中 `N` 为实例字段个数。显示形态仅供诊断,**不得**作为程序判等或解析依据。

### 2.6 静态类型词汇(编译期)

本节描述的是**注解词汇**,不是运行期值域。§2.1 的表才是值的论域;`TYPE(x)`(§2.5)**永不**返回本节的名字。这些名字只出现在类型注解(§5.2)与旁路签名文件(§9.6)里,**且仅当 `[features] gradual_typing` 开启时才被解释**(§5.2.1)。

| 注解类型 | 含义 |
|---|---|
| `INTEGER` / `FLOAT` / `STRING` / `BOOLEAN` / `NULL` | 与 §2.1 同名运行期类型的顶层形状 |
| `ARRAY[T]` / `DICT[K, V]` | 容器;`T` / `K` / `V` 为类型参数 |
| `OPTION[T]` | **纯注解糖**:§2.1 没有这个运行期类型。它的两个见证是 `NULL`("就是没有")与 `RESULT[T, ·]`("或者是一个 T",错误侧不要求已知)。**裸 `T` 不满足 `OPTION[T]`** —— 否则 `OPTION` 退化成 `T` 的别名,失去全部意义 |
| `RESULT[T, E]` | `OK(_)` / `ERR(_)` 两个构造子 |
| `FUN[...] -> U` | 函数类型。**箭头形式不在语法内**(见本节末) |
| `DYNAMIC` | 未标注处的回退类型;它与任何类型双向可赋值,因此**从不**产生诊断 |
| `T: Bound` | 类型变量(§5.2.1) |

`TASK` / `CHANNEL` / `CLASS` / `INSTANCE`(§2.1)在本层**不做结构化建模**,作为不透明具名类型参与比较。

**三条规范性事实**:

1. **容器类型用方括号,不用尖括号。** `ARRAY` **要求**方括号,裸写 `ARRAY` 报 `E0010: expected '[' after 'ARRAY' in type expression`。`DICT` / `OPTION` / `RESULT` 裸写**不报语法错**,映射成带 `DYNAMIC` 参数的正式变体(`DICT[DYNAMIC, DYNAMIC]` / `OPTION[DYNAMIC]` / `RESULT[DYNAMIC, DYNAMIC]`),不是「不透明具名类型」。
2. **尖括号形式与箭头形式的命运不同。**
   - `DICT<STRING, INTEGER>` 是**响亮的语法错**:`E0011: expected ')', got Gt`。
   - `FUN(INTEGER) -> STRING` 才是**静默吸收**:词法层没有 `->` 终结符(`-` 与 `>` 是两个独立记号),残余记号被并进类型名,得到 `FUN ( INTEGER ) - > STRING` 这个谁也不认识的类型 —— 用户看不到任何错误,却也得不到任何检查。**本规范不承认这两种形式**。
   - 单个类型参数的 `DICT<STRING>` 同样被静默吸收成 `DICT < STRING >`。
3. **显式约束只跟在裸标识符后,且不可嵌套。** `T: Comparable` 合法;`ARRAY[INTEGER]: Comparable` 报 **`E0010`**,消息是 `a type constraint may only follow a bare type variable`(与返回类型失配的 `E0112` 无关)。约束**不可右嵌套**:`T: Comparable: Integer` 报 `E0010: a type constraint may not be nested`。给**已知基类型**加约束是无意义的废话,约束被丢弃、类型不变:`INTEGER: Comparable` 就是 `INTEGER`。吸收不可达的类型形式时,残余记号会被并进类型名并**保留整个类型头**,所以格式化器能把这样的源码原样写回、可再解析。

## 3 变量、作用域与单元格

### 3.1 绑定

`LET(name, value)` 在**当前作用域**为 `name` 建立一个**不可变绑定**,并将 `value` 存入新创建的**单元格**(cell)。`LET` 表达式本身的值是 `NULL`。

`LET MUT(name, value)` 建立**可变绑定**:单元格的可变标志在创建时即置为真,允许后续 `SET`(§3.4)改写。

```wlwl
LET(x, 1);              // 不可变
LET MUT(count, 0);      // 可变
```

`LET` 的第一个实参**可以**是解构模式,此时按模式同时建立多个绑定;模式**必须**与值精确匹配,失配产生 `E0026`:

```wlwl
LET([a, b], [1, 2]);            // a=1, b=2
LET([head, *rest], [1, 2, 3]);  // head=1, rest=[2, 3]
LET(["k": v], ["k": 9]);        // v=9
LET([_, x, _], [1, 2, 3]);      // x=2
```

模式形态的完整定义见 §7.2。`LET MUT` 仅接受简单标识符,不支持解构。

**通配符模式**:`LET(_, value)` 的模式是通配符,**不**建立任何绑定,`value` 仍按完整表达式求值。该形式是本语言**唯一的显式丢弃构造** —— 它对 §8.6 的未消费 `ERR` 规则有专门语义(§8.6.4)。

**说明**:通配符模式与 `LET` 的普通形态在求值上无差别,差别只在**是否留下一个可读的绑定**。§8.6 之所以把"留下可读绑定"当作语义事件,是因为只有可读的绑定才能被消费。

### 3.2 作用域与遮蔽

作用域由**函数体、括号序列(§4.4)、`FOR` 循环体、`MATCH` 分支体**引入,以及每个模块的顶层。作用域按词法嵌套。

- 内层作用域中的 `LET` **总是**在内层新建单元格;若外层已有同名绑定,内层绑定**遮蔽**外层。
- 同一作用域中对同一名字再次 `LET` 是**重绑定**:旧绑定被替换。
- 读一个不存在的名字产生 `E0020`(附最近候选名)。
- **没有**变量提升:在 `LET` 之前读名字产生 `E0020`。

### 3.3 单元格可变性

每个绑定由一个单元格实现,单元格持有值与一个可变标志。可变标志由绑定形式决定:`LET` 建立的为不可变,`LET MUT` 建立的为可变。该标志一经设定**不再改变**。

当一个闭包捕获某单元格时,捕获环境保留对该单元格的引用;不论该单元格是 `LET` 还是 `LET MUT` 所建立,闭包均按原标志判定是否可写。多个闭包可共享同一单元格。

```wlwl
LET(make_counter, FUN((),
    (LET MUT(count, 0);
     FUN((), (SET(count, +(count, 1)); count)))
));
LET(c, make_counter());
c();   // 1
c();   // 2 — count 的单元格在闭包间共享
```

这是 WLWL 中唯一的原位状态突变机制(对象字段的突变是第二条显式路径,见对象册 §13.4)。循环累加等命令式惯用法**应当**经由 `LET MUT` 与 `SET` 表达,或 `REDUCE`(标准库册 §5)。

### 3.4 SET

`SET(name, value)` 将 `name` 当前绑定的单元格改写为 `value`:

- 名字不存在 → `E0020`。
- 单元格不可变(由 `LET` 建立而非 `LET MUT`)→ `E0024`。
- `SET` 表达式的值是 `NULL`。

`SET` 对不可变单元格产生 `E0024`,不论该写入发生在单任务内还是跨任务(并发册 §17.1)的共享单元格上;跨任务与单任务路径统一,不存在独立的跨任务错误码。

**说明**:`SET` 改写单元格时,旧值的处置受 §8.6 约束 —— 旧值若是一个未被消费的 `ERR`,改写即构成一个丢弃点。

### 3.5 遮蔽内建

`LET` 或命名函数定义(§5.1)遮蔽第 10 章的内建名时:默认产生 `E0025`;当模块清单声明 `[features] allow_builtin_shadow = true` 时允许并产生警告 `W0030`。遮蔽保留关键字(§1.4)产生 `W0030`。

## 4 表达式

### 4.1 操作数

操作数是字面量(§1)、标识符、括号序列(§4.4)、数组与字典字面量(§4.8),或下文定义的各构造。

### 4.2 调用

```
Call = identifier "(" [ Expression { "," Expression } ] ")" .
```

调用将实参自左向右全部求值后执行被调者。被调者不是函数值时产生 `E0020`。

`CLASS`、`NEW`、`THIS` 以关键字身份出现在调用位置(§1.4),文法上按具名调用解析;`THIS` 也可单独作为零参引用出现(对象册 §15.1)。

### 4.3 运算符即函数

所有运算符都是具名函数,以 §1.5 的记号作前缀调用:

| 调用 | 语义 | 结果 |
|------|------|------|
| `+(a, b)` | 数字相加(整数与浮点混合提升为浮点);字符串拼接;数组拼接 | 同类 |
| `-(a, b)`、`*(a, b)` | 减、乘;类型规则同上 | 数字 |
| `/(a, b)` | 除法,见 §2.2 | 数字 |
| `%(a, b)` | 整数取余,见 §2.2 | 整数 |
| `NEG(a)` | 取负 | 数字 |
| `==(a, b)`、`!=(a, b)` | 相等、不等(`=` 是 `==` 的别名) | 布尔 / `ERR` 透传 |
| `<(a, b)`、`>(a, b)`、`<=(a, b)`、`>=(a, b)` | 比较;数字按数值,字符串按码点序 | 布尔 / `ERR` 透传 |
| `&&(a, b)` | 合取,**短路**:`a` 为 `ERR` 时透传 `ERR`(不求 `b`);`a` 为假值时不求 `b`,返回 `FALSE`;否则求 `b`,返回 `BOOL(b)`(`b` 为 `ERR` 时透传) | 布尔 / `ERR` 透传 |
| `\|\|(a, b)` | 析取,**短路**:`a` 为 `ERR` 时透传 `ERR`(不求 `b`);`a` 为真值时不求 `b`,返回 `TRUE`;否则求 `b`,返回 `BOOL(b)`(`b` 为 `ERR` 时透传) | 布尔 / `ERR` 透传 |
| `NOT(a)` | 真值取反 | 布尔 |

`AND` 与 `OR` **不是**内建:合取与析取只有 `&&` 与 `||`(见上表)。这两个名字落回普通标识符解析,既不是 `&&` / `||` 的别名,也不做任何事 —— 实参先被求值,之后才轮到解析这个名字:

| 写法 | 行为 |
|---|---|
| `AND(TRUE, FALSE)` | `E0020: undefined name 'AND'` |
| `AND(FALSE, /(1, 0))` | `E1003` 除零 —— 实参先被求值 |
| `AND(ERR("x"), TRUE)` | `E0102` —— `ERR` 实参先传播 |

**说明**:`NOT` 与 `AND` / `OR` 的差别在解析路径,不在语义层。`NOT` 是可按名解析到的内建;`AND` / `OR` 只是普通标识符,名字解析发生在实参求值之后。

- `+`、`-`、`*`、`/`、`%`、`CONCAT` 是**严格二元**的;实参数不符产生 `E0022`。
- 任一操作数为 `ERR` 时,所有运算符调用按 §8.2 透明传播 —— **包括 `NOT`**。`BOOL(x)` 是单独的 `ERR` 消费者(§8.3),与 `NOT` 不对称,但两者都返回布尔真值;`BOOL(ERR(...))` 不传播,`NOT(ERR(...))` 传播。如需安全取反,请先经 `BOOL`:`NOT(BOOL(ERR(...)))` → `FALSE`(等价于 `!TRUE`)。`&&` / `||` 短路求值中,未求值那一侧的 `ERR` 不被传播(因为它没被求值)。
- `NOT` 与 `!` 接受任何值并按真值表返回布尔。

### 4.4 括号序列(块)

```
Block = "(" [ Expression ";" ] { Expression ";" } [ Expression ] ")" .
```

括号序列按顺序求值其中的表达式;其值是最后一个表达式的值。空括号序列 `()` 的值是 `NULL`。

### 4.5 下标

```
Index = Expression "[" Expression "]" | Expression "[" Expression "]" "=" Expression .
```

`a[i]` 是 `INDEX_GET(a, i)` 的语法糖;`a[i] = v` 是 `INDEX_SET(a, i, v)` 的语法糖。两者**可以**与 §4.6 的属性链自由组合:`a[0].b`、`a.b[0][1]`。

- `INDEX_GET(coll, k)`:数组接受整数索引(负数自尾部计数,`-1` 为末元素),越界产生 `E0036`;字典按键取值,键类型不符产生 `E0031`,键不存在产生 `E0037`;**字符串接受整数索引**,按码点返回单字符字符串,越界产生 `E0036`。
- `INDEX_SET(coll, k, v)`:接受数组或字典,返回**插入或更新后的新容器**;接收者不变(§2.1)。`INDEX_SET` 不接受字符串(`E0030`)。
- 下标链与属性链可挂在变量、调用、属性访问、**数组/字典字面量**、**或括号序列**之后。`[1, 2, 3][0]` 与 `["a": 1]["a"]` 都是合法表达式,等价于 `INDEX_GET` 对字面量直接求值;`[[1,2][0], 3]` 同样合法;`(d)["a"]` 与 `(d).a` 也是合法表达式(附录 A 的 `PostfixExpr = Primary { Postfix }`,`Primary` 含 `"(" Block ")"`)。
- `INDEX(arr, x)` **不是**下标的反操作,它是**值 → 位置**的查找(`x` 是待找的**值**,不是下标),且返回的是 **1-based** 位置;`x` 不在 `arr` 中返回 `-1`(不报错)。因此它与 `INDEX_GET` 的基数**相反**:`INDEX([7, 8, 9], 8)` 得 `2`,而 `INDEX_GET([7, 8, 9], 1)` 取的是**第 2 个**元素(0-based 的下标 `1`)。

### 4.6 属性与方法

```
Selector = Expression "." identifier [ "(" [ Expression { "," Expression } ] ")" ] .
```

`a.b` 是 `GET_PROP(a, "b")` 的语法糖;`a.b(args)` 是 `CALL_METHOD(a, "b", args...)` 的语法糖。接收者**可以**是字典(模块也是字典,§9.4)或 `INSTANCE`(对象册 §13):

- `GET_PROP(obj, k)`:键不存在产生 `E0037`;`obj` 不是 `DICT` 或 `INSTANCE` 产生 `E0030`。
- `a.b(args)` 调用 `a` 的 `"b"` 成员。当被调成员是**闭包**且其**第一个形参名为 `self`** 时,接收者 `a` 作为首实参自动注入,即等价于调用 `f(self=a, 其余实参...)`;形参命名不影响绑定之外的语义,首个形参**不**叫 `self` 时不注入。`CALL_METHOD` 亦遵守该注入规则,**不得**再显式传入接收者。
- 当被调成员是内建函数值(标准库注入)时,**不**注入接收者:`io.PRINT("hi")` 等价于 `PRINT("hi")`。
- 成员存在但不可调用时产生 `E0030`。

### 4.7 求值顺序

实参、括号序列各元素、数组与字典字面量的各元素,都按源代码顺序自左向右求值;除 §6.1、§6.2 与 `&&` / `||` 的短路语义外,不存在条件求值。`&&` / `||` 的短路路径只求值被选中的那一侧。

### 4.8 数组与字典字面量

```
ArrayLit = "[" [ Expression { "," Expression } ] "]" .
DictLit  = "[" Key ":" Expression { "," Key ":" Expression } ]" .
Key      = Expression .
```

- 第一项无 `:` 时为**数组字面量**;第一项为 `k: v` 时为**字典字面量**;空字面量 `[]` 恒为空数组。空字典只有一种写法:`DICT()`(§10.9)。
- 同一字面量中混用裸值与键值对产生警告 `W0020`。

## 5 函数

### 5.1 定义

```
Function = "FUN" "(" [ identifier ] "(" ParameterList ")" Expression .
```

- `FUN((params), body)` 产生一个**匿名函数值**。
- `FUN(name(params), body)` 产生同样的函数值,**并**在当前作用域将 `name` 绑定到它 —— 与 `LET(name, FUN(...))` 等价。两种形式的函数值相同,表达式的值都是该函数值。

具名形式的 `name` 写在**第一对括号之内**,不是括号之前:`FUN f(x) x` 不是合法语法(解析报 `E0011`)。

**规范性澄清**:`FUN(name(params), body)` 与 `LET(name, FUN(...))` 等价,二者表达式的值都是该函数值;`LET(name, value)` 的值是 `NULL`(绑定动作已完成,无值可传递)。`LET` 因此**不得**作为实参或运算符操作数(语义上是「声明」而非「值表达式」)。如需在表达式位置产生绑定效果,请用 `LET MUT` + `SET` 序列,或将值绑定到一个 `FUN` 表达式。

### 5.2 形参

形参列表由以下形态组成(按位置排列):

| 形态 | 含义 |
|------|------|
| `name` | 必需参数 |
| `name = Expression` | 默认参数;缺省实参时求值该表达式。默认表达式在**被调函数的词法帧**内求值,因此**可以**引用更外层的捕获与排在其前的形参 |
| `*name` | 剩余参数;收集多余的实参为**新数组**。只**可以**出现在末位 |
| `name: Type`、`name: Type = Expression` | 类型注解。运行时忽略,除非模块清单开启 `strict_types`(§9.4),此时在调用边界按 `TYPE` 名做顶层形状检查,失配产生 `E0033` |

方法约定:实例方法(对象册 §13.2)的第一个形参**应当**命名为 `self`;该名字是接收者注入(§4.6)的触发条件。

### 5.2.1 类型注解的静态解释

§5.2 的 `name: Type` 有两套解释,互不干扰:

| 开关 | 层 | 缺省 | 失配码 |
|---|---|---|---|
| `strict_types`(§9.4) | 运行期边界检查 | `false` | `E0033` |
| `gradual_typing`(§9.4) | 编译期静态契约 | `off` | `E0110`–`E0112` |

两者**正交**:可同时开启,先静态拦、再运行时兜底。`gradual_typing` 取 `"off"` / `"warn"` / `"error"`,分别对应**不执行整条静态链路**(零开销的保证)/ 发 `W0110`–`W0112` 不阻塞 / 发 `E0110`–`E0112` 并以退出码 `1` 终止。

**注解类型**(§2.6)的静态规则:

- 结构一致 + **安全的数值放宽**:`INTEGER` 满足 `FLOAT`(运行期的 silent upcast 接受它,静态层的判定**必须**一致,否则会拒掉运行期认为合法的程序);反方向 `FLOAT` 满足 `INTEGER` **不**成立;
- `OPTION[T]` 额外承认 `NULL` 与 `RESULT[T, ·]`,但**该糖不泄漏**到别的注解(`NULL` 不满足 `RESULT[INTEGER, STRING]`);
- 未标注处落 `DYNAMIC`;`DYNAMIC` 与任何类型双向可赋值,因此**不产生诊断**。

**类型变量 `T: Bound` 与运行期擦除**:

- 语法是**裸标识符 + 显式约束**,在**顶层注解与方括号内的类型参数**两处都认(附录 A 的 `BoundedVar`)。本规范**没有量词语法** —— `FUN[T]` 形式的泛型声明不存在,同一个变量在每个出现位置都要重写约束;
- 裸的未知类型名(`x: Foo`)**不是**变量,而是不透明类型:语言没有声明名义类型的语法,没人认识的名字要么是拼错了、要么是某个运行期类型。`LET(x: Foo, 1)` 因此报 `E0110` —— 泛型语法**没有**削弱这条诊断;
- 变量在**调用点**被实参实例化,返回类型里的同名变量随之代入;**运行期完全擦除**:`Value` 模型没有增加任何东西,变量在运行期不存在。违反约束的调用在运行期**不被拦截**(没有 monomorphization 就没有运行期类型检查器),它只在 `gradual_typing` 开启时被静态层抓住;
- 唯一的约束是 `Comparable`。成员集合**对着运行期比较算子量出来**,下表即「成员」的可判定形式:

  | 类型 | 运行期比较算子 | 静态层 `Comparable` |
  |---|---|---|
  | `INTEGER` | 支持 | 成员 |
  | `FLOAT` | 支持 | 成员 |
  | `STRING` | 支持 | 成员 |
  | `BOOLEAN` | `E0030` | 非成员 |
  | `NULL` | `E0030` | 非成员 |
  | `ARRAY` / `DICT` | `E0030` | 非成员 |
  | 函数 / 闭包值 | `E0030` | 非成员 |
  | `CLASS` / `INSTANCE` | `E0030` | 非成员 |
  | `RESULT` | `E0030` | 非成员 |

  两层**必须**逐项一致,否则会出现「check 说行、run 抛错」。这张表就是一致性的验收形式:比较算子每新增一个成员,**必须**同时出现在两列。

**覆盖率边界(必须如实声明)**:编译期静态层**只**检查**用户定义的、带注解的**函数边界与模块契约;内建调用的返回类型只在注册表**已结构化**的条目上可知,其余落 `DYNAMIC` 而不产生诊断。

**说明**:本节所谓**已结构化** = 注册表条目的形参表非空。其余内建的形参不可知,调用点不做实参比对。附录 G 的「ERR 消费者 / 宏构造」两列记录每个内建消费的 `ERR` 面,与本条正交。

### 5.3 调用与元数

设必需参数数为 `R`、形参总数为 `N`(含默认与剩余):

- 无剩余参数:`R ≤ 实参数 ≤ N`。省略的尾部实参由默认表达式填充;无默认而缺位产生 `E0022`。
- 有剩余参数:`实参数 ≥ R`;超出固定形参的实参收集为剩余数组。
- 违反范围产生 `E0022`,消息形如 `expects R..N argument(s), got A`。

### 5.4 函数是一等值

函数值**可以**存储、传递、返回、放入容器,没有名与值的区别。递归经由顶层绑定即可实现(调用时解析名字):

```wlwl
LET(fib, FUN((n), IF(<(n, 2), n, +(fib(-(n, 1)), fib(-(n, 2))))));
PRINT(fib(10));          // 55
```

## 6 控制流

### 6.1 IF

```
If = "IF" "(" Expression "," Expression [ "," Expression ] ")" .
```

`IF` 在条件位置注册为 `ERR` 消费者:**条件为 `ERR` 时等价于条件为假** —— 若存在第三实参(else),求 else 并以其值为结果;否则 `IF` 整体透传该 `ERR`。

条件非 `ERR` 时:条件为真(§2.3)求第二实参并以其值为结果,否则求第三实参(若有)并以其值为结果,缺省第三实参时结果为 `NULL`。**未求值的分支不产生任何效果。** 分支表达式自身产生的 `ERR` 正常传播。

### 6.2 WHILE

```
While = "WHILE" "(" Expression "," Expression ")" .
```

条件为真时反复求值体。`WHILE` 表达式的值是 `NULL`。体产生的 `ERR` 终止循环并传播。

### 6.3 FOR

```
For = "FOR" "(" identifier "," Expression "," Expression ")" .
```

对可迭代对象逐项求值体。可迭代对象是:数组(逐元素)、字典(按**插入序**逐键)、字符串(逐码点,绑定单字符字符串)。循环变量在每次迭代是**新绑定**,体结束后即不可见。`FOR` 表达式的值是 `NULL`。体产生的 `ERR` 终止循环并传播。

### 6.4 提前退出

- `RETURN(expr?)`:从最内层函数返回,值为 `expr`(缺省 `NULL`)。
- `BREAK()`、`CONTINUE()`:终止 / 跳过最内层 `WHILE` 或 `FOR`。

三者出现在函数或循环体之外时产生 `E0014`。

## 7 模式匹配

### 7.1 语法

```
Match  = "MATCH" "(" Expression "," ClauseArray [ "," Expression ] ")" .
ClauseArray = "[" [ Clause { "," Clause } ] "]" .
Clause = "[" Pattern "," Expression "]" .
```

`MATCH` 按字面顺序试各子句的模式;首个命中的子句的右值被求值并作为 `MATCH` 的值。无命中且省略默认表达式时,值为 `NULL`。

### 7.2 模式

```
Pattern = identifier | wildcard | Literal | ArrayPattern | DictPattern | VariantPattern .
wildcard       = "_" .
ArrayPattern   = "[" [ Pattern { "," Pattern } [ "," "*" identifier ] ] "]" .
DictPattern    = "[" Key ":" Pattern { "," Key ":" Pattern } ]" .
VariantPattern = "OK" "(" Pattern ")" | "ERR" "(" Pattern ")" .
```

- 标识符模式绑定该名;通配符 `_` 匹配任意值不绑定。
- 字面量模式按 §2.4 相等匹配。
- `OK(p)` / `ERR(p)` 匹配 `RESULT` 的对应变体并继续匹配载荷;对非 `RESULT` 值失配。
- 数组、字典模式按结构匹配;数组可捕余(`*rest`),字典可部分匹配(值**必须**包含全部模式键)。

### 7.3 语义

- 模式匹配的形状**必须**穷尽:子句或默认表达式终将被选中。
- 模式绑定的作用域**仅为**对应分支;分支体是一个新作用域,绑定在其中遮蔽外层同名绑定,分支结束后不可见。
- 模式与值形状失配不算错误,只是不命中;`LET` 解构(§3.1)失配则是错误 `E0026`。

### 7.4 静态诊断(编译期)

开关 `[features] match_exhaustiveness`,取值 `"off"` / `"warn"` / `"error"`;**缺省跟随 `gradual_typing`**,两个开关**独立**(可只关 MATCH 而保留其它静态检查)。

| 条件 | `error` 档 | `warn` 档 |
|---|---|---|
| 子句没盖住被检查值的**可枚举构造子空间** | `E0116` | `W0116` |
| 某个子句 / default 臂**永远跑不到** | `W0117`(恒警告) | `W0117` |

三条语义,顺序即重要性:

1. **非穷尽以「default 臂被省略」为前提。** §7.1 规定省略默认表达式时值为 `NULL`,即 `MATCH` 恒为全覆盖 —— 所以「子句没盖满」本身**不是**错误,作者写了 default 就是有意兜底,再报一遍纯噪声。要报的是**省略了 default 却没盖满**:那种情况下漏掉的分支**静默得到 `NULL`**,是个真陷阱。诊断会**列出**缺的具体构造子。
2. **可枚举的构造子空间只有三种**:`BOOLEAN` → `{TRUE, FALSE}`;`NULL` → `{NULL}`;`RESULT` → `{OK(_), ERR(_)}`。整数 / 浮点 / 字符串是无限域,`ARRAY` / `DICT` 按元数 / 键集无限展开 —— 这几类**不报非穷尽**,报了就是误报。
3. **`W0117` 恒为警告,并且没有 `E0117`。** 不可达子句通常出现在渐进重构的中间态(先留兜底臂、再逐条细分),当成硬错会拦下正在写的代码。`E0117` 是**故意不存在**的码号(§11.2),不是保留名。

可达性判定只对**可判定**的情况给结论:子句被前面的子句盖住、通配之后还有子句、重复字面量、闭合容器下的死 default 臂。

**说明**:「可盖住」的形式定义是:子句 `C` 被子句 `P` 盖住 ⟺ `P` 的模式与 `C` 的模式有交集。可判定的有两类:

- **字面量子句**:`P` 与 `C` 都是闭合字面量集合时,交集非空即盖住;
- **通配子句**:`P` 含 `_` 时盖住其后的**任何**子句。

数组 / 字典的穷尽性**不判定**:`[1, _]` 与 `[_ , 2]` 的并集可盖住 `[_ , _]`,而任一行单独都盖不住 —— 交集非空但并集才构成覆盖,判不了。

## 8 错误模型

### 8.1 RESULT

`OK(v)` 把任意值 `v` 包装为 `RESULT` 的成功变体;`ERR(e)` 把载荷 `e` 包装为失败变体。`e` **必须**是字符串或字典,否则产生 `E0030`。

**说明**:推荐以字典载荷携带结构化字段(`kind`、`input` 等),便于程序化消费。

并发与通道产生的结构化 `ERR` 使用字典载荷,`kind` 字段取下列值之一(载荷仍**必须**是 STRING 或 DICT,不变):

| `kind` | 产生处 |
|--------|--------|
| `"ChannelClosed"` | `CHANNEL_RECV` / `CHANNEL_TRY_RECV` 在通道已关闭且缓冲已读空时(含被 `CHANNEL_CLOSE` 唤醒的挂起接收方) |
| `"Cancelled"` | `AWAIT` 一个已取消的任务;载荷含 `reason` 字段(并发册 §17.3) |

`ERR(kind="ChannelWouldBlock")` **没有**触发路径:阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在满 / 空时挂起(并发册 §17.2),非阻塞形态 `CHANNEL_TRY_SEND` / `CHANNEL_TRY_RECV` 以布尔或 `NULL` 报告,不经 `ERR` 载荷。

关闭信号**必须**用 `IS_ERR` + `ERR_PAYLOAD` 的 `kind` 识别;`NULL` **不得**作为关闭信号。

取消载荷的 `reason` 字段是发起取消时传入的 `DICT`(缺省空字典)。

### 8.2 透明传播

**任何不在消费者注册表(§8.3)内的函数调用** —— 内建或用户定义 —— 若任一实参求值为 `ERR`,则该调用不求函数体,直接以该 `ERR` 为调用结果。传播不消耗、不改写 `ERR`。于是未显式处理的错误沿调用链上浮,直到被消费者处理或逃逸到顶层(§8.5)。

**本节的规范对象是函数调用。** `SET` 与 `LET` 是语句形式,不适用本节的透传。

`SET` 与 `LET` 同属「装盛」:`SET(z, ERR("x"))` 把 `ERR` 写进单元格,随后 `IS_ERR(z)` / `ERR_PAYLOAD(z)` **可以**正常消费它。因此 `SET(z, ERR("x"))` 作为末条语句时 `rc=0`、不报 `E0102` —— 与 §8.5 同属一类,不是违反。两者取同一口径:若 `SET` 透传而 `LET` 不透传,同样的装盛动作会因写法不同而语义不同,反而更危险。

`&&` / `||` 短路求值时,未求值的那一侧不产生任何效果(包含副作用与 `ERR` 传播):仅被选中求值的那一侧的 `ERR` 才会沿当前调用链上浮。

**推论(错误处理惯用法)**:检查并消费一个 `ERR` 值**必须**在拥有它的作用域内进行 —— 先以注册表消费者(`IS_ERR`、`ERR_PAYLOAD`、`UNWRAP_OR` 等)提取信息或兜底,再把**提取结果**(字符串、字典等普通值)传给其他函数:

```wlwl
LET(r, ERR("boom"));                    // r 是 ERR
LET(p, ERR_PAYLOAD(r));                 // 在此处消费,p 是普通值
PRINT(FORMAT("failed: {0}", p));        // 传普通值,安全
```

把 `ERR` 值原样作为实参传给普通函数(包括「渲染函数」「检查函数」)只会触发传播,函数体永不执行:

```wlwl
// ERR 作为实参触发透明传播,函数体不执行
LET(show, FUN((r), IF(IS_ERR(r), "E", "O")));
LET(r, ERR("x"));
LET(y, show(r));          // y = ERR("x") — show 的体永不执行
PRINT(TYPE(y));           // "RESULT"
LET(_, y);                // 显式丢弃 y 持有的未消费 ERR(§8.6.4)
```

**未消费的 `ERR` 必须被消费或显式丢弃**:传播把 `ERR` 交给了 `y`,而 `PRINT(TYPE(y))` 只是**观察** `y`、**不**消费它 —— 读完之后 `y` 里仍持有一个未消费的 `ERR`,程序会以 `E0103` 终止(§8.6)。末行的 `LET(_, y)` 是本语言唯一的显式丢弃构造(§8.6.4),它让这段代码正常退出。

`OK` 包装**可以**阻断传播 —— 此后按 §2.4,`OK` 与 `ERR` 永不相等,且 `IS_OK(OK(...))` 为真。将 `ERR` 装入数组或字典能通过**当前**求值,但取出元素再作实参时会再次触发传播 —— 装盛不是消费。唯一合法的消费路径是 §8.3 的注册构造。

**说明**:把 `ERR` 放在末条语句上会走顶层逃逸(§8.5)并以 `E0102` 终止程序,而不是静默通过 —— 下面这段**预期**以 `E0102` 终止,不作为可运行示例:

```
LET(show, FUN((r), IF(IS_ERR(r), "E", "O")));
LET(r, ERR("x"));
show(r);                  // 末条语句的值是 ERR → E0102,程序终止
```

### 8.3 消费者注册表

以下构造消费 `ERR` 而不触发 §8.2 的传播(它们的**实参位置**是注册的 `ERR` 合法入口;返回值是普通值,可自由传递):

| 构造 | 对 `ERR` 的行为 |
|------|-----------------|
| `IS_OK(x)` / `IS_ERR(x)` | 返回布尔,不消耗载荷 |
| `UNWRAP_OR(x, d)` / `OR_DIE(x, d)` | `ERR` 时返回 `d`;`OK(v)` 时返回 `v`(`OR_DIE` 是弃用别名) |
| `TRY(x)` | `ERR` 时等价于 `RETURN(err)`,`OK(v)` 时取 `v`;只能在函数体内使用 |
| `UNWRAP(x)` | `OK(v)` 取 `v`;`ERR` 产生 `E0100` PANIC |
| `ERR_PAYLOAD(x)` | `ERR(e)` 取 `e`;对 `OK` 或非 `RESULT` 产生 `E0030` |
| `WRAP(x, ctx)` | `ERR(e)` 包装为 `ERR(["original": e, "context": ctx])`;`OK(v)` 原样返回 |
| `TYPE(x)` | 返回 `"RESULT"` |
| `==` / `!=` | 按 §2.4,对 `ERR` 操作数透传而非消费 |
| `IF` | 条件位置消费:条件为 `ERR` 时等价于条件为假;若存在 else 则求 else,否则 `IF` 整体透传该 `ERR` |
| `&&` / `\|\|` | 短路消费:左为 `ERR` 时透传 `ERR`(不求右);右为 `ERR` 时按 §8.2 透传 |
| `BOOL(x)` | 返回真值化结果(`BOOL(ERR(...))` 与 `BOOL(OK(0))` 等),**不**透传 `ERR` |
| `EXPECT_ERR(x)` | 供测试使用;`x` 为 `ERR` 时返回 `OK(载荷)`,否则返回 `ERR(E0049)` |

本表不新增条目。对象册与并发册的内建(`CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` 与全部并发原语)**均不是**消费者:实参为 `ERR` 时按 §8.2 透明传播。

**说明**:本表把「消费」一词用在一个宽泛意义上 —— 它只表示「该构造的实参位置是 `ERR` 的合法入口」。就 §8.6 的未消费判定而言,本表的条目还要按**取走型**与**观察型**再分一次,见 §8.6.1。

### 8.4 PANIC

`PANIC(msg)`,`msg` **必须**是字符串或字典,立即以诊断 `E0100` 终止程序(§11.4)。PANIC 不参与透明传播。`UNWRAP` 于 `ERR`、以及 `INTEGER` 下界取负(`E0034`)同样以 PANIC 终止。

### 8.5 顶层逃逸

`ERR` 到达程序顶层而未被消费时,实现**必须**以诊断 `E0102` 报告该载荷并以退出码 1 终止。

作为表达式语句被求值并被丢弃的表达式,其值若为 `ERR`,按它在顶层的位置分三种情形:

| 顶层语句 | 行为 |
|---|---|
| 末条是 `ERR(...)`(值成为程序值) | `E0102`,rc=1 |
| 首条 / 中间一条是 `ERR(...)` | 该语句值被丢弃,是丢弃点(§8.6.2),报 `E0103` |
| 末条是 `LET(r, ERR(...))` / `SET(z, ERR(...))` | `ERR` 进了单元格,不外泄;该绑定若此后仍未被消费,在作用域结束时按 §8.6.2 报 `E0103` |
| 末条是 `WHILE(...)` / `FOR(...)`,体产出 `ERR` | `E0102`,rc=1(体按 §6.2 / §6.3 传播) |

**`LET` / `SET` 绑定不算「消费」**:§8.2 的规范性示例里 `LET(r, ERR("boom"))` 的 `r` 就是 `ERR`,随后由 `LET(p, ERR_PAYLOAD(r))` 消费 —— 若绑定触发传播,那条示例直接不成立。§8.2 另有明文:「将 `ERR` 装入数组或字典能通过**当前**求值……**装盛不是消费**」。绑定与装盛同属装盛。

**说明**:错误处理惯用法因此只有下列几种合规写法:把会失败的表达式放在**末条**以走顶层逃逸;用注册表消费者(`IS_ERR` / `UNWRAP_OR` / `TRY` / `ERR_PAYLOAD`)把它显式消费掉;用 `LET(_, …)`(§8.6.4)显式丢弃;或用 `LET` / `SET` 把 `ERR` 收进单元格后再检查。

### 8.6 未消费 `ERR` 的报告

**未消费的 `ERR` 不得被丢弃。** 持有未消费 `ERR` 的值一旦在某个丢弃点被丢弃,实现**必须**产生诊断 `E0103`(§11.2)并以退出码 1 终止。

本节的三条支柱:未消费的定义(§8.6.1)、丢弃点的确切清单(§8.6.2)、以及错误状态在绑定之间的转移(§8.6.3)。

#### 8.6.1 未消费的定义

一个 `ERR` 值是**未消费**的,当且仅当它同时满足下列三条:

1. 它尚未被**取走型**消费者取走;
2. 它尚未被**显式丢弃**(§8.6.4);
3. 它尚未作为程序值逃逸到顶层(§8.5)。

消费者按是否把 `ERR` 的载荷取走分成两类:

| 类别 | 成员 | 效果 |
|---|---|---|
| **取走型** | `ERR_PAYLOAD` / `UNWRAP_OR` / `OR_DIE` / `TRY` / `UNWRAP` / `WRAP` / `EXPECT_ERR` | 该 `ERR` 被取走,不再处于未消费状态 |
| **观察型** | `IS_ERR` / `IS_OK` / `BOOL` / `TYPE` / `==` / `!=` | **不**取走载荷;来源是**绑定**时,未消费状态留在该绑定(§8.6.3) |

`OR_DIE` 是 `UNWRAP_OR` 的弃用别名,归入取走型。

**说明**:观察型消费者只「看一眼」。`IS_ERR` / `IS_OK` / `BOOL` / `TYPE` 只看不带走 —— 来源是绑定时,`ERR` 仍留在被读取的绑定里;来源**不是**绑定时(典型是一个调用的结果值),没有绑定可留下该状态,该 `ERR` 在观察中**结清**(§8.6.3)。`==` / `!=` 按 §2.4 透传该 `ERR`,但不消费它 —— 透传意味着该 `ERR` 继续到结果值,未消费状态随之转给结果值。

**条件位**的 `ERR`(`IF` 的条件、`&&` / `||` 的左操作数)按 §8.3 登记,**不**取走载荷;它的去向见 §8.6.3。

#### 8.6.2 丢弃点

一个持有未消费 `ERR` 的值被丢弃时,实现**必须**产生诊断 `E0103`(§11.2)并以退出码 1 终止。丢弃点**恰好**有三处:

1. **语句值丢弃** —— 一个表达式语句的值被丢弃,即该值既不成为所在作用域的返回值或括号序列的值,也不成为程序值(§9.5)。
2. **绑定被覆盖** —— 持有未消费 `ERR` 的绑定被改写:同作用域重绑定(§3.2)或 `SET` 改写单元格(§3.4)。
3. **作用域结束时仍未消费** —— 作用域(§3.2)结束时,仍有绑定持有未消费 `ERR`。

**说明**:遮蔽(§3.2)**不**构成丢弃点 —— 内层作用域的 `LET` 建立新单元格,外层绑定不受影响;外层绑定里的 `ERR` 在外层作用域结束时按第 3 项处置。容器装盛(把 `ERR` 放进数组或字典)**不**构成丢弃点,它构成转发(§8.6.3)。

**程序值不属丢弃点**:顶层最后一个表达式的值是程序值,它按 §8.5 报 `E0102`,**不**报 `E0103`。

#### 8.6.3 转发

绑定被读取时,其中的未消费状态随之转移:

- 读入**取走型**消费者(§8.6.1)→ 该 `ERR` 视为已消费;
- 读入**观察型**消费者(§8.6.1)→ `IS_ERR` / `IS_OK` / `BOOL` / `TYPE` 只看不带走:来源是**绑定**时,未消费状态留在被读取的绑定;来源**不是**绑定时(典型是一个调用的结果值),没有绑定可留下该状态,该 `ERR` 在观察中**结清** —— 它不取走载荷,但不再处于未消费状态,也**不**产生 `E0103`。`==` / `!=` 按 §2.4 透传,该 `ERR` 继续到结果值,未消费状态随之转给结果值;
- 读入**其它任何位置** → 由接收方承担:接收位置建立绑定时,未消费状态转给该绑定;接收位置是语句值时,该语句值是一个未消费的 `ERR`,在丢弃点被处置(§8.6.2)。

**说明(观察的来源不是绑定时)**:观察的语义是「看一眼这个错误」。来源是绑定时,看一眼之后该 `ERR` 仍在那个绑定里,于是它仍可能在下一次被真正处理 —— 这正是 §8.6.4 那个例子的形状。来源不是绑定时(观察的是一个**调用的结果**),观察之后没有任何地方还持有它:再报一次只是噪声,而噪声会让 `E0103` 自己变成新的误报源。⇒ 观察**结清**它。

⚠ 这一条不是可有可无的细节:它决定 `IS_ERR(<某个 std 成员>(…))` 这类**极常见**的写法会不会误报。读模式**只作用于当前位置**(§8.6.3 的三条转发规则都是关于「读入某位置」),因此调用体内的读**不继承**调用点的观察模式 —— 否则被调体自己的作用域结束会按 §8.6.2 第 3 项报 `E0103`。

**条件位**是「其它位置」的一种,按 §8.6.1 的登记与 §8.3 的语义处理:

- `IF` 有 else 臂时,条件位的 `ERR` 被该 `IF` 放弃 —— 该 `ERR` 不在接收位置继续,未消费状态留在被读取的绑定;
- `IF` 无 else 臂时,条件位的 `ERR` 是 `IF` 的结果值(§8.2 透传),未消费状态转给该结果值;
- `&&` / `||` 的左操作数为 `ERR` 时,该 `ERR` 是该构造的结果值(§8.2 透传),未消费状态转给该结果值。

**说明**:容器装盛**不算消费**(§8.2)但**算转发** —— 把 `ERR` 放进数组或字典,未消费状态转给该容器;容器本身在丢弃点被处置。`LET(a, err); LET(b, a); ERR_PAYLOAD(b);` 因此**不**误报:`b` 取走了那个 `ERR`,`a` 的状态在读取时已转出。

```wlwl
LET(a, ERR("boom"));            // a 持有未消费的 ERR
LET(b, a);                       // 转发:b 承担未消费状态
LET(p, ERR_PAYLOAD(b));          // 取走型消费者:已消费
PRINT(p);                        // boom
```

**未消费状态是**集合**,不是单个标志。** 一个绑定、一个容器、一个数组元素序列,都**可以**同时持有多个未消费的 `ERR`。因此:

- **汇入同一接收位置时取并集** —— 多个未消费 `ERR` 转给同一个绑定或容器时,**全部**保留,不是「保留第一个」也不是「后者覆盖前者」;
- **丢弃时逐个报告** —— 一个丢弃点上丢弃的集合里有几个 `ERR`,就产生几条 `E0103`(§8.6.5 保证每个 `ERR` 至多一次)。诊断按它们在容器中的**出现序**排列 —— 顺序是规范的一部分(§11.1),不随实现而变;
- **取走型消费者取走的是它拿到的那个 `ERR`** —— 容器里还剩几个,不受它影响。

**说明**:本节的"转发"因此不是**一对一**的搬运,而是**状态集合的搬运**。只记「这个绑定有没有未消费 `ERR`」的表示无法满足本节 —— 那是实现侧的代表性问题(一致性册 §5.4 的 X-06),不是本节的缺口。

#### 8.6.4 显式丢弃

`LET(_, expr)` 是本语言**唯一**的显式丢弃构造(§3.1)。它把 `expr` 求值后**不**建立任何绑定,因而未消费状态不转给任何绑定 —— 该 `ERR` 被显式丢弃,**不**产生 `E0103`。

实现**不得**提供其它显式丢弃构造;任何其它形式的丢弃按 §8.6.2 处理。

```wlwl
LET(_, ERR("boom"));       // 唯一的显式丢弃:不报 E0103
PRINT("ok");               // ok
```

**说明**:观察与处置是两回事 —— 观察不解除未消费状态,处置才解除:

```wlwl
LET(r, ERR("boom"));
PRINT(IS_ERR(r));          // TRUE — 观察型消费者不解除未消费状态
LET(_, r);                 // 之后显式丢弃
```

#### 8.6.5 只报告一次

一个 `ERR` **至多**被报告一次。实现报告 `E0103` 后,该 `ERR` 视为已处理,后续丢弃点**不得**对它重复报告。

**说明**:这条约束让一次失败对应一条诊断。若不设它,同一个 `ERR` 在语句值丢弃与作用域结束时会被各报一次,读者无从判断是两次失败还是一次。

## 9 模块与程序

### 9.1 文件即模块

每个源文件是一个模块。模块顶层**可以**有 `EXPORT(name_array)`;未导出的绑定对外不可见。

模块顶层还**可以**有 `SEALED(name_array)`,声明本模块的**完整公开面**:

```
SealedDecl = "SEALED" "(" name_array ")" .
```

`SEALED([...])` 列出的名字就是**全部**对外可见的名字:多导出任何一个(`EXPORT` 有而 `SEALED` 没有)产生 `E0113`,声明了却不导出产生 `E0114`(§11.2,需 `gradual_typing` 开启)。**未写 `SEALED` 的模块没有任何契约** —— 没有声明就没有契约,不存在「忘了写标记」这回事。

`SEALED` 是**声明**而非求值构造:运行期不产生任何值、不改变任何绑定(与 `EXPORT` 同为 no-op),它只被编译期读取。越界访问在运行期仍按 §9.2 的 `E0023` 报告,`SEALED` 不改变这条规则。

### 9.2 IMPORT 与 MODULE_REF

```
Import = 'IMPORT' "(" string_lit "," name_array ")" .
name_array = "[" [ NameItem { "," NameItem } ] "]" .
NameItem = string_lit | string_lit ":" string_lit | identifier .
```

- `IMPORT(path, ["a", "b"])` 将模块 `path` 的导出名 `a`、`b` 绑定到当前作用域。
- `["orig": "alias"]` 将导出名 `orig` 绑定为本地名 `alias`(重命名)。
- 路径以 `./`、`../` 开头时按文件系统相对解析(后缀 `.wll` 可省);形如 `wlwl:std.*` 的路径指向标准库命名空间(§9.3)。
- 模块不存在产生 `E0040`;导出名不存在产生 `E0023`;循环导入产生 `E0041`。
- 同一作用域内重复导入同一名字产生 `E0021`。

`MODULE_REF(path) -> DICT` 加载并返回**模块字典**(导出名 → 值),**不**把任何名字绑定到当前作用域。

**说明**:其返回字典与 `IMPORT` 展开后可绑定的值集合不可区分;它不是新的模块机制,而是 `IMPORT` 的非绑定形式,供运行时动态加载、测试与自省使用。加载失败(`E0040` / `E0041` 等)原样以诊断形式报告。

模块本身是字典值;模块字典的属性读写按 §4.6 的字典规则。

### 9.3 标准库命名空间

`wlwl:std.` 前缀的路径由实现直接提供,不经文件系统:`wlwl:std.io`、`wlwl:std.fs`、`wlwl:std.json`、`wlwl:std.collection`、`wlwl:std.format`、`wlwl:std.test`、`wlwl:std.str`、`wlwl:std.math`。

`wlwl:std.ai` / `wlwl:std.agent` **不由**本前缀提供:它们是**官方包**,经 `"ai:ask"` / `"agent:task"` 导入,旧路径**不再解析**。`wlwl:` 是标准库的**保留前缀**,因此官方包**不能**写成 `wlwl:ai` —— 那会落进「裸模块名」分支、被当成文件名,最终 `E0040`。

**说明**:成员面(名字 / 签名 / 语义)与 `wlwl:std.*` 的对应成员一致,变的只有可见面。

各命名空间按**实现分层**归入语言层(纯 wlwl)、原生层(Rust)或混合实现;无论归属哪一层,同一成员的名字、签名与语义**必须**一致,调用方式不因实现层而异。分层归属表与各命名空间的成员契约见[标准库册](../stdlib/)。实现**可以**提供开发期加载覆盖,这是非规范性的实现自由度,**不得**改变任何成员的名字与语义。

### 9.4 清单文件

模块目录**可以**包含 `wlwl.toml` 清单,声明包名、语言版本与特性开关。本规范定义以下特性:

| 特性 | 默认 | 含义 |
|------|------|------|
| `strict_types` | `false` | 开启 §5.2 类型注解的调用边界检查(`E0033`) |
| `allow_builtin_shadow` | `false` | 允许遮蔽内建名(§3.5),以 `W0030` 代替 `E0025` |
| `strict_deadlock_detect` | `true` | 死锁检测 L1 的严格模式开关(§11.2 `E0065` / §11.3 `W0065`)。为 `true`(或缺省)时触发即抛 `E0065`;为 `false` 时降级为 `W0065` 并以 `E0053` 报告 |
| `native_channel_close` | `false` | 为 `true` 时,关闭后 `RECV` / `TRY_RECV` 在缓冲读空后改抛硬诊断 `E0054`,而不是返回 `ERR(kind="ChannelClosed")` |
| `channel_large_buf_threshold` | `1024` | `CHANNEL_NEW(buf)` 的软阈值;`buf` 超过该值产生 `W0066`。取 `0` 关闭该警告 |
| `gradual_typing` | `off` | 编译期静态契约层的严重级(§5.2.1):`"off"`(不执行整条静态链路)/ `"warn"`(`W0110`–`W0112`)/ `"error"`(`E0110`–`E0112` 阻塞退出码)。与运行期 `strict_types` **正交** |
| `match_exhaustiveness` | 跟随 `gradual_typing` | `MATCH` 穷尽性 / 不可达子句的严重级(§7.4)。缺省跟随 `gradual_typing`,但**独立生效**,故可只关 MATCH 而保留类型检查 |

清单的其余字段(依赖、版本求解、锁文件)属于包管理器职责,不在本规范内。

### 9.5 程序入口

被运行的文件即入口模块;其顶层表达式按顺序求值。**程序值**是顶层最后一个表达式的值;其余顶层表达式的值被丢弃(丢弃点见 §8.6.2)。顶层求值产生的 `ERR` 按 §8.5 处理。

### 9.6 模块契约

一个模块**可以**有旁路签名文件 `<module>.wll.sig`(与源文件同目录,文件名后追加 `.sig`)。它记录该模块对外承诺的名字与类型,文法见附录 E.1。三个方向都会被检查(需 `gradual_typing` 开启):

| 条件 | 码 |
|---|---|
| 实现 `EXPORT` 了、或外部 `IMPORT` 了签名没声明的名字 | `E0113` |
| 签名声明了实现没有导出的名字 | `E0114` |
| 签名里的类型与实现注解冲突 | `E0115` |

**说明**:三条设计后果如下。

- **无签名 = 无契约**,这是**结构性**保证而不是约定:语言里没有任何内嵌的「这是签名」的标记语法,签名是**旁路文件**,不存在「忘了写签名标记」这回事;
- **签名是给消费方看的契约,密封面是模块自己划的私有线。** 所以 `IMPORT` 用了签名没声明的名字报 `E0113`(消费方在依赖一个没承诺过的东西),而 `SEALED` 只在模块自查那一侧比对(§9.1)—— 越界是模块自己的问题,不该让每个调用点各背一条诊断;
- 类型表达式与注解**同一套文法**(§2.6),因此类型变量 `T: Comparable` 在签名里同样可表达。

签名的发现与比对由实现提供:`wlwl sig-gen <file>` 生成骨架,`wlwl check` 沿 import 图验证;`wlwl interface <file>` 把同一份承诺以 JSON 暴露(附录 E.2)。

## 10 标准库

### 10.1 约定

- **全局内建**:§10.2–§10.5、§10.7(`FORMAT`)、§10.9、§10.12 的名字无须导入即可调用。
- **命名空间成员**:§10.6、§10.8、§10.10、§10.11 的名字**必须**经 `IMPORT` 导入。
- 除注明外,容器操作都是**非破坏性**的:返回新容器,接收者不变;更新绑定用 `SET`(§3.4)。
- 对 `ERR` 实参:全局内建按 §8.2 透明传播;接受回调的命名空间成员,其回调抛出的 `ERR` 同样使整个调用传播。

**说明**:第 10 章只保留语言表面(全局内建)与命名空间的机制性条目;各命名空间的成员表、语义细节与错误码的触发归属归[标准库册](../stdlib/)。标准库册与本册**互不重复定义**:本册定义「怎么导入、叫什么、怎么与语言交互」,标准库册定义「每个成员做什么」。

### 10.2 I/O

| 签名 | 说明 |
|------|------|
| `PRINT(args...) -> NULL` | 依序渲染实参(§2.5),以空格分隔输出到标准输出 |
| `PRINT_ERR(args...) -> NULL` | 同上,输出到标准错误 |
| `INPUT(prompt?) -> STRING` | 读一行标准输入 |

### 10.3 类型与转换

| 签名 | 说明 |
|------|------|
| `LEN(coll) -> INTEGER` | 数组元素数、字典键数、字符串码点数 |
| `TYPE(x) -> STRING` | §2.1 类型名;`RESULT` 报 `"RESULT"` |
| `STR(x) -> STRING` | 渲染为文本(§2.5) |
| `INT(x)` | 整数→恒等;浮点→向零截断;字符串→解析整数,失败返回 `ERR(["kind": "ParseError", "input": s])` |
| `FLOAT(x)` | 浮点→恒等;整数→提升;字符串→解析,失败同上 |
| `BOOL(x) -> BOOLEAN` | 真值(§2.3);对 `ERR` 直接返回布尔而不透传(§8.3) |
| `CALL(fn, args...)` | 动态调用 `fn` 并传递 `args...`;`fn` 不是函数值产生 `E0020` |

### 10.4 容器操作(全局)

| 签名 | 说明 |
|------|------|
| `PUSH(arr, x) -> ARRAY` | 尾部追加的新数组 |
| `UNSHIFT(arr, x) -> ARRAY` | 头部插入的新数组 |
| `SHIFT(arr) -> ARRAY` | 去除首元素的新数组 |
| `AT_K(d, k, default) -> v` | 字典取值:`k` 存在返回其值,否则返回 `default`;不修改 `d` |
| `SLICE(arr, start, end?) -> ARRAY` | 区间 `[start, end)`;负索引自尾部计数;缺省 `end` 到末尾;越界部分截为空 |
| `CONCAT(a, b) -> ARRAY` | 两数组连接 |
| `CONTAINS(coll, x) -> BOOLEAN` | 成员测试;亦接受字符串(子串) |
| `INDEX(arr, x) -> INTEGER` | **值 → 位置**查找,返回 `x` 首次出现的 **1-based** 位置;无则 `-1` |
| `REVERSE(arr) -> ARRAY` | 逆序副本 |
| `INDEX_GET(coll, k) -> v` | 见 §4.5 |
| `INDEX_SET(coll, k, v) -> ARRAY/DICT` | 见 §4.5;返回更新后的新容器 |
| `AT(coll, k, default) -> v` | 安全下标;越界 / 缺键返回 `default` |
| `KEYS(d) -> ARRAY`、`VALUES(d) -> ARRAY` | 按**插入序** |
| `HAS(d, k) -> BOOLEAN` | 键存在测试 |
| `MERGE(a, b) -> DICT` | `b` 覆盖 `a` 的新字典 |
| `REMOVE_KEY(d, k) -> DICT` | 去键的新字典;键不存在则等价于 `d` |
| `DEL(d, k) -> DICT` | `REMOVE_KEY` 的弃用别名(警告 `W0051`) |

**说明**:数组没有原位弹出;移除字典键用 `REMOVE_KEY`,字典取值用 `AT_K`;通用安全下标用 `AT`。

| 签名 | 说明 |
|------|------|

| `REPLACE(s, old, new) -> STRING` | 全部替换 |
| `UPPER(s)` / `LOWER(s)` | **仅**转换 ASCII 字母;非 ASCII 字符原样保留。非 ASCII 的处理是**实现定义**,且**不产生任何诊断** |
| `TRIM(s)` / `TRIM_START(s)` / `TRIM_END(s)` | 去两端 / 前端 / 尾端空白 |

| `REPEAT(s, n) -> STRING` | 重复 `n` 次 |

### 10.6 集合套件 —— `wlwl:std.collection`

`wlwl:std.collection` 是**命名空间成员**(§10.1),其成员**必须**经 `IMPORT` 导入,导入路径与形态与其它命名空间一致:

```
IMPORT("wlwl:std.collection", ["MAP", "FILTER", "REDUCE", "SORT"]);
```

导入后成员以**裸名**调用。本语言**没有**命名空间限定调用(§10.11),故 `collection.MAP(…)` 一类写法**不得**使用。

**成员面以[标准库册 §5](../stdlib/wlwl-v1.0-stdlib-core.md)为准** —— 名字、签名、语义与失败口径(成员的「失败」列)一律不在本册复述。回调抛出的 `ERR` 按 §10.1 与 §8.2 传播。

### 10.7 格式化 —— `FORMAT`(全局)

`FORMAT(template, args...) -> STRING`:模板中 `{N}` 以第 `N` 个实参的 `STR` 渲染替换;`{name}` 以首个实参为字典按键取值;两类占位符可混用。未匹配的 `{...}` 原样保留;模板畸形(孤立的 `{`)产生 `E0039`。`wlwl:std.format` 命名空间导出同一函数。

**`{N}` 与 `{name}` 混用规则**:`{N}` 的 `N` 自 `0` 起,指 `FORMAT(template, args...)` 中 `args` 的第 `N` 项(template 是第 `-1` 项,不计入索引)。当模板同时含 `{name}` 与 `{N}`:

- 若首个 `args` 项(`{0}`)是 `DICT`,`{name}` 优先在该 `DICT` 中查键;`{0}` 仍按 `STR` 渲染该 `DICT`(例:`["age": 30]` → `"[age: 30]"`)。
- 若首个 `args` 项是标量,`{name}` 在所有 `DICT` 实参中按位置查找首个 `DICT`;`{0}` 渲染该标量。
- 都找不到则占位符保留原样(`{name}` / `{N}` 不抛错)。

### 10.8 JSON 与文件系统

`wlwl:std.json`(`STRINGIFY` / `PARSE`)与 `wlwl:std.fs`(`WRITE_FILE` / `READ_FILE` / `EXISTS`)是**命名空间成员**,**必须**经 `IMPORT` 导入。成员契约 —— 含 JSON 与字典 / 数组 / 标量的映射规则(字典键序、文档序)、文件不存在时的 `E0061` 与解析 / 序列化失败的 `E0070` / `E0071` —— 见[标准库册](../stdlib/)。

### 10.9 构造器

`DICT() -> DICT`:空字典(唯一写法)。`ARRAY() -> ARRAY`:空数组的构造器写法,与字面量 `[]` 等价。非空数组只能用字面量(§4.8)。

带参的 `ARRAY(items...)` 形式**不存在**,非空数组只能用字面量(§4.8);`ARRAY(1, 2)` 报 `E0020: undefined name ARRAY`。零参 `ARRAY()` / `DICT()` 是空容器的构造器写法。

### 10.10 测试 —— `wlwl:std.test`

`wlwl:std.test` 是**命名空间成员**,**必须**经 `IMPORT` 导入。成员契约 —— `TEST` / `ASSERT` / `ASSERT_EQ` / `ASSERT_NEQ` / `EXPECT_ERR` / `RUN_TESTS` 的签名、语义与断言失败码 `E0046`–`E0049` —— 见[标准库册](../stdlib/)。

**说明**:测试体通常以 `ASSERT` 族断言收尾并以 `TRUE` 结束;体求值期间逃逸的 `ERR` 使该项 `passed = FALSE`。

### 10.11 AI 与代理 —— 官方包 `ai` / `agent`

`ai` / `agent` 是**官方包**,**不**由 `wlwl:std.` 前缀提供,经 `"ai:ask"` / `"agent:task"` 导入。

**说明**:两个包的成员面(名字 / 签名 / 语义 / 错误码)与 `wlwl:std.*` 的对应成员一致,变的只有可见面,不是移除成员,故**不走**弃用两步。

成员契约 —— `ASK` / `ASK_STREAM` / `ASK_ALL` / `EMBED` / `COMPLETE` 与 `MODEL` / `TASK` / `TOOL` / `CALL_TOOL` / `CONTEXT` 的签名、语义、错误码语义(`E0080`–`E0083`、`E0090`–`E0094`)与 `W0052` 的触发条件 —— 见[标准库册](../stdlib/wlwl-v1.0-stdlib-official.md);传输与供应商细节属实现文档,不在规范内。

规范层面的两条对接点:`TASK` 返回的任务句柄按并发册 §17.1 经 `AWAIT` 取值,已取消任务的 `AWAIT` 按并发册 §17.3 返回 `ERR(kind="Cancelled", reason: ...)`;用户作用域内裸名 `TASK`(若 `IMPORT` 引入了同名函子)与类型名 `TASK`(§2.1)不构成运行时冲突。

**「全限定写法」在本语言不存在**:文法没有「命名空间限定调用」表达式,冒号只出现在 `IMPORT` 的路径字符串与改名处。`ai:ask.ASK(…)`、`ai.ASK(…)` 与旧式的 `wlwl:std.ai.ASK(…)` **一律解析失败**(`E0011 expected ')' got Colon`)。成员只能经 `IMPORT` 取裸名,或用改名避开与类型名的阅读混淆 —— `IMPORT("agent:task", ["TASK": "AGENT_TASK"])`。

### 10.12 对象模型内建

`CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` 是全局构造,语义见对象册 §13、对象册 §14 与对象册 §15;签名与注册状态见附录 G。

## 11 诊断

### 11.1 结构

诊断是错误(`E`)或警告(`W`),带四位数字码。错误形式的 CLI 输出包含码、消息、位置(文件、行列)与源行摘录;`--format json` / `jsonl` 产生机器可读结构(含 `error_schema_version`、`error_category`、`retryable`、`idempotent`、`suggestion_code`、`trace` 等字段)。死锁检测产生的 `E0065` 的 `error_category` 字段值为 `"deadlock"`。

诊断的**顺序**也是结构的一部分:`E0020`(未定义名,§3.2)附带的候选提示按 **(编辑距离, 名字字典序)** 排序 —— 先比编辑距离,距离相同时再比候选名的字典序。候选提示的顺序因此不依赖任何运行时序:同一份源码的同一处未定义名,在任何一次运行中给出逐字节相同的候选序列。

### 11.4 退出码

| 退出码 | 含义 |
|--------|------|
| `0` | 成功 |
| `1` | 程序不对:运行期诊断(`E0020` 未定义名、`E0022` 元数、`E0100` PANIC、`E0102` 顶层 `ERR`、`E0103` 未消费 `ERR` 被丢弃、`E0065` 死锁检测 …),或静态层拦下的类型 / 契约诊断(`E0110`–`E0116`) |
| `2` | 命令行用法错误(未知子命令、缺参数、互斥选项) |
| `3` | **有输入文件没能解析出来** |
| `101` | 实现内部崩溃(非规范性;出现即属实现缺陷) |

判据是**诊断码**,不是「哪个阶段报的」:

- **`3` = 解析失败**,恰为 parser 产出的 7 个码:`E0001` `E0002` `E0003`(词法)与 `E0010` `E0011` `E0012` `E0013`(语法)。
- **`E0014` 不在其列**,尽管它归 `Syntax` 类别 —— 它是**求值期**的位置错(`YIELD` / `RETURN` 放错地方),源文件本身完全合法,退出码仍是 `1`。
- 「读不出来的文本」出现在**旁路签名文件**里同样是 `3`:签名写 `EXPORT add (ARRAY[INTEGER]: Comparable)` 报的就是 `E0010`。同一种故障不该因为走哪条路而拿到不同的退出码。

`check` 与 `run` 共用这张表:两者对解析失败的结论**必须**一致。

**说明**:`check` 的能力边界是:它做解析、未用绑定警告(`W0010` / `W0011` / `W0012`)、以及清单启用时的静态契约诊断;**它不做名字解析**。`PRINT(NOPE)` 在 `check` 下是成功退出,`E0020` 只由 `run` 报。

## 18 复杂度与性能保证

### 18.1 记法

- `n` —— 被操作容器的元素个数;对字符串是码点数,对字典是键数。
- `m` —— 第二个操作数的规模(字符串拼接时是另一段的长度)。
- **最坏** —— 该操作在所有合法输入上的代价上界。
- **摊还** —— 一串同类操作的**总**代价除以操作数所得的界;单次操作**可以**超出该界。
- **期望** —— 对实现内部的随机化取期望;单次操作**可以**超出该界。

复杂度只计**语言可观察的**代价:函数调用、容器构造与元素访问。实现内部的内存分配、回收、缓存局部性**不**计入。

### 18.2 承诺强度

| 档 | 含义 | 约束力 |
|---|---|---|
| **规范性上界** | 实现**必须**在该界内完成该操作 | 构成一致性要求 |
| **推荐上界** | 实现**应当**在该界内完成;偏离**必须**在实现文档中说明 | 弱约束 |
| **实现定义** | 规范**不**给界;实现**必须**在文档中声明自己的口径 | 无上界,但须声明 |
| **仅注记** | 记录当前实现的实测行为 | 无约束 |

**规范性上界是"必须满足",不是"当前已达到"。** 某一操作当前未达标的,在 §18.6 登记为已知偏差并附收敛路线;条款的强度**不**因实现进度而降低。

| `SORT(arr)` 的比较器调用次数 | O(n²) 最坏 | 规范性 | §18.5.1 |

#### 18.3.1 字典查找的期望复杂度与插入序

字典的**键序是插入序**,这一点是可观察的(§2.1、§2.5:JSON 渲染、错误载荷、任务结果都依赖它)。O(1) 期望的键查找与插入序**不冲突**:实现**可以**在内部维护一张哈希索引指向位置,对外仍按插入序呈现。

键的哈希由实现内部决定,**不**要求与 `STR` 渲染一致;实现**不得**因为哈希而改变可观察的键序。

#### 18.3.2 数组追加的代价结构

`PUSH` 返回**新**数组,原数组不变(§3.3、§10.4)。因此单次 `PUSH` 的代价**必须**是 O(n) 最坏 —— 产出 n+1 个元素的新数组,拷贝量下界是 Ω(n)。

**这不意味着"建一个 n 元数组要 O(n²)"。** 后者取决于**惯用法**:若每次追加都把上一个结果当作输入重新产出,则总代价是 O(n²);若实现能识别"同一个累加器被反复追加"这一形态并就地累积,则总代价有望降到 O(n) 摊还。§18.4 对这两种形态分别给出承诺。

### 18.4 高成本惯用法与推荐写法

| 惯用法 | 目标代价 | 档 | 说明 |
|---|---|---|---|
| 循环内 `SET(acc, PUSH(acc, x))` 累积 n 个元素 | O(n) 摊还 | 推荐上界 | 见 §18.4.1 |
| 循环内 `SET(acc, CONCAT(acc, t))` 累积字符串 | O(n) 摊还 | 推荐上界 | 同上 |
| 循环内逐次 `INDEX_SET(d, k, v)` 写 n 个键 | O(n) 摊还 | 推荐上界 | §18.3.1 的哈希索引让单次插入 O(1) |
| 单次 `PUSH` / `CONCAT` | O(n) / O(n+m) | 规范性 | §18.3 |

#### 18.4.1 累加器形态

"同一个绑定在循环体内被反复追加"是本语言最常见的建容器写法。实现**应当**识别该形态并避免每次重拷整个容器;**可以**选择不识别(则该惯用法退化为 O(n²),但**必须**在实现文档中说明)。

**判断该形态的推荐写法**:把累加器声明为 `LET MUT` 绑定,循环体内**只**对它做 `SET(acc, PUSH(acc, x))` 一种写法的追加。`PUSH` / `CONCAT` / `+` 三种追加形态**都**出现在真实代码里,只认一种会让另外两种静默退回平方级。

#### 18.4.2 更省事的替代

能用标准库成员一次算完的,**应当**用它,而不是手工累加:`MAP` / `FILTER` / `REDUCE` / `FOLD_RIGHT` / `SORT_BY` 等单遍成员比手工循环更快也更清楚(成员契约见标准库册 §5)。

### 18.5 明确不承诺的性能

| 项 | 口径 |
|---|---|
| 常数因子 | **不**承诺。同一操作在不同实现上的常数差异**不**构成不一致 |
| 延迟 / 吞吐 | **不**承诺任何数值阈值 |
| 内存占用 | **不**承诺。值的大小、分配的次数、是否存在回收都属实现自由度(§19.5) |
| `SORT` 的 O(n log n) | **不**承诺,理由见 §18.5.1 |
| 并发路径的吞吐 | **不**承诺。并发路径**只**保证正确性与无泄漏 |
| 回收停顿 | **不**承诺。若实现使用回收机制,其停顿**不**构成不一致 |

#### 18.5.1 为什么 `SORT` 不承诺 O(n log n)

比较排序的 O(n log n) 上界要求比较器给出**全序**。本语言的 `SORT` 口径是"不可比 ⇒ 判相等"(标准库册 §5.1),这给出的是**偏序** —— 偏序上的排序结果**未指定**,且不存在能同时满足"稳定"与"组间次序确定"的全序。

因此 `SORT` 的比较器调用次数上界是 **O(n²) 最坏**。实现**可以**做到更少(若它能在偏序上做拓扑排序),但**不得**承诺 O(n log n)。

#### 18.5.2 复杂度判定的口径

**复杂度的判定不使用墙钟比值。** 同一份线性实现在不同机器上可能测出 4 倍与 12.8 倍的差异,比值里混着缓存命中率与调度噪声,不足以判定复杂度。

判定**必须**用**确定性工作量计数**(比较器调用次数、元素访问次数、拷贝的元素个数),并满足两条:① 带**下界断言**,确认计量点确实被走到;② 计量点收在**被测数据结构内部** —— 在调用点计数对"内部换成线性扫"不敏感。

### 18.6 与参考实现的关系

本节登记**当前参考实现未达到** §18.3 规范性上界的项,以及各自的收敛路线。上游基线见册首的「上游基线」行。

| 项 | 规范上界 | 参考实现现状 | 收敛路线 |
|---|---|---|---|
| `d[k]` / `HAS` / `INDEX_SET`(语言级) | O(1) 期望 | O(n) 最坏 —— 字典的表示是线性扫描的键值序列,每次查找逐项深比较 | 需要内部哈希索引 + 插入序物化;该表示变更**本批未做**,须另立决策 |
| 循环内累加数组 / 字符串 | O(n) 摊还(推荐上界) | 数组 O(n²);字符串超线性 | 可变累加器形态识别已实现,覆盖 `PUSH` / `CONCAT` / `+` 三种追加形态 |
| `SORT` 比较次数 | O(n²) 最坏 | 恰好 C(n,2) 次 | **不追求** O(n log n) —— §18.5.1 已说明原因 |
| `MAP` / `FILTER` / `CHUNK` / `WINDOW` 等建数组族 | O(n) 摊还 | 已达标(单遍内核) | —— |

**偏差登记的纪律**:上表的"现状"一列**必须**有实测依据(工作负载计数或基准存档),**不得**凭印象填写;收敛路线**必须**指向一份已裁决的决策或一条明确的待办,**不得**只写"以后优化"。

## 19 内存与资源模型

### 19.1 值与生存期

WLWL 的值是**不可变**的。值的生存期由**绑定**决定,不由值本身决定 —— 一个值可同时被任意多个绑定持有,也可不被任何绑定持有。

值的**可观察行为**不含"它住在哪儿":两个内容相等的值在一切可观察的方面等价(§2.4、§2.5)。

**规范不暴露任何内存管理原语。** 没有 `FREE`、没有 `DELETE`、没有引用计数查询、没有显式所有权转移。程序员**无法**观察到内存管理的存在。

### 19.2 单元格与别名

每个绑定由一个**单元格**实现(§3.1、§3.3)。单元格**按引用**共享:

- 闭包捕获某单元格时,捕获环境保留对该单元格的引用(§3.3);
- 同一单元格可被多个闭包、多个作用域、多个任务同时持有;
- 单元格的可变标志在创建时设定,**不再改变**(§3.3)。

**别名不引入悬垂**:单元格的生存期由持有它的绑定与闭包共同决定,与它被引用的次数无关。

**别名 + 可变**是本语言唯一的共享可变状态。它**不**提供任何同步保证(对象册 §16.3);并发册 §17.0.1 把"共享可变状态"列为本语言的反模式。

### 19.3 容器与共享

容器(数组、字典)不可变(§2.1)。因此**共享容器是安全的**:不存在"两个持有者看到不同内容"的可能。

但**元素**仍适用 §19.2 的别名规则 —— 一个元素可能是某个单元格的值的拷贝,也可能是共享的实例(§2.1 允许 `INSTANCE` 作字典键)。

### 19.4 资源的释放责任

| 项 | 规范要求 |
|---|---|
| 通用 | 资源在**取得它的操作返回后****必须**仍然可用,直到该操作或该资源类型规定的释放点 |
| 任务 | 任务终止时其资源释放;`SCOPE` 结束时该作用域内的任务**必须**全部已终止(并发册 §17.1) |
| 通道 | 通道在其最后一个持有者消失时释放;`CHANNEL_CLOSE` 提供显式关闭(并发册 §17.2) |
| 文件 / 进程 / 网络 | 释放责任由**各成员自己**规定,见标准库册对应章;本册**不**统一规定 |

**程序终止时,全部资源必须被释放**:进程退出、文件描述符关闭、网络连接关闭、子进程被收割。实现**不得**因为某个失败路径而泄漏资源。

**规范不要求显式关闭 API**,除 `CHANNEL_CLOSE` 外。

### 19.5 内存管理策略

规范**不**规定实现采用何种内存管理策略。实现**可以**使用垃圾回收、引用计数、区域分配、所有权转移或它们的组合。

实现**必须**保证:

1. **无悬垂**:任何按引用共享的对象(§19.2)在所有持有者消失前保持有效;
2. **无泄漏**:程序终止时全部资源被释放(§19.4);
3. **不因策略改变可观察行为**:内存管理**不得**改变值相等(§2.4)、键序(§18.3.1)、显示(§2.5)或任何诊断。

实现**不得**把内存管理策略暴露为可观察行为 —— 程序**无法**区分"值被回收了"与"值还在"(§19.1)。

### 19.6 与对象模型的关系

类对象与实例按引用共享(对象册 §13.2、§13.3)。实例字段的写入对所有持有该实例的引用可见(对象册 §16.3)。

这是 §19.2 别名规则在对象模型上的延伸:**共享 + 可变**,同样不提供同步保证。

## 附录 A 文法(规范性)

### A.1 记法

产生式用 EBNF:`=` 定义;`|` 选择;`[ x ]` 可选;`{ x }` 重复;`"..."` 终结符。终结符与 §1.4–§1.5 的记号一致。

### A.2 语法

```
Program     = { ExprStmt | ModuleDecl } [ Expression ] .
Block       = "(" { ExprStmt | ModuleDecl } [ Expression ] ")" .
ExprStmt    = Expression ";" .

Expression  = LetExpr | FunExpr | IfExpr | WhileExpr | ForExpr | MatchExpr
            | TryExpr | ReturnExpr | BreakExpr | ContinueExpr
            | OkExpr | ErrExpr | PanicExpr
            | PostfixExpr .

ModuleDecl  = Import | Export | SealedDecl .
Import      = "IMPORT" "(" string_lit "," name_array ")" .
Export      = "EXPORT" "(" name_array ")" .
SealedDecl  = "SEALED" "(" name_array ")" .
name_array  = "[" [ NameItem { "," NameItem } ] "]" .
NameItem    = string_lit | string_lit ":" string_lit | identifier .

LetExpr     = "LET" [ "MUT" ] identifier [ ":" TypePos ] "," Expression .
FunExpr     = "FUN" "(" [ identifier ] "(" [ Param { "," Param } ] ")" [ ":" TypePos ] Expression .
IfExpr      = "IF" "(" Expression "," Expression [ "," Expression ] ")" .
WhileExpr   = "WHILE" "(" Expression "," Expression ")" .
ForExpr     = "FOR" "(" identifier "," Expression "," Expression ")" .
MatchExpr   = "MATCH" "(" Expression "," ClauseArray [ "," Expression ] ")" .
TryExpr     = "TRY" "(" Expression ")" .
ReturnExpr  = "RETURN" "(" [ Expression ] ")" .
BreakExpr   = "BREAK" "(" ")" .
ContinueExpr= "CONTINUE" "(" ")" .
OkExpr      = "OK" "(" Expression ")" .
ErrExpr     = "ERR" "(" Expression ")" .
PanicExpr   = "PANIC" "(" Expression ")" .

Param       = identifier [ ":" TypePos ] [ "=" Expression ] | "*" identifier .

TypePos     = Type | BoundedVar .
Type        = TypeHead [ "[" TypeArg { "," TypeArg } "]" ] .
TypeHead    = identifier .
TypeArg     = Type | BoundedVar .
BoundedVar  = identifier ":" Type .

PostfixExpr = Primary { Postfix } .
Primary     = Literal | identifier | OperatorCall | identifier "(" [ Args ] ")"
            | KeywordCall | "(" Block ")" | ArrayLit | DictLit .
KeywordCall = ( "CLASS" | "NEW" | "THIS" ) "(" [ Args ] ")" .
OperatorCall= OpToken "(" [ Args ] ")" .
Postfix     = "." identifier [ "(" [ Args ] ")" ]
            | "[" Expression "]"
            | "[" Expression "]" "=" Expression .
Args        = Expression { "," Expression } .

ArrayLit    = "[" [ Expression { "," Expression } ] "]" .
DictLit     = "[" Key ":" Expression { "," Key ":" Expression } ]" .
Key         = Expression .

Literal     = int_lit | float_lit | string_lit | "TRUE" | "FALSE" | "NULL" .
OpToken     = "+" | "-" | "*" | "/" | "%" | "==" | "=" | "!=" | "<" | ">"
            | "<=" | ">=" | "&&" | "||" | "!" .

string_lit     = '"' { string_element | interpolation } '"' .
string_element = any_char_except_quote_backslash_newline_dollar | escape .
interpolation  = "${" Expression "}" .
escape         = "\" ( "n" | "t" | "r" | "\" | '"' | "/" | "0" | "b" | "f" | "$" ) .

ClauseArray = "[" [ Clause { "," Clause } ] "]" .
Clause      = "[" Pattern "," Expression "]" .

Pattern     = identifier | "_" | Literal
            | ArrayPattern | DictPattern
            | "OK" "(" Pattern ")" | "ERR" "(" Pattern ")" .
ArrayPattern= "[" [ Pattern { "," Pattern } [ "," "*" identifier ] ] "]" .
DictPattern = "[" Expression ":" Pattern { "," Expression ":" Pattern } ]" .
```

**说明**:`Block` 允许以一个无分号的表达式收尾,其值为括号序列的值;顶层 `Program` 通常写作若干 `ExprStmt`。`Postfix` 的三种形式可任意交错。`LetExpr` 中的 `MUT` 是上下文关键字(§1.4);`string_lit` 中的 `Expression` 是完整的 `Expression` 文法,但为避免歧义,实现通常在词法阶段以括号配对定位插值边界。

`CLASS` / `NEW` / `THIS` 是关键字(§1.4),出现在调用位置(对象册 §13、对象册 §15)。会话协议表达式(对象册 §14.1)是普通 `Expression`(以 `ArrayLit` / `DictLit` / 字符串字面量书写),无独立文法。

`ModuleDecl`(§9.1 / §9.2)只出现在模块顶层,不作为 `Expression`。

**`RETURN` 的括号不可省**:`ReturnExpr` 要求 `RETURN` 之后**必须**跟一对括号(`RETURN()` / `RETURN(expr)`)—— 与 §6.4 的 `RETURN(expr?)`、附录 G 成员表的 `RETURN(v?)` 一致。裸用 `RETURN 5` **不是**本语言的一部分,产生 `E0011`(期望左括号)。

类型注解有三条**必须**照实写明的规则(详见 §2.6):① 容器用**方括号**;② **尖括号与 `FUN(...) -> U` 的箭头形式都不可达**,且**直接报错**(`E0010` / `E0012`)—— 解析器**不**把它们吸收成一个名字里含括号的不透明类型;③ `BoundedVar` 只能跟在**裸标识符**后,给容器加约束报 `E0010: a type constraint may only follow a bare type variable`。

### A.3 规范格式化器

实现**必须**随附一个把程序重排为唯一规范形式的格式化器(不保留注释)。`--check` 模式对偏离规范形式者产生 `W0053`。

**实现注(非规范)**:规范形式的确切空白策略属实现文档,不构成一致性要求。

## 附录 E 模块契约文件与工具接口

本附录分两部分:**E.1 签名文件文法是规范性的** —— 它是语言设施(§9.6 的契约载体),文法由本册定义;**E.2–E.5 是非规范的** —— 它们描述参考实现的工具接口,不构成对其它实现的约束。

### E.1 签名文件文法(规范性)

`<module>.wll.sig` 是**行导向**的 UTF-8 文本:一条声明一行,`#` 起行注释,空行忽略。

```
sig_file    = { sig_line } .
sig_line    = comment | export_decl | blank .
export_decl = "EXPORT" sig_name [ "(" [ Type ] { "," Type } ")" ] ":" Type .
sig_name    = identifier .
```

`Type` 即附录 A 的 `Type`。函数条目用 `名字(形参) : 返回` 而**不是** `FUN(...) -> U`(§2.6 已述箭头形式不可达)。规范形式由实现渲染;渲染与解析**必须**往返一致。

### E.2 `wlwl interface <file>` 的 JSON(非规范)

机器可读地暴露**同一个承诺**(与 `.wll.sig` 同源,不是另建一套推导):

| 字段 | 含义 |
|---|---|
| `interface_schema_version` | 本契约的 schema 版本;字段增删时递增版本号 |
| `module` | 被检查的 `.wll` 路径 |
| `signature_file` | 旁路签名文件在磁盘上的位置 |
| `sealed` | `SEALED([...])` 的名字数组;`null` 表示**未声明**(与「声明了空面」不同) |
| `exports[]` | 每项含 `name`、`kind`(`"function"` / `"value"`);函数另有 `params[]` 与 `returns`,值另有 `type` |

### E.3 `wlwl schema` 的 JSON(非规范)

工具的静态分析层据此认识 WLWL 的类型,而不必把清单硬编码在自己代码里:

| 字段 | 含义 |
|---|---|
| `schema_version` | 本契约的 schema 版本 |
| `types[]` | 静态类型词汇(§2.6)每项的 `name` / `kind` / `syntax`;`kind` ∈ `scalar` / `container` / `wrapper` / `function` / `top_bottom` |
| `named_types_not_modelled[]` | `TASK` / `CHANNEL` / `CLASS` / `INSTANCE` |
| `bounds[]` | 每个约束的 `name` / `syntax` / `members[]` |
| `type_variables` | 类型变量的语法、作用域与擦除语义(§5.2.1) |
| `diagnostics[]` | 静态契约诊断码:`code`、`warn`(同号 W 码,`W0117` 为 `null`)、`always_warning`、`condition` |

工具按 `diagnostics[]` 决定是否把某条诊断当硬错:`always_warning` 为真的项**不得**被升级。

### E.4 `wlwl sig` / `wlwl sig-gen`(非规范)

| 子命令 | 行为 |
|---|---|
| `wlwl sig <file>` | 打印该模块的签名。`--format text`(默认)/ `--format json` |
| `wlwl sig-gen <file>` | 从实现**反推**签名骨架并写进 `<file>.wll.sig`。**默认不覆盖**已有文件(`--force` 才覆盖);零导出的模块**不写盘** |

**三处渲染同源**:stdout 的文本、`--format json` 的 `text` 字段、落盘内容,都出自同一个渲染函数,不允许三者分叉。

`--format json` 的契约:

| 字段 | 含义 |
|---|---|

| `module` | 被检查的 `.wll` 路径 |
| `text` | 与 `sig` 文本模式、与落盘内容**逐字相同**的签名文本 |
| `exports[]` | 与 E.2 同构(见 E.2 的字段说明) |

### E.5 `wlwl lsp`(非规范)

`wlwl lsp` 是走 stdio 的 JSON-RPC 薄壳,提供 `diagnostics` / `definition` / `hover` 三项能力,外加由附录 G 的注册表驱动的补全。

**能力边界是规范性的**:`initialize` 的 capabilities 里**没有** `renameProvider`,也**没有** `documentFormattingProvider`。工具**不得**假设这两项存在。

**诊断口径**:`lsp` 的 `diagnostics` 与 `wlwl check` **共用同一个收集函数**(§11),所以编辑器里的划线**不会比命令行少**。这是本节唯一的功能性要求 —— 工具链各走各的判据会让「编辑器不报、CI 报」这种最难查的分裂。

**说明**:零新依赖 —— LSP 侧不引入任何 crate。
