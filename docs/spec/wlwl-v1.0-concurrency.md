# WLWL 并发规范 v1.0

本册定义 WLWL 的**并发**:结构化并发、通道、取消、代数效果执行模型(§17),以及挂起与恢复的形式化操作语义(附录 H)。

- **结构化并发**。任务**必须**词法地嵌套在某个 `SCOPE` 内;作用域退出前等待其子任务结束(§17.1)。
- **协作式单线程调度**。任务在让步点与阻塞点把控制交还调度器;调度器担当效果处理器(§17.4)。
- **真挂起**。阻塞型通道操作**真的**挂起调用任务(§17.2.1),**不**以 `ERR` 载荷代替。
- **错误即值**。取消**不**产生用户 `ERR` 值,只在 `AWAIT` 观察点显现(§17.3)。
- **不保存续体**。挂起是「让出控制再回来」;挂起点所在表达式的中断状态**不保留**(§17.0、附录 H)。

语言核心见[语言核心册](wlwl-v1.0-language.md);对象模型、行为类型与 `THIS` 见[对象与行为类型册](wlwl-v1.0-objects.md);标准库成员契约见[标准库册](../stdlib/)。

## 17 并发(结构化并发与通道)

本章定义并发原语。语言核心册 §8 的错误模型(含语言核心册 §8.2 透明传播、语言核心册 §8.3 消费者注册表)对本章全部内建**原样适用**。本章原语全部是全局内建(语言核心册 附录 G「并发 / 通道」组),不经 `IMPORT`。

### 17.0 执行模型

本章的并发是**结构化并发 + 通道**、**协作式单线程调度**、**真挂起**。任务在让步点与阻塞点把控制交还调度器;调度器担当效果处理器(§17.4),按代数效果模型捕获让步、通道等待与取消,并切换到下一个可运行任务。取消携带结构化 `reason` 载荷;取消本身**不**产生用户 `ERR` 值,只在 `AWAIT` 观察点显现(§17.3)。

**段。** 任务体在派生时被切分为若干**段**:一个段是任务体中一段连续的顶层语句,其**最后一条**(含任意深度)含 `YIELD`;含 `YIELD` 的那条顶层语句属于它**前面**的那个段,两个段以它为界。任务体**不含** `YIELD` 时,整个任务体是唯一的一段。

**挂起点。** 挂起点是任务交还控制的表达式位置。本语言有且只有三类挂起点:

| 挂起点 | 切段 | 恢复起点 | 挂起点之前的代码 | 挂起点所在表达式 |
|---|---|---|---|---|
| `YIELD()` | **切段** | 下一段的**首条语句** | **不重跑** | 中断状态**不保留**;所在最外层表达式**不完成** |
| 阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` | **不切段** | 当前段的**首条语句** | **重放** | 中断状态**不保留**;所在最外层表达式**不完成** |
| `AWAIT(task)`(等待子任务) | **不切段** | `AWAIT` 调用处,调用返回子任务的值 | **不重跑** | 正常求值完成 |

实现**必须**按本表实现挂起与恢复。表中每一格都是**可观察行为**,偏离任一格即与本规范不一致。

- `YIELD()` 挂起时,恢复**必须**从**下一段**开始,挂起点之前的代码**不重跑**。
- 阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 挂起时,恢复**必须**从**当前段首**重跑,挂起点之前的代码**重放**。
- `AWAIT(task)` 等待子任务期间**不**挂起调用任务所在的段:恢复后 `AWAIT` 调用正常返回子任务的值,挂起点之前的代码**不重跑**。

**恢复语义。** 任务恢复后,挂起点之前已经建立的绑定**仍然可见**(§17.1);挂起点所在表达式的中断状态(实参表、分支选择、循环计数)**不保留**。

**不完成。** 挂起点所在的最外层表达式**不完成** —— 它**不**产生值;含它的顶层语句随之**不**完成,该语句的其余部分**不**执行。已经发生的部分副作用**不**回滚。逐形态见 §17.1 的表。

**续体。** 本规范**不保存续体**。挂起只是「让出控制再回来」,回来之后从挂起点**之后**继续,而不是从挂起点**之内**继续。兑现续体保存需要改运行期栈模型,是一项独立改造,**不**在本规范范围内(总纲 §0.10;理由见路线图册 §2.2)。

**取消。** 取消请求携带结构化 `reason` 载荷(§17.3),**不**产生用户 `ERR` 值;它只在 `AWAIT` 观察点显现。

```wlwl
SCOPE(FUN(() ,
  LET(t, SPAWN(FUN(() ,
    LET(x, 7);
    YIELD();          // 切段:恢复从下一段开始
    PRINT(x);         // 7 —— 挂起点之前建立的绑定在恢复后仍可见
    1
  )));
  LET(v, AWAIT(t));
  PRINT(v)            // 1
));
// 输出: 7 / 1
```

```wlwl
SCOPE(FUN(() ,
  LET(ch, CHANNEL_NEW(0));
  LET(s, SPAWN(FUN(() ,
    PRINT("A");          // 挂起点之前的代码
    CHANNEL_SEND(ch, 1); // 挂起点:阻塞型通道操作
    PRINT("B");          // 恢复之后才执行
    7
  )));
  LET(r, SPAWN(FUN(() , CHANNEL_RECV(ch))));
  LET(v, AWAIT(s));
  PRINT(v)                // 7
));
// 输出: A / A / B / 7
// "A" 打印两次:恢复从段首重跑,挂起点之前的代码被重放
```

**实现注(非规范)**:参考实现**在派生时一次性**算出段序列,运行期不再重算 —— 恢复时因此能确定地回到同一段的段首。任务体**不含** `YIELD` 时,参考实现用**空的**段序列作内部哨兵,运行期等价于「整个任务体作为一段」。

### 17.0.1 「共享可变状态」是**本语言的反模式**(规范性)

**规范约束**:任务之间**不得**通过**共享的可变 cell**(即 `LET MUT` 绑定的、被 `SCOPE` 内多个任务读写的 cell)来传递数据。正确形态是 **actor**:每个任务独占状态、只经**通道**(`CHANNEL_*`)传消息,正确性由**语言**保证,**不**依赖用户划临界区。

违反本条的**不**构成符合本规范的程序(一致性册 §1.1)。

**说明**:这条是规范约束而不是一条风格建议,两个理由都是模型的性质,不是风格。

其一,**粒度对不上**。调度点只在**段首**(或阶段边界),而**临界区由用户代码划定**;两个边界格式不同,无法对齐。已落地的结果是:阻塞型通道操作**不切段**(§17.0),任务被唤醒后从**段首重跑**;因此一个锁的**锁前用户代码会再执行一遍** —— 这**不是**「加个护栏」能解决的(护栏能拦住活锁,拦不住**已发生的副作用重放**)。在当前架构下,「锁」不是一个可实现的成员,而是一个**与调度边界不能对齐的概念**。

其二,**可复现性**(语言的第一位卖点)。单线程协作式下,临界区边界与调度点不对齐 ⇒ **同一个程序两次运行的交错可能不同**。actor 形态下的交错**由通道语义决定**,**不**由临界区划分的粗粒度决定。

**说明**:本条与「段内恢复」是否落地**无关** —— 上面的粒度结论是**协作式模型的固有性质**。因此 `MUTEX` / `CONDITION` / `ONCE` / `SEMAPHORE` / `WAIT_GROUP` 这类用户级同步原语**不**属于本语言面;它们属标准库范畴,见标准库册。

**说明**:本册所说的「共享可变状态」在语言核心册 §19.2 有精确对应 —— 单元格**按引用**共享,「别名 + 可变」是本语言**唯一**的共享可变状态。它**不**提供任何同步保证(对象册 §16.3)。

### 17.1 任务与作用域

| 构造 | 签名 | 语义 |
|------|------|------|
| `SCOPE(fn)` | `SCOPE(fn) -> v` | 创建**子作用域**并调用 0 元函数 `fn`;返回 `fn` 的值。`fn` 不是函数 → `E0052`。支持嵌套 |
| `SPAWN(fn)` | `SPAWN(fn) -> TASK` | 在当前作用域派生子任务,返回任务句柄。`fn` **必须**是 0 元函数(`E0056`);`fn` 不是函数 → `E0052` |
| `AWAIT(task)` | `AWAIT(task) -> v` | 等待并取得子任务终值。非句柄 / 过期句柄 → `E0053` |
| `YIELD()` | `YIELD() -> NULL` | 协作让步检查点 |
| `TASK_CURRENT()` | `TASK_CURRENT() -> TASK` | 当前任务句柄;任务外 → `E0053` |
| `TASK_IS_CANCELLED()` | `TASK_IS_CANCELLED() -> BOOLEAN` | 协作取消检查;任务外返回 `FALSE`(不报错) |

**作用域与生命周期**

- 子任务寿命**不**超过词法 `SCOPE`;`SCOPE` 返回前**必须**等待其子任务结束(结构化并发不变量)。
- **无隐式 runtime scope**:任何 `SPAWN` **必须**直接或间接嵌套在某个 `SCOPE(...)` 内;顶层 `SPAWN` → `E0058`。不提供 free-floating task / 守护线程。
- `SCOPE` 的返回值是 `fn` 主体的值。若 `fn` 主体给出未消费的 `ERR`,该 `ERR` 成为 `SCOPE` 的返回值(与语言核心册 §8.2 一致);已被消费者处理掉的 `ERR` **不**再上浮。
- `SCOPE(fn)` 的 `fn` 在**调用者**的执行上下文中同步求值;只有 `SPAWN` 创建的任务体才是调度驱动的。

**AWAIT**

- 任务以用户 `ERR` 结束时,`AWAIT` **返回该 `ERR` 值**(不自动消费)。
- **宿主诊断**(实现内部错误,如 `E0101` 栈溢出、句柄失效 `E0053` 等)在 `AWAIT` 处重新抛出,并以诊断 trace 链关联目标任务的失败帧;**用户 `ERR` 值**(`RESULT` 变体)作为普通结果返回,不重新抛出。
- 已取消任务的 `AWAIT` 返回 `ERR(kind="Cancelled", reason: <dict>)`(§17.3)。
- `AWAIT` 的目标任务若永久阻塞在通道操作上且无对端可唤醒,产生 `E0053`(或在死锁检测触发时先见 `E0065` / `W0065`,§17.7)。

```wlwl
SCOPE(FUN(() ,
  LET(t, SPAWN(FUN(() , ERR(["tag": "boom"]))));
  LET(r, AWAIT(t));
  PRINT(IS_ERR(r));        // TRUE —— 用户 ERR 值作为普通结果返回
  PRINT(ERR_PAYLOAD(r))    // [tag: boom]
));
// 输出: TRUE / [tag: boom]
```

**YIELD 的位置与上下文**

`YIELD()` **可以**出现在**任务体内的任何表达式位置** —— 实参、`LET` 右值、`IF` 分支、数组与字典字面量、嵌套的 `WHILE` / `FOR` / `IF` 体内,以及闭包函数体内。`YIELD` **不要求**是块的直接子项 —— 任务体内的任何表达式位置**可以**。

| 形态 | 行为 |
|------|------|
| 语句位 `YIELD()`(其值被丢弃) | 挂起后**同一条序列的剩余部分照常执行** |
| `LET(x, YIELD())` | 整条 `LET` **不完成**:`x` **根本没绑定**,后续引用 `x` → `E0020: undefined name` |
| `IF(TRUE, YIELD(), 42)` | 整条 `IF` **不完成** —— 它**不**产生值(**不是** `42`) |
| `[1, YIELD(), 3]` | 整条数组字面量 **不完成** —— 它**不**产生值(**不是** `[1, NULL, 3]`) |
| `+(YIELD(), 100)` | 整条调用 **不完成** —— 它**不**产生值(**不是** `100`) |
| `WHILE` / `FOR` **循环体内**的 `YIELD` | 循环**只执行一轮**;体内 `YIELD` 之后的语句**不**执行 |
| `LET(y, YIELD); y()` | `E0020: undefined name 'YIELD'` —— `YIELD` **不是可绑定的值**,间接调用不成立 |

**可用的规律,两条**

1. **挂起点之前已经建立的绑定,在恢复后仍然可见** —— `LET(x, 7); YIELD(); x` 得 `7`;`LET MUT(k, 0); YIELD(); YIELD(); SET(k, 5); k` 得 `5`。
2. **`YIELD()` 的值一旦被外层表达式消费,那个最外层表达式就不完成** —— 不完成的是**整个最外层表达式**,不只是 `YIELD` 所在的那个子表达式。

**说明**:第 1 条第二个示例里 `k` **必须先绑定且可变**(`LET MUT`):`SET` 要求名字**当前已绑定**且单元格**可变**(语言核心册 §3.4)⇒ 少了 `LET MUT(k, 0)` 这一行,示例按原文跑是 `E0020`(未定义名 `k`),不是 `E0024`。

```wlwl
SCOPE(FUN(() ,
  LET(t, SPAWN(FUN(() ,
    PRINT("a");
    YIELD();          // 任意表达式位置均可
    PRINT("b");
    42
  )));
  LET(v, AWAIT(t));
  PRINT(v)            // 42
));
// 输出: a / b / 42
```

`YIELD` **必须**位于调度驱动的上下文(任务体)内。在任务体之外(例如模块顶层、`SCOPE` 的同步主体)调用 `YIELD` 产生 `E0014`。任务体末尾的 `YIELD()` 使任务以 `NULL` 值结束,**不**与「未消费 `ERR`」的语义冲突(语言核心册 §8.6)。

### 17.2 通道

| 构造 | 签名 | 语义 |
|------|------|------|
| `CHANNEL_NEW(buf)` | `-> CHANNEL` | 创建缓冲大小为 `buf` 的通道;`buf = 0` 为同步通道。`buf` 须为非负 `INTEGER`;负数或非整数 → `E0031`。超过软阈值 → `W0066`(语言核心册 §9.4) |
| `CHANNEL_SEND(ch, v)` | `-> NULL` | 发送。缓冲满且无等待中的接收方时**挂起**(§17.2.1)。关闭后发送 → `E0054` |
| `CHANNEL_RECV(ch)` | `-> v` | 接收。缓冲空且无等待中的发送方时**挂起**。关闭且读空 → `ERR(kind="ChannelClosed")` |
| `CHANNEL_TRY_SEND(ch, v)` | `-> BOOLEAN` | **不挂起**:成功 `TRUE`,满 `FALSE`;关闭后 → `E0054` |
| `CHANNEL_TRY_RECV(ch)` | `-> v / NULL` | **不挂起**:成功返回值;空返回 `NULL`(**不是**关闭信号);关闭且读空 → `ERR(kind="ChannelClosed")` |
| `CHANNEL_CLOSE(ch)` | `-> NULL` | 关闭。幂等 |
| `CHANNEL_LEN(ch)` | `-> INTEGER` | 当前缓冲长度 |
| `CHANNEL_CAP(ch)` | `-> INTEGER` | 配置容量;同步通道为 `0` |

`TYPE(ch)` 为 `"CHANNEL"`。句柄恒等见语言核心册 §2.4。

#### 17.2.1 真挂起

阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在满足下列条件之一时**挂起**调用任务,把控制交还调度器:

- `SEND`:缓冲满,且没有等待中的接收方;
- `RECV`:缓冲空,且没有等待中的发送方。

挂起的任务离开运行队列,登记在通道的等待表上;对端到达或通道关闭时被唤醒。**不**返回 `ERR(kind="ChannelWouldBlock")` —— 该载荷**没有**触发路径。

**对端配对。** 当一侧到达时,若对端已在等待,双方**必须**配对交接:

- 发送方到达且有等待中的接收方 → 值直接交给该接收方,双方就绪;
- 接收方到达且有等待中的发送方 → 取走该发送方的值,双方就绪;
- 缓冲有余位 / 有存货时,按缓冲路径立即完成,并顺带唤醒一个可推进的对端。

配对成功的双方都被标记为就绪,进入调度队列尾部(§17.8)。

**非阻塞形态** `CHANNEL_TRY_SEND` / `CHANNEL_TRY_RECV` 从不挂起,亦从不经 `ERR` 载荷报告「满 / 空」:`TRY_SEND` 以 `TRUE` / `FALSE` 报告,`TRY_RECV` 以值 / `NULL` 报告。

**阻塞型操作要求活跃任务**:在任务体之外调用阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 产生 `E0053`。`TRY_*` 无此限制。

#### 17.2.2 操作语义矩阵

| 操作 | closed | 缓冲状态 | 行为 |
|------|--------|----------|------|
| SEND | false | 有空位或有等待中的接收方 | 交接 / 入队,返回 `NULL` |
| SEND | false | 满且无接收方 | **挂起** |
| SEND | true | — | `E0054` |
| RECV | false | 非空或有等待中的发送方 | 交接 / 出队,返回值 |
| RECV | false | 空且无发送方 | **挂起** |
| RECV | true | 空 | `ERR(kind="ChannelClosed")` |
| RECV | true | 非空 | 先出队;读空后后续 `RECV` 得 `ChannelClosed` |
| TRY_SEND | false | 有空位 | `TRUE` |
| TRY_SEND | false | 满 | `FALSE` |
| TRY_SEND | true | — | `E0054` |
| TRY_RECV | false | 非空 | 返回值 |
| TRY_RECV | false | 空 | `NULL` |
| TRY_RECV | true | 空 | `ERR(kind="ChannelClosed")` |
| CLOSE | false | — | `closed = true` |
| CLOSE | true | — | 幂等 no-op |

#### 17.2.3 关闭协议

1. `CHANNEL_CLOSE(ch)` 置 `closed = true`;重复关闭是 no-op。
2. 关闭后 `SEND` / `TRY_SEND` → `E0054`。
3. 关闭后 `RECV` / `TRY_RECV` 在缓冲读空后返回 `ERR(kind="ChannelClosed", channel: <handle 显示>)`。
4. `NULL` **不得**用作关闭信号;**必须**用 `IS_ERR` + `ERR_PAYLOAD` 的 `kind` 识别。

**关闭对挂起等待方的唤醒**:关闭**必须**释放该通道上全部挂起的等待方 ——

- 挂起的**接收方**被唤醒后,其 `RECV` 按「关闭且读空」完成,返回 `ERR(kind="ChannelClosed")`;
- 挂起的**发送方**被唤醒后,其 `SEND` 以 `E0054` 失败(发送到已关闭通道)。

多个等待方同时被唤醒时的次序**未定义**(实现可任选)。

**实现注(非规范)**:**基线 `46b153b` 的**参考实现在通道关闭时**只**释放停泊的**接收方**;停泊的**发送方**保持挂起,**不**被唤醒。此时对该任务执行 `AWAIT` 得到 `E0053`(无对端可唤醒),**不**是本节规定的 `E0054`。⚠ **实现仓 `wip0.11.4` 已于 2026-10-23 收敛**:关闭**同时**释放停泊的**发送方** ⇒ 它们的 `SEND` 以 **`E0054`** 失败(本节规定的那个码)⇒ ⇒ **待并入上游基线之后**,本实现注才转「已实现」。

`native_channel_close` 特性(语言核心册 §9.4)开启时,第 3 条的 `ERR(kind="ChannelClosed")` 改为硬诊断 `E0054`。

#### 17.2.4 限制

- 通道缓冲长度不设硬上界;`CHANNEL_NEW` 对大缓冲产生 `W0066`(默认阈值 1024,可经 `channel_large_buf_threshold` 调整,`0` 关闭)。
- `ERR(kind="ChannelWouldBlock")` 无触发路径;需要「满 / 空即返回」的语义请用 `TRY_*`。

```wlwl
LET(ch, CHANNEL_NEW(2));
CHANNEL_SEND(ch, 10);
CHANNEL_SEND(ch, 20);
PRINT(CHANNEL_LEN(ch), CHANNEL_CAP(ch));  // 2 2
PRINT(CHANNEL_TRY_RECV(ch));               // 10
PRINT(CHANNEL_TRY_RECV(ch));               // 20
PRINT(CHANNEL_TRY_RECV(ch));               // NULL —— 不是关闭信号
CHANNEL_CLOSE(ch);
CHANNEL_CLOSE(ch);                         // 幂等
PRINT("closed-twice-ok")
// 输出: 2 2 / 10 / 20 / NULL / closed-twice-ok
```

```wlwl
SCOPE(FUN(() ,
  LET(ch, CHANNEL_NEW(0));
  LET(r, SPAWN(FUN(() ,
    LET(v, CHANNEL_RECV(ch));
    IF(IS_ERR(v), PRINT(ERR_PAYLOAD(v)), PRINT(v));
    0
  )));
  CHANNEL_CLOSE(ch);
  LET(x, AWAIT(r));
  PRINT(x)                                 // 0
));
// 输出: [kind: ChannelClosed, channel: <channel handle id=0 gen=0>] / 0
```

### 17.3 取消

| 构造 | 签名 | 语义 |
|------|------|------|
| `TASK_CANCEL(task, reason?)` | `-> NULL` | 请求取消目标任务(advisory)。`reason` 缺省空字典 `{}`;**必须**是 `DICT`,否则 `E0066`。**不**产生用户 `ERR`;过期/已结束句柄静默 no-op。非句柄 → `E0053` |
| `TASK_CANCEL_PARENT(reason?)` | `-> NULL` | 请求取消当前任务及当前作用域子树(自顶向下)。`reason` 规则同上。任务外 no-op |
| `SHIELD(fn)` | `SHIELD(fn) -> v` | 调用 `fn` 并屏蔽屏蔽块内收到的取消请求。**不**创建新作用域 |

`SHIELD` 与 `SCOPE` 正交:作用域负责生命周期,屏蔽负责取消推迟;可独立组合(`SCOPE(FUN(() , SHIELD(...)))`)。在顶层调用时,`SHIELD` 仅屏蔽来自当前任务的取消(顶层任务无取消源,故为 no-op)。

**结构化 reason**

- `TASK_CANCEL(task, reason)` / `TASK_CANCEL_PARENT(reason)` 携带结构化 `reason` 载荷;缺省为空字典。
- `reason` 不是 `DICT` → `E0066`(在元数与句柄校验之后)。
- `AWAIT` 已取消任务时返回的载荷为 `["kind": "Cancelled", "task": <handle>, "reason": <dict>]`;`reason` 直接透传用户传入的字典,不丢弃、不改写。

```wlwl
SCOPE(FUN(() ,
  LET(t, SPAWN(FUN(() , WHILE(TRUE, YIELD()))));
  TASK_CANCEL(t, ["why": "stop"]);
  LET(r, AWAIT(t));
  IF(IS_ERR(r), PRINT(ERR_PAYLOAD(r)), PRINT(r))
));
// 打印 [kind: Cancelled, task: <task handle id=0 gen=0>, reason: [why: stop]]
```

**SHIELD 语义**

1. **可嵌套**:层数累计;取消只在**最外层** `SHIELD` 退出后生效。
2. **内部取消仅记录**:屏蔽块内 `TASK_CANCEL_PARENT` 等只标记挂起取消(含 `reason`),不立即打断。
3. **退出后再生效**:最外层退出后,后续检查点(`TASK_IS_CANCELLED` / `YIELD` / 阻塞操作)立刻观察到取消。
4. **自身 `ERR` 不屏蔽**:`fn` 抛出的 `ERR` 仍走语言核心册 §8 的传播,不受 `SHIELD` 影响。
5. `SHIELD` 的返回值是 `fn` 的返回值(透明包装)。
6. **作用域退出的硬清理豁免**:`SCOPE` 返回前的强制清理(§17.1「`SCOPE` 返回前**必须**等待其子任务结束」)**不**受 `SHIELD` 推迟 —— 作用域退出时仍非终态的子任务被**强制取消**,**不**受它自身 `SHIELD` 块的保护。⚠ **依据**:若硬清理也受屏蔽保护 ⇒ 子任务活过 `SCOPE` ⇒ 违 §17.1 的结构化并发不变量 ⇒ **豁免是必需的**。⚠ 本条**只**豁免**作用域退出**这一条路径;`TASK_CANCEL(handle)` / `TASK_CANCEL_PARENT()` / 兄弟失败连带**仍**受屏蔽保护(见第 2 条与「实现注」)。

**实现注(非规范)**:参考实现按**目标**判定取消请求是否被推迟 —— 取消请求**到达目标**时,若该目标正处在 `SHIELD` 块内,则该请求只被记录,直到该目标**自己的**最外层 `SHIELD` 退出后才生效;否则立即登记在目标任务的取消标记上,目标在下一个检查点即观察到它。`TASK_CANCEL_PARENT()` 取消的是**自己 + 同域兄弟 + 子树**,其中每个目标**各自**按自己的状态判定 ⇒ 同域兄弟若不在 `SHIELD` 块内,会被**立即**取消。**例外**:**作用域退出**的硬清理**豁免**于 `SHIELD`(见上文第 6 条)。**屏蔽块的边界**取**帧口径**:屏蔽块 = `SHIELD` 语句在**栈上**的那段时间 ⇒ 挂起点(`YIELD` / 阻塞型通道 park)返回时屏蔽帧即退出、该次屏蔽保护随之结束(阻塞型通道 park 恢复后**段首重放** ⇒ 屏蔽块**再进入**一次);`AWAIT` **不**切段 ⇒ 屏蔽帧**留在栈上** ⇒ 该窗口内仍算「块内」。⇒ 与 §17.0 的「**不完成**」条款一致(挂起点所在的最外层表达式**不完成**、该语句其余部分**不**执行)。

```wlwl
SCOPE(FUN(() ,
  LET(t, SPAWN(FUN(() ,
    SHIELD(FUN(() ,
      TASK_CANCEL_PARENT(["why": "deferred"]);
      PRINT(TASK_IS_CANCELLED());   // FALSE —— 屏蔽块内的取消只被记录
      0
    ));
    PRINT(TASK_IS_CANCELLED());     // TRUE —— 最外层 SHIELD 退出后取消生效
    1
  )));
  LET(r, AWAIT(t));
  IF(IS_ERR(r), PRINT(ERR_PAYLOAD(r)), PRINT(r))
));
// 输出: FALSE / TRUE / 1
```

**取消与错误**

- 取消本身**不**生成用户 `ERR` 值;唯一观察点是 `AWAIT` 已取消任务(上列载荷)。
- 取消自顶向下传播;响应是**协作式**的:取消在检查点生效,**不**强制打断正在执行的表达式。
- 观察取消用 `TASK_IS_CANCELLED()`;`reason` 经 `ERR_PAYLOAD` 取得。

`TASK_CANCEL(task)` / `TASK_CANCEL_PARENT()` 不带 `reason` 是合法的,`reason` 隐式为空字典;仅按 `kind` 匹配载荷的消费代码不受影响。

### 17.4 代数效果执行模型

本章并发原语在语义上建模为**代数效果**(algebraic effects):任务在效果点交出控制,调度器作为效果处理器接管并决定何时恢复。

| 用户语言构造 | 效果形式 |
|--------------|----------|
| `YIELD()` | `perform Yield` |
| `CHANNEL_SEND(ch, v)` | `perform ChannelOp(Send, ch, v)` |
| `CHANNEL_RECV(ch)` | `perform ChannelOp(Recv, ch)` |
| `TASK_CANCEL(t, reason)` | 对目标注入 `Cancelled(reason)` |

**效果点与挂起**

- 任务在 `YIELD`、阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV`、以及 `AWAIT` 等待子任务时进入**挂起**;挂起任务交出控制,恢复后从挂起点**之后**的文本继续,而**不**是从挂起点**之内**接续。**恢复的粒度**由 §17.0 的挂起点分类给出。
- **挂起对程序文本不是透明的。** 可兑现的部分是:**挂起点之前已经建立的绑定,在恢复后仍然可见**(§17.1)。不可兑现的部分是「恢复后语义上等价于『该表达式刚完成』」:本规范**不保存续体**(§17.0),挂起点**之内**的中断状态不保留,因此该最外层表达式**不完成**。逐形态见 §17.1 的表。
- 阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 的挂起点只有对端出现 / 通道关闭才恢复,与表达式求值位置无关,因此**不**受上一条的限制;本条只约束 `YIELD`。
- 间接调用不成立:`YIELD` 不是可绑定的值,`LET(y, YIELD)` 报 `E0020: undefined name 'YIELD'`。

**调度循环。** 实现**必须**按下列步骤推进任务:① 从运行队列按 FIFO 取出一个就绪任务(§17.8);② 推进该任务直到它完成、或发出效果而挂起;③ 挂起的任务登记到对应等待表(通道 / 子任务),移出运行队列;④ 被配对、关闭、取消唤醒的任务重新入队;⑤ 循环直至 `SCOPE` 的全部子任务结束。

**取消注入。** 取消请求把目标任务标记为「待取消」;目标在其下一个检查点观察到取消并按 §17.3 终止。被 `SHIELD` 屏蔽的取消只记录不生效。

**说明**(非规范):`YIELD` 对应 `perform Yield`;通道阻塞对应 `perform ChannelOp`;取消对应带载荷的 `Cancelled` 效果。实现**可以**把 `YIELD` / `ChannelOp` / `Cancelled` 作为内部效果标签,并把调度循环实现为效果处理器;本规范只规定可观察行为,**不**暴露用户自定义效果处理器。

**保留的 tag 面。** `MethodCall`(OOP 方法调用)与 `ProtocolViolation`(会话类型协议违规)两个 tag 属于**为代数效果后端迁移预留**的 tag 面(后端迁移时每个 tag 映射一条 `suspend` 指令)。它们**不由运行期产生**:OOP 的协议违规与调用顺序违规以 `E0050` / `E0051` 当场报告(对象册 §16.4),方法调用同步直落。保留这两个 tag 是为了让后端迁移**不**必回头改 tag 面;实现**不得**依赖它们产生任何可观察行为。

### 17.5 与错误模型的关系

- 本章全部内建**均不是**语言核心册 §8.3 的消费者:实参求值为 `ERR` 时按语言核心册 §8.2 透明传播,函数体不执行。
- `AWAIT` **返回**子任务的 `ERR` 作为普通结果值;是否消费由调用方按语言核心册 §8.3 决定。
- 跨任务边界后,`ERR` 载荷(含 `kind` 与 `reason`)保持原值。
- 未消费的 `ERR` 到达顶层仍为 `E0102`(语言核心册 §8.5);`ERR` 被丢弃时的报告规则见语言核心册 §8.6。
- `SCOPE(ERR("x"))` 中,实参 `ERR("x")` 在语言核心册 §8.2 的透明传播阶段先于 `fn` 的函数类型检查生效,故结果是 `ERR("x")` 透传,**不**产生 `E0052`。`E0052` 仅在语言核心册 §8.2 的透明传播放过之后、参数被识别为非函数时触发。

### 17.7 限制与不承诺

| 项 | 说明 |
|----|------|
| 线程模型 | **单线程协作调度**。CPU 密集任务**不**获得并行加速 |
| 性能 | **不**承诺任何数值阈值(语言核心册 §18.5)。并发路径的性能是**非规范性观察**,不是承诺 |
| 延迟 / 吞吐 | **不**承诺延迟上界或吞吐提升 |
| 复杂度判定 | **不**使用墙钟比值(语言核心册 §18.5.2) |
| 阻塞挂起 | **真挂起**:阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在满 / 空且无对端时挂起;`TRY_*` 保持非阻塞 |
| 死锁检测 | **L1**,见下 |
| 隐式 scope | **不**提供(§17.1) |
| 通道关闭唤醒次序 | **未定义**(实现可任选)。可观察的**硬要求**只有两条:关闭后被唤醒的接收方**必须**拿到 `ERR(kind="ChannelClosed")`(语言核心册 §8.1),被唤醒的发送方**必须**得到 `E0054`;两者在**哪个**次序被唤醒,规范不管 |
| 效果处理器 | **不**暴露用户自定义效果处理器 |

公平性与在飞兄弟取消的承诺见 §17.8。

**关于「性能」一行。** 性能**不**承诺任何可验收的阈值(没有口径、没有环境、没有基准),因此它是非规范性的观察,并按下表写清口径:

| 项 | 内容 |
|---|---|
| 测什么 | 单任务、纯计算、不触通道的微基准(不含解析 / IO / 分配抖动) |
| 相对谁 | 同机同编译档,与本规范的当前行为同基准比 |
| 环境 | 需记录 CPU 型号、`rustc` 版本、`--release` 档、是否开 LTO |
| 重复 | ≥ 20 次取中位数,并报标准差 |
| 阈值 | **不写进规范**。回归由实现自己的基准门禁承担 |

并发路径**只保证正确性与无泄漏**,这一条是承诺,不受上表影响。

**复杂度判定的口径。** 并发路径的复杂度判定与语言核心册 §18.5.2 一致:**不**使用墙钟比值,判定**必须**用**确定性工作量计数**。

**死锁检测 L1**

在同一 `SCOPE` 内,当 ≥ 2 个任务阻塞在通道操作上(`SEND` / `RECV` 挂起),且不存在任何可推进的对端配对(即运行队列已空、所有等待方都无法被唤醒)时,判定为死锁:

- **默认(严格)**:`[features] strict_deadlock_detect` 为 `true` 或缺省 → 抛 `E0065` 并终止(退出码 1);
- **软化**:`strict_deadlock_detect = false` → 先发 `W0065` 警告,随后相关 `AWAIT` 以 `E0053`(无对端唤醒)报告;
- **范围限制**:
  - **不跨 `SCOPE` 检测**;
  - **不检测**纯 `YIELD` 互让(多个任务互相让步但无通道依赖不算死锁);
  - **单个**通道挂起不算死锁(只是等不到对端;此时 `AWAIT` 该任务产生 `E0053`);
  - 同一通道上互为对端的挂起收发双方**不**构成死锁(见 §17.2.1 对端配对)。

### 17.8 公平性 / 可观测性

| 维度 | 承诺 |
|------|------|
| 调度公平性 | **best-effort FIFO**:让步检查点间隔下,同优先级任务按入队次序轮转。调度器从运行队列**按入队次序**取下一个可运行任务 |
| 通道配对顺序 | 对端配对成功的双方都被标记为就绪并加入运行队列**尾部**,避免一对抢占其他就绪任务 |
| 在飞兄弟取消 | **保证在下一个检查点可观测**:目标任务在下一个 `YIELD`、阻塞型通道操作或 `TASK_IS_CANCELLED()` 处观察到取消请求 |
| 取消扫描 | 每轮调度前扫描待取消标记,把对应任务置为已取消并清空其等待登记 |

## 附录 H 操作语义(规范性)

本附录给出 §17 并发原语的**小步**(small-step)操作语义:任务状态迁移的形式化描述。

**本附录不引入任何新语义。** 它形式化的是 §17 已经规定的行为,不是新设计(总纲 §0.9 的 D-04)。本附录与 §17 冲突时以 §17 为准;本附录只负责把 §17 的规则写成可核验的迁移规则。

本附录**不**重述表达式求值规则 —— 那些在语言核心册 §4。本附录只描述**并发相关**的迁移:求值在何处**可以**被打断、打断后配置如何变化、恢复时从哪里继续、取消如何传播。

### H.1 记法与配置

```
配置 C = ⟨ T, K, Q ⟩

T : 任务表     任务标识 ↦ 任务记录
K : 通道表     通道标识 ↦ 通道记录
Q : 调度队列   就绪任务标识的有序列表(先进先出)

任务记录 = ⟨ state, segs, cur, env, cancel, reason ⟩
  state   ∈ { pending, running, suspended(ch, dir), done(v), cancelled }
  segs   : 段序列(§17.0)
  cur    : 当前段下标
  env    : 绑定环境(名字 ↦ 单元格)
  cancel : 待取消标记
  reason : 结构化取消原因(DICT)

通道记录 = ⟨ cap, buf, closed, sendWait, recvWait ⟩
  cap      : 缓冲容量
  buf      : 缓冲值序列(先进先出)
  closed   : 关闭位
  sendWait : 停泊发送方的任务标识有序表
  recvWait : 停泊接收方的任务标识有序表
```

| 记号 | 含义 |
|---|---|
| `C[x := v]` | 配置 `C` 的分量 `x` 换为 `v` |
| `Q ⧺ [τ]` | 把任务 `τ` 追加到调度队列**尾部** |
| `Q \ τ` | 把任务 `τ` 从调度队列中移除 |
| `S \ [τ]` | 从有序表 `S` 中移除任务 `τ` |

**配置不变式。** 下列各项在任何迁移之后**必须**成立:

- 每个任务的 `cur` **不**超过 `segs` 的长度;任务体**不含** `YIELD` 时 `segs` 只有一个元素(整个任务体)。
- 状态为 `suspended(ch, dir)` 的任务**必须**登记在 `K[ch]` 的 `sendWait`(当 `dir` 为 send)或 `recvWait`(当 `dir` 为 recv)中。
- `sendWait` / `recvWait` 中的任务**不**在 `Q` 中。
- `Q` 中的每个任务状态**必须**是 `pending`。

### H.2 求值关系

```
⟨C, e, ρ⟩ ↦ ⟨C', v⟩     表达式 e 在环境 ρ 下求值为值 v,配置由 C 变为 C'
⟨C, τ⟩ ⇀ C'              迁移:配置 C 经迁移 τ 变为 C'
```

**H.2.1(普通步骤)。** 前置:`e` 的求值按语言核心册 §4 的规则进行且**未**到达挂起点。结论:`C' = C`。普通步骤**不**改变 `T` / `K` / `Q`。

**H.2.2(挂起点)。** 前置:`e` 的求值到达一个挂起点。结论:该步骤**不**产生值;配置的迁移由 H.3(挂起与恢复)或 H.4(取消)给出。

普通求值步骤**不**改变配置的并发相关部分;只有到达挂起点的步骤才改变它们。表达式求值规则本身在语言核心册 §4,本附录**不**重述。

### H.3 挂起与恢复

```
H.3.1  段切分
  前置  任务 τ 由 SPAWN 派生,任务体为 b
  结论  C' = C[ τ.segs := seg(b),
               τ.cur  := 0 ]
  依据  §17.0「段」
```

```
H.3.2  YIELD 挂起
  前置  任务 τ 正在求值,求值到达 YIELD()
  结论  C' = C[ τ.state := pending,
               τ.cur  := τ.cur + 1,
               Q      := Q ⧺ [τ] ]
  读法  切段:恢复从下一段开始;挂起点之前的代码不重跑
  保留  本段已建立的绑定对恢复后仍然可见(§17.0)
```

```
H.3.3  阻塞型 SEND 挂起
  前置  任务 τ 正在求值,求值到达 CHANNEL_SEND(ch, v);
        K[ch].buf 已满且 K[ch].recvWait 为空
  结论  C' = C[ τ.state := suspended(ch, send),
               K[ch].sendWait := K[ch].sendWait ⧺ [τ],
               Q := Q \ τ ]
```

```
H.3.4  阻塞型 RECV 挂起
  前置  任务 τ 正在求值,求值到达 CHANNEL_RECV(ch);
        K[ch].buf 为空且 K[ch].sendWait 为空
  结论  C' = C[ τ.state := suspended(ch, recv),
               K[ch].recvWait := K[ch].recvWait ⧺ [τ],
               Q := Q \ τ ]
```

```
H.3.5  对端配对
  前置  一侧到达通道操作,且对端已停泊在同一通道上
  结论  值交给对端;双方状态 := pending;双方进入调度队列尾部
        C' = C[ K[ch].sendWait := K[ch].sendWait \ [对端],
                 K[ch].recvWait := K[ch].recvWait \ [对端],
                 Q := Q ⧺ [τ] ⧺ [对端] ]
  依据  §17.2.1 对端配对;§17.8 通道配对顺序
```

```
H.3.6  恢复(阻塞型)
  前置  任务 τ 因 H.3.3 或 H.3.4 停泊,并被对端或关闭唤醒
  结论  τ.state := pending;Q := Q ⧺ [τ];τ.cur 不变
  读法  不切段:恢复从当前段首重跑,挂起点之前的代码重放(§17.0)
  保留  本段已建立的绑定对恢复后仍然可见
```

```
H.3.7  关闭
  前置  CHANNEL_CLOSE(ch) 在通道未关闭时执行
  结论  K[ch].closed := true
        停泊的接收方全部释放:其 RECV 按「关闭且读空」完成,
        返回 ERR(kind="ChannelClosed")
        停泊的发送方全部释放:其 SEND 以 E0054 失败
  依据  §17.2.3 关闭协议;§17.7 通道关闭唤醒次序
```

```
H.3.8  调度器取任务
  前置  Q 非空
  结论  取 Q 的首条任务 τ;C' = C[ Q := Q \ τ ]
  依据  §17.4 调度循环;§17.8 调度公平性
```

```
H.3.9  AWAIT 等待
  前置  任务 τ 正在求值,求值到达 AWAIT(τ')
  结论  等待 τ' 达终态;等待期间调度器可运行其它可运行任务(§17.4);
        τ' 的终值按 §17.1 AWAIT 交付给 τ;
        τ 的段**不**中断:τ.state 保持 running,τ.cur 不变
  读法  不切段:τ 的段首代码不重跑;AWAIT 调用正常求值完成
        (§17.0 三类挂起点表的第三行)
  依据  §17.0 挂起点三类;§17.1 AWAIT;§17.4 调度循环
```

⚠ **三类挂起点,两套转移**:YIELD(H.3.2)与阻塞型通道操作(H.3.3 / H.3.4)产生**停泊与恢复**转移 ⇒ 任务离开 `Q`、恢复时重入队列(H.3.5 / H.3.6);而 `AWAIT` 只把控制权交给调度器,**不**使调用任务停泊 ⇒ **没有对应的恢复规则** —— 它不切段、段首不重跑(§17.0 的第三行)。⇒ V-04 取证时,`AWAIT` 这一格的判据与前两类**不同**:前两类看「段首是否重放」,`AWAIT` 看「调用任务是否在 `AWAIT` 处继续求值」。

### H.4 取消

```
H.4.1  TASK_CANCEL
  前置  目标任务句柄有效
  结论  C' = C[ 目标任务.cancel := true,
               目标任务.reason := reason ]
  读法  取消本身不产生用户 ERR 值(§17.3)
```

```
H.4.2  TASK_CANCEL_PARENT
  前置  在任务 τ 内执行
  结论  τ 及其所在作用域子树的全部任务 cancel := true
  依据  §17.3 取消与错误;§17.8 在飞兄弟取消
```

```
H.4.3  检查点观察取消
  前置  任务 τ 到达检查点 —— YIELD、阻塞型通道操作、
        TASK_IS_CANCELLED() 三者之一(§17.8);
        或调度器的取消扫描扫到 τ 的待取消标记(§17.8)
  结论  C' = C[ τ.state := cancelled ]
        若 τ 停泊在通道 ch 上,清空它的等待登记:
        K[ch].sendWait := K[ch].sendWait \ [τ]
        K[ch].recvWait := K[ch].recvWait \ [τ]
  读法  取消是协作式的:不打断正在执行的表达式(§17.3)
```

```
H.4.4  SHIELD 推迟
  前置  屏蔽块内的 TASK_CANCEL_PARENT 被调用,屏蔽层数 > 0
  结论  取消请求只被记录,不被作用于任务;
        最外层 SHIELD 退出后,取消请求转为 H.4.1 的待取消标记
  依据  §17.3 SHIELD 语义第 1—3 条
```

```
H.4.5  AWAIT 观察取消
  前置  任务 τ 的状态为 cancelled
  结论  AWAIT(τ) 返回 ERR(kind="Cancelled", task: <τ 的句柄>,
        reason: <τ 的取消原因>)
  依据  §17.3 结构化 reason;§17.1 AWAIT
```

### H.5 任务与作用域

```
H.5.1  SPAWN
  前置  当前存在活动的 SCOPE
  结论  新任务 τ 登记到当前作用域;τ.state := pending;
        C' = C[ Q := Q ⧺ [τ] ]
  例外  无活动的 SCOPE 时不派生任务,报 E0058(§17.1 无隐式 runtime scope)
```

```
H.5.2  SCOPE 进入
  前置  SCOPE(fn) 正在求值
  结论  压入子作用域;fn 在调用者的执行上下文中同步求值(§17.1)
```

```
H.5.3  SCOPE 退出
  前置  SCOPE 的 fn 已求值完毕
  结论  作用域内的全部子任务达到终态之后,SCOPE 才返回(§17.1);
        子任务的终值按 §17.1 AWAIT 交付
```
