# WLWL 语言规范 v1.0 —— 总纲

本册是 WLWL v1.0 规范体系的**总纲**:它不定义语言行为本身,而是定义这套规范**怎么读、怎么分层、每条话有多大约束力、以及 v1.0 相对 v0.11 改了什么**。

- **语言行为**在[语言核心册](wlwl-v1.0-language.md)(§1–§12、§18、§19)、[对象与行为类型册](wlwl-v1.0-objects.md)(§13–§16)、[并发册](wlwl-v1.0-concurrency.md)(§17)与[标准库册](../stdlib/)。
- **一致性与稳定性**在[一致性册](wlwl-v1.0-conformance.md)。总纲 §0.7 是它的摘要,冲突时以一致性册为准。
- **演进方向**在[路线图册](../roadmap/wlwl-v1.0-roadmap.md),**非规范**。

**编号分两套空间**:

- **语言编号空间** —— 语言核心册、对象与行为类型册、并发册**共用**一套编号。§1–§17 沿用 v0.11 不变,§18、§19 为 v1.0 新增,附录沿用 v0.11 的字母。这三册内的任何 `§N.M` 引用都指向同一处,**不因分册而重排**。
- **标准库编号空间** —— 标准库各册**共用**另一套编号(§1–§22),沿用 v0.11 标准库册的编号。

### 0.2 读者

本规范面向四类读者:WLWL 程序员;语言工具(格式化器、静态检查器、编辑器)的实现者;标准库实现者;以及判断某个行为是否合规的审计者。各类读者的最短阅读路径见[一致性册](wlwl-v1.0-conformance.md) §7。

### 0.3 规范性用语

本规范中的关键词 **必须**(MUST)、**不得**(MUST NOT)、**应当**(SHOULD)、**可以**(MAY)按以下含义使用:

- **必须 / 不得**:实现的硬性约束。违反时实现必须产生一个诊断(语言核心册 §11)并按 §11.4 终止或报告。
- **应当**:强烈推荐的行为;实现可以偏离,但偏离必须在本规范或实现文档中说明。
- **可以**:真正的实现自由度。

标注为**非规范**(non-normative)的段落、注释与附录不构成一致性要求。

### 0.4 一致性

一个 WLWL 程序是符合本规范的,当且仅当它只使用本规范定义的语法形式与语义,且不依赖任何标注为未定义、保留或实现定义的行为。一个实现是一致的,当且仅当它接受所有一致的程序并产生本规范规定的结果。完整的判定口径、条款分类与验证要求见[一致性册](wlwl-v1.0-conformance.md)。

### 0.5 记法

语法用扩展巴科斯范式(EBNF)书写,记法约定见语言核心册 附录 A。正文中 `code` 样式表示词法记号、字面代码或诊断码;`name` 斜体表示文法产生式。示例代码以 `//` 注释标出其求值结果。值形状用 `json` 标记的代码块给出。

**围栏约定**:文法块用**无标记**围栏;示例代码块用 **`wlwl`** 标记的围栏,且**必须**能在参考实现上运行且退出码为 0。

**标点约定**(v1.0 全册统一):逗号 `,`、冒号 `:`、分号 `;`、圆括号 `()`、方括号 `[]` 一律用**半角**;句号 `。`、顿号 `、`、引号 `「」`、破折号 `——` 用**全角**。全角 `,` `:` `;` `(` `)` **不得**出现在本规范的正文里。

**跨册引用**写全册名加节号,例:"语言核心册 §8.2"、"标准库册 §5.2"、"一致性册 §3"。同册内的引用可只写节号,例:"(§8.2)"。

### 0.6 规范矩阵

**本节是这套规范的管辖总表。** 每个主题**有且只有一个**归属册;归属册的表述是该主题的唯一规范性来源。其它册**不得**重复定义归属主题的语义,只能引用。

| 主题 | 归属册 | 节 | 规范性 |
|---|---|---|---|
| 词法结构、源文件、注释、标识符、字面量 | 语言核心册 | §1 | 是 |
| 值域、算术性质、真值、相等、显示 | 语言核心册 | §2 | 是 |
| 静态类型词汇(注解层) | 语言核心册 | §2.6 | 是(受 `gradual_typing` 开关约束) |
| 绑定、作用域、单元格可变性、`SET` | 语言核心册 | §3 | 是 |
| 表达式、求值顺序、运算符即函数 | 语言核心册 | §4 | 是 |
| 函数、形参、类型注解的静态解释 | 语言核心册 | §5 | 是 |
| 控制流 | 语言核心册 | §6 | 是 |
| 模式匹配 | 语言核心册 | §7 | 是 |
| 错误模型、消费者注册表、顶层逃逸、**未消费 `ERR` 的报告** | 语言核心册 | §8 | 是 |
| 模块与程序、清单文件、模块契约 | 语言核心册 | §9 | 是 |
| 标准库机制面(全局内建、命名空间导入方式) | 语言核心册 | §10 | 是(成员契约见标准库册) |
| 诊断结构、错误码表、警告码表、退出码 | 语言核心册 | §11 | 是 |
| 保留形式 | 语言核心册 | §12 | 是 |
| 对象模型 | 对象册 | §13 | 是 |
| 行为类型与会话类型协议 | 对象册 | §14 | 是 |
| `THIS` 与线性 capability | 对象册 | §15 | 是 |
| OOP 与并发的交互 | 对象册 | §16 | 是 |
| 并发(结构化并发、通道、取消、代数效果执行模型) | 并发册 | §17 | 是 |
| **复杂度与性能保证** | 语言核心册 | §18 | 是 |
| **内存与资源模型** | 语言核心册 | §19 | 是 |
| 标准库成员的签名、语义、失败口径、边界 | 标准库册 | §1–§22 | 是 |
| 成员注册镜像(冻结快照) | 标准库·注册镜像册 | 附录 A | 是 |
| 一致性、条款类型、稳定性政策、公共面、验证要求 | 一致性册 | 全文 | 是 |
| 演进方向、已否决方向、候选方向 | 路线图册 | 全文 | **否** |

**三条由本表推出的规则**:

1. **R0 / R1 / R2 是实现分层,不是规范层级。** 它只出现在标准库册的「层」列,含义是"这段成员由哪一层实现"。**成员的规范强度与它落在哪一层无关** —— 一个 R1 成员与一个 R2 成员承担同样的规范性义务。归属判定规则见标准库册 §0.7。
2. **跨册冲突不靠"以谁为准"解决,靠本表消除。** v0.11 的"两册冲突时以语言规范为准"是权宜之计,它掩盖了真实的管辖重叠;v1.0 用本表让每个主题只有一个主人,因而不再需要冲突裁决规则。
3. **矩阵缺项即为规范空白。** 若某个行为在矩阵里找不到归属册,它**没有**规范性 —— 实现**可以**自由发挥,用户**不得**依赖。

### 0.7 条款类型

本规范的每一条陈述属于且仅属于下列五类之一。分类的完整定义、判据与各类的约束力见[一致性册](wlwl-v1.0-conformance.md) §2。

| 类型 | 标记 | 约束力 |
|---|---|---|
| 规范条款 | 无标记,含 **必须** / **不得** / **应当** / **可以** | 构成一致性要求 |
| 解释性说明 | 段落以**说明**起首 | 帮助理解,不构成要求 |
| 实现注 | 段落以**实现注**起首 | 记录当前实现的做法,不构成要求 |
| 示例 | `wlwl` 代码块及其相邻说明 | 展示用法,不构成要求 |
| 演进方向 | 路线图册全文 | 非规范 |

**实现注必须与规范条款物理分离**:它只能以独立段落出现,**不得**与规范条款同段,**不得**夹在一条规则的中间。一段话若同时含有规范断言与实现描述,作者**必须**把它拆成两段。

### 0.8 文档层级

WLWL 生态里的文档不止规范。下列层级是**全局**的,任何项目引用 WLWL 文档时**应当**先确认它在哪一层。

| 层 | 是什么 | 具规范性 | 变更节奏 |
|---|---|---|---|
| **L-规范** | 本体系的 11 册 | 是 | 受稳定性政策约束(一致性册 §3) |
| **L-实现注** | 记录实现机制、实测数据、踩过的坑的文档(如实现仓的 agent 工作说明、`wlwl-skill`) | **否** | 随实现变化,可随时改 |
| **L-决策** | ADR、偏差台账、构建计划 | **否** | 随裁决变化 |
| **L-历史** | 已收口的方案、审查报告、日次归档 | **否** | 只增不改 |

**硬规则:L-实现注永远不得成为可观察行为的第二来源。** 它与 L-规范冲突时,以 L-规范为准;它与源码实测冲突时,以实测为准并回头修 L-实现注 —— 但**不得**在 L-实现注里悄悄"修正" L-规范。L-规范与实测冲突时,走一致性册 §5 的差异登记流程。

### 0.9 与 v0.11 的差异

本节登记 v1.0 相对 v0.11 的**全部**语义变更。**未在本表出现的改动不构成语义变更**(措辞、章节顺序、拆分与合并不在此列)。实现者据此判断自己需要改什么。

| # | 变更 | 类别 | 落点 | 实现状态 |
|---|---|---|---|---|
| D-01 | **未消费的 `ERR` 不再被静默丢弃。** 任何被丢弃的未消费 `ERR` 产生 `E0103`;`LET(_, expr)` 是唯一的显式丢弃构造 | **breaking** | 语言核心册 §8.6 | 未实现 |
| D-02 | 复杂度与性能保证升为规范性条款:字典键查找 O(1) 期望、数组追加 O(n) 最坏、字符串拼接 O(n+m) 最坏、累加器惯用法 O(n) 摊还(推荐上界)、`SORT` 比较次数 O(n²) 最坏 | **breaking**(部分上界收紧) | 语言核心册 §18 | 未实现 |
| D-03 | 内存与资源模型成文:值的生命周期、单元格持有、实例字段共享边界、资源释放责任 | 补充 | 语言核心册 §19 | 未实现 |
| D-04 | 挂起与恢复语义形式化(小步操作语义推理规则),不新增语言语义 | 补充 | 并发册 附录 H | 未实现 |
| D-05 | 早期未处理 `ERR` 的"静默丢弃"限制**被删除**,不再作为已知限制存在 | **breaking** | 语言核心册 §8.5 / §8.6 | 未实现 |
| D-06 | 语言核心册 §10.6 的 `std.collection` 成员面快照**作废**(v0.11 偏差 D11-012:彼处写 17 个成员,标准库册实为 27 个);该节只保留机制性内容 | **breaking**(订正错误事实) | 语言核心册 §10.6 | 已实现 |
| D-07 | 标准库附录 A 由"从实现清单生成的活镜像"改为**v1.0 冻结快照** | 补充 | 标准库·注册镜像册 | 未实现 |
| D-08 | 新增诊断码 `E0103`(未消费 `ERR` 被丢弃) | **breaking** | 语言核心册 §11.2 | 未实现 |
| D-09 | 稳定性政策由标准库册的一节升为独立册,并显式定义「公共面」 | 补充 | 一致性册 §3、§4 | 未实现 |
| D-10 | 规范矩阵、条款类型、文档层级三套机制成文 | 补充 | 总纲 §0.6、§0.7、§0.8 | 未实现 |

**「实现状态」列的三态**:「已实现」= 当前参考实现已符合;「未实现」= 规范已定,实现侧待办;「部分」= 行为已存在但与条款不完全一致。v1.0 发布前,「未实现」与「部分」**必须**清零 —— 一致性册 §3.4 把它写成了发布前置条件。

### 0.10 已裁定与未决

v1.0 的设计取舍已在下列文档中裁定,不再重开:

- **模块别名不引入。** `IMPORT` 的改名形态(`IMPORT(path, ["orig": "alias"])`)已覆盖命名冲突;命名空间限定调用按设计不存在,故"模块别名"在 WLWL 里没有对应概念。理由见路线图册 §2。
- **续体(continuation)保存不进入 v1.0。** WLWL 的挂起模型是"让出控制再回来",恢复从挂起点**之后**继续,不保存续体;v1.0 把这套现有语义形式化,不引入新的挂起语义。理由见路线图册 §2。
- **性能注解(`@complexity` 之类)不进入 v1.0 的语言表面。** v1.0 只承诺 §18 的复杂度上界,不承担"注解与实现不符即报错"这类合同。理由见路线图册 §2。
- **字符串构建器不进入 v1.0 的语言表面。** 它是标准库成员,不是语言构造;是否提供属标准库范畴,见路线图册 §3。

尚未裁定的开放项集中在路线图册 §3,以及一致性册 §6.2 列出的待验证清单。

### 0.11 命名与引用约定

- 规范册统一置于 `docs/spec/` 与 `docs/stdlib/`,文件名形如 `wlwl-v1.0-<主题>.md`。
- 章节标题的编号与正文里出现的编号**必须**一致;本册 §0.1 的册表是册子清单的唯一权威。
- 引用诊断码写作 `E0103`;引用成员写作 `成员名` 或 `命名空间::成员名`(如 `std.json::JSON_PARSE`)。
- 引用上游实现时**必须具名**:项目名、仓库、基线提交、相关 issue。具名要求与理由见一致性册 §6.3。
