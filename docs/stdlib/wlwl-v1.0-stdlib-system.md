## 0 导言与总则

### 0.1 本册的构成

本册定义 WLWL 标准库的**系统与外部世界**部分:`std.io`(§1)、`std.fs`(§2)、`std.time`(§15,墙钟与单调钟)、`std.rand`(§17,显式播种的随机数)、`std.env`(§18,进程环境与命令行参数)、`std.process`(§19,不经 shell 跑子进程)、`std.compress`(§20,Zstandard 与 DEFLATE 家族)、`std.net`(§21,网络)。每章对应一个命名空间,每章含成员表(签名 / 语义 / 失败 / 复杂度 / 层)、共享失败口径、值形状与边界、示例与该章特有条款;附录 A 是**规范性**的成员注册镜像,由[标准库·注册镜像册](wlwl-v1.0-stdlib-registry.md)承载。

**成员数以附录 A 镜像为准**:本册各章的成员表与附录 A **逐项对拍**,两者**必须**集合相等。

全局内建(`PRINT` / `LEN` / `FORMAT` 等)**不在**本册重复定义,见语言核心册 §10.2–§10.5、§10.7、§10.9、§10.12 与其附录 G。

### 0.2 读者

本册面向三类读者:使用标准库的 WLWL 程序员、标准库实现者,以及需要判断某个成员行为是否合规的工具作者。

### 0.3 规范性用语

本册中的关键词 **必须**(MUST)、**不得**(MUST NOT)、**应当**(SHOULD)、**可以**(MAY)按以下含义使用:

- **必须 / 不得**:实现的硬性约束。违反时实现必须产生一个诊断(语言核心册 §11)并按 §11.4 终止或报告。
- **应当**:强烈推荐的行为;实现可以偏离,但偏离必须在本册或实现文档中说明。
- **可以**:真正的实现自由度。

标注为**非规范**(non-normative)的段落、注释与附录不构成一致性要求。

### 0.4 一致性

一个 WLWL 程序是符合本规范的,当且仅当它只使用本册定义的成员面,并按各章的语义与失败口径使用它们。一个实现是一致的,当且仅当它提供本册各章列出的全部成员,对每个成员给出规定的签名、语义、失败行为与边界,且不依赖任何标注为未定义、保留或实现定义的行为。

### 0.5 记法

成员表统一为**五**列:

| 列 | 含义 |
|---|---|
| 签名 | 成员名与形参;`?` 表示可选形参;`...` 表示变参 |
| 语义 | 正常路径的可观察行为 |
| 失败 | 失败时的可观察行为;`—` 表示**不因输入内容失败**。实参层诊断(元数错 `E0022`、类型错 `E0030`)适用于**全部**成员,由语言核心册 §8 与 §11.2 统一规定;各章**可以**重复列出以便查阅 |
| 复杂度 | 时间代价上界,记法见语言核心册 §18;`—` 表示规范不约束 |
| 层 | 实现分层(§0.7);R0 内建层 / R1 语言层 / R2 原生层 |

正文中的 `code` 样式表示词法记号、字面代码或诊断码。示例代码以 `//` 注释标出其求值结果。值形状用 `json` 标记的代码块给出。

**标点约定**:逗号 `,`、冒号 `:`、分号 `;`、圆括号 `()`、方括号 `[]` 一律用**半角**;句号 `。`、顿号 `、`、引号 `「」`、破折号 `——` 用**全角**。

**围栏约定**:文法块用**无标记**围栏;示例代码块用 **`wlwl`** 标记的围栏,且**必须**能在参考实现上运行且退出码为 0。

**失败示例的记法**:预期产生诊断的片段**不**写成 `wlwl` 围栏 —— 它们以非零退出码终止,不是可运行示例。本册用表格列出失败形态与预期诊断码。

**引用**:同册内写 `(§5.2)`;跨册写册名加节号,例:"语言核心册 §8.2"、"并发册 §17.3"、"一致性册 §3"。

**规范性标注**:本册**全部**为**规范性**;各章的「设计依据」小节是**非规范性**的追溯材料,不构成要求。

### 0.6 调用面

标准库的调用面只有两种形式,与实现层无关:

- **全局内建**(R0 内建层):无须导入;契约见语言核心册 §10.2–§10.5、§10.7、§10.9、§10.12 与其附录 G。本册不重复、不镜像全局内建。
- **命名空间成员**:`IMPORT("wlwl:std.X", [names])` 导入后调用;成员契约见本册各章。官方包 `ai` / `agent` 的导入路径分别是 `ai:ask` 与 `agent:task`。

**本语言没有「命名空间限定调用」表达式**:文法里没有 `ns.MEMBER(...)` 这种形式,冒号只出现在 `IMPORT` 的路径字符串与改名处。成员只能经 `IMPORT` 取裸名;需要避开与类型名同名时,在 `IMPORT` 时改名。

### 0.7 实现分层

| 层 | 实现语言 | 内容 |
|---|---|---|
| R0 内建层 | 纯 Rust(编译器/运行时内部) | 语言自身无法表达或与编译器强耦合的原语;即语言核心册附录 G 全部条目 |
| R1 语言层 | 纯 wlwl(`.wll` 源码,`include_str!` 嵌入二进制) | 不触系统调用且非性能敏感的库;**非敏感库的默认归宿** |
| R2 原生层 | 纯 Rust(`wlwl-std`) | 触系统调用、性能敏感、或需复用成熟 Rust crate 的库 |

**归属判定**(机械执行):

1. 触系统调用 / OS 资源 / 进程·网络·时间·随机 → R2;
2. 语言核心语义 → R0;
3. 其余 → R1;仅当基准数据证明热点且解释器短期无优化空间时下沉 R2;
4. R2 成员**必须**有不依赖实现细节的语义描述,保证可被 R1 等价替换。

**层间规则**:R1 **可以**调用 R0 与 R2;R2 **不得**调用 R1(确需时走白名单并登记偏差)。混合模块以门面(R1 侧)为对外契约层。层归属变更(下沉/上浮)**不算**破坏性变更,但**必须**附基准数据并登记。

**R0 / R1 / R2 是实现分层,不是规范层级。** 成员的规范强度与它落在哪一层**无关** —— 一个 R1 成员与一个 R2 成员承担同样的规范性义务(总纲 §0.6 规则 1)。

### 0.8 与语言规范的依赖与差异登记

本册以语言核心册 的值域、错误模型、模块机制、诊断码表、并发语义、复杂度保证与内存模型为前提,不重复定义。两册冲突时**以语言核心册为准**。

本册**唯一**的跨册差异登记是:`ERR` 的产生与消费规则。语言核心册 §8.6 规定"未消费的 `ERR` **不得**被丢弃",本册各章的「失败」列**只**描述成员自身在失败时**返回什么**,**不**复述 §8.6 —— `ERR` 值的丢弃与报告一律由 §8.6 承担。

## 1 `std.io` —— 基础 I/O

三个成员,与全局内建**同名同语义**(冻结例外;机制面的定义见语言核心册 §10.2,成员契约以本章为准)。

> **记法约定**:预期产生诊断的片段**不**写成 `wlwl` 围栏 —— 它们以非零退出码终止,不是可运行示例。本册用**表格**列出失败形态与预期诊断码。

### 1.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `PRINT(args...) -> NULL` | 依序渲染实参(语言核心册 §2.5),以空格分隔输出到标准输出 | — | — | R2 |
| `PRINT_ERR(args...) -> NULL` | 同上,输出到标准错误 | — | — | R2 |
| `INPUT(prompt?) -> STRING` | 读一行标准输入;给了 `prompt` 时**必须**先把 `prompt` 写到标准输出再读 | 元数 > 1 → `E0022`;`prompt` 非 `STRING` → `E0030`;读失败(I/O 错误)→ `E0060` | — | R2 |

**本章的共享失败口径**:元数 / 类型错是**程序员错误**,走原生诊断(语言核心册 §11.2);读输入失败也是原生诊断口径(终止运行)。本章**不**产生 `ERR` 值。

三个成员都触宿主的标准流,耗时由宿主的设备与调度决定,规范**不**给上界(语言核心册 §18.5)。

### 1.2 值形状与边界

- **`PRINT` / `PRINT_ERR` 恒返回 `NULL`**,不返回被打印的值;它们**不**返回打印出的字符数。
- **分隔符无条件插入** —— 实参自带尾空格时会得到两个空格(`"hello, "` + `"world"` ⇒ `hello,  world`)。分隔符**不**因实参为空而省略。
- **渲染口径**是语言核心册 §2.5 的 `STR` 口径:数组渲染成 `[1, 2, 3]`,字典按**插入序**渲染,`NULL` 渲染成 `NULL`。
- **`PRINT_ERR` 与 `PRINT` 的可观察差别只有输出流**:内容与分隔规则逐字相同。
- **读到 EOF 与读失败是两件事**:`INPUT` 在**一个字节都没读到**时返回 `""`;只有 I/O 错误才产生 `E0060`。
- **成员名与全局内建同名**:程序不导入 `std.io` 时,`PRINT` 解析到全局内建(语言核心册 §10.2);导入 `std.io` 之后,导入的名字**优先**。两条路径**必须**逐字相同(限**成功路径**:prompt 的写法与读到的行)。
- **失败路径各按各层的失败模型**:内建层的读失败产 `ERR` 值(语言核心册 §10.2),本成员的读失败是原生诊断 `E0060`(§1.1)—— 这是**分层设计**(内建层用 `ERR` 值,成员层用原生诊断),**不是**待收敛的分叉。EOF **不是**失败:两条路径都返回 `""`(上一条)。

### 1.3 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `PRINT` | 无外部资源。标准输出流由宿主持有,成员**不得**关闭它;输出**必须**在返回前完成。 |
| `PRINT_ERR` | 同 `PRINT`;标准错误流同样由宿主持有,成员**不得**关闭它。 |
| `INPUT` | 标准输入流由宿主持有,成员**不得**关闭它。一次读**必须**只消费一行,**不得**为「留后读」而预读后续行。 |

### 1.4 示例

```wlwl
IMPORT("wlwl:std.io", ["PRINT", "PRINT_ERR"]);
PRINT("hello", "world");   // hello world
PRINT_ERR("to stderr");    // to stderr(输出在标准错误流上)
```

### 1.5 该章特有条款

**冻结例外**:这三个成员与全局内建同名同语义,自 v0.3 起冻结。它们**不得**因「统一两处实现」而改变可观察行为 —— 两处实现**必须**逐字相同,而不是「语义大致相同」。

**`INPUT` 的输入不是可复现的**:读标准输入的结果依赖调用方写了什么,用了 `INPUT` 的程序因此**不**满足「同一输入 ⇒ 同一行为」。本册**不**检测这件事(运行时检测不到「你有没有读输入」),只在此声明。

### 1.6 设计依据

**本节为非规范的追溯材料,不构成一致性要求。**

本章三个成员自 v0.3 起冻结,语义一字未动;与全局内建同名的形态是 v0.3 的既有设计。R2 归属按本册 §0.7 的机械规则第 1 条(触系统调用)判定 —— 标准输入 / 标准输出 / 标准错误都是宿主资源。

## 2 `std.fs` —— 文件系统

路径、目录与字节读写的成员面。**规范分隔符恒为 `/`**(§2.2);字节形状恒为 `ARRAY[INTEGER]`(§2.2);**IO 失败一律是 `ERR` 值**,**不**产生原生诊断(§2.3)。

### 2.1 成员表

本节 `p` = 路径片段数,`m` = 路径字符串的码点数。IO 密集成员的耗时由外部环境决定,规范**不**给上界(语言核心册 §18.5)。

**v0.3 的三个冻结成员**(签名与语义自 v0.3 起冻结;⚠ **v1.0.2 起 `READ_FILE` / `WRITE_FILE` 的 IO 失败口径由原生诊断改为 `ERR` 值** —— 定性与迁移写法见 §2.3.1):

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `READ_FILE(path) -> STRING` | 读 UTF-8 文本;父目录**必须**已存在 | IO 失败(不存在 / 读不出 / 是目录)→ `ERR([kind: "FsError", op, reason])` | — | R2 |
| `WRITE_FILE(path, text) -> NULL` | 写 UTF-8 文本;父目录**必须**已存在 | 写失败 → `ERR([kind: "FsError", op, reason])` | — | R2 |
| `EXISTS(path) -> BOOLEAN` | 存在测试。⚠ **读不到元数据一律当作「不存在」** ⇒ 本成员**没有**失败面 | — | — | R2 |

**路径族**:

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `PATH_JOIN(parts...) -> STRING` | 变参(≥1,全 `STRING`);用 `/` 连接,**合并重复分隔符**、**跳过空片段** | 元数 < 1 或类型错 → `E0022` / `E0030` | `O(p + m)` | R2 |
| `PATH_DIR(p) -> STRING` | 父目录。**无父目录时返回 `""`**(不是 `"."`) | 同上 | `O(m)` | R2 |
| `PATH_BASE(p) -> STRING` | 最后一段。**不剥扩展名**(`a.tar.gz` → `a.tar.gz`) | 同上 | `O(m)` | R2 |
| `PATH_EXT(p) -> STRING` | 扩展名,**不含前导点**;无扩展名 → `""`;**点文件没有扩展名**(`.gitignore` → `""`) | 同上 | `O(m)` | R2 |
| `PATH_NORMALIZE(p) -> STRING` | 消 `.` / `..` / 冗余分隔符。**纯词法,绝不碰符号链接** | 同上 | `O(m)` | R2 |

**目录与字节族**:

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `LIST_DIR(p) -> ARRAY[STRING]` | 列目录(不递归),返回**以 `p` 为前缀的完整路径**(用 `/`),**含目录条目本身**,**结果排序** | 不存在 / 非目录 → `ERR([kind: "FsError", op, reason])` | — | R2 |
| `WALK_DIR(p, pattern?, follow?) -> ARRAY[STRING]` | 递归,返回**相对 `p`** 的路径(用 `/`),**排序**。⚠ `p` 本身打不开 ⇒ `ERR`,与 `LIST_DIR` 同口径;递归途中的**子目录**打不开(权限 / 竞态删除)静默跳过 | 同上 | — | R2 |
| `MKDIR(p) -> NULL` | 建**单层**;**已存在 → `ERR`**(不静默) | 同上 | — | R2 |
| `MKDIRS(p) -> NULL` | 建**多级**(`mkdir -p`);**已存在即成功** | 同上 | — | R2 |
| `REMOVE(p, recursive?) -> NULL` | 删文件 / 删目录;目录**未**带 `recursive = TRUE` 时非空即失败 | 同上 | — | R2 |
| `COPY(src, dst) -> NULL` | 复制**文件**;目录**不做** | 同上 | — | R2 |
| `MOVE(src, dst) -> NULL` | 移动 / 重命名;跨设备自动回退为「复制 + 删除」 | 同上 | — | R2 |
| `FILE_SIZE(p) -> INTEGER` | 字节数 | 同上 | — | R2 |
| `READ_BYTES(p) -> ARRAY[INTEGER]` | 二进制读,元素 `0..=255`。⚠ 单次超过 `MAX_READ_BYTES` = **1 MiB** ⇒ `ERR`,**不是截断、不是 OOM** | 同上 | — | R2 |
| `WRITE_BYTES(p, data) -> NULL` | 二进制写;`data` 是 `ARRAY[INTEGER]`,**逐元素校验** `0..=255`。⚠ 单次超过 `MAX_WRITE_BYTES` = **64 MiB** ⇒ `ERR`,**不是截断、不是 OOM**;⚠ **超限时目标文件必须原封不动** | 同上 | — | R2 |

**本章的共享失败口径**:本章**只有一套 IO 失败口径** —— 一律 **`ERR` 值**;元数 / 类型错一律 `E0022` / `E0030` 原生诊断。完整规定见 §2.3。

### 2.2 值形状与边界

- **字节形状**恒为 `ARRAY[INTEGER]`,元素 `0..=255`。这是本语言**唯一**的无损字节载体 —— `std.encode::RANDOM_BYTES` 返回的就是这个形状。`STRING` 是 UTF-8,装不了任意字节,硬塞只能**有损替换**成 `U+FFFD`,而本册**不**提供有损替换。**范围**:这是给**小**二进制用的(配置、图标、密钥材料片段);**大载荷的正解是让它待在文件里**。
- **分隔符口径**:规范形态恒为 `/`。**输入端**在 Windows 上额外容忍 `\` —— 那是 v0.3 三个成员**既有**的行为(它们把 path 原样交给 OS),收掉就是破坏性变更。**POSIX 上不做 `\` → `/` 的替换**:`\` 在 POSIX 里是**合法文件名字符**,把它换成 `/` 会让一个真实存在的文件「找不到」。
- **出参端同理**:`LIST_DIR` / `WALK_DIR` 返回的相对路径**只在 Windows 上**做 `\` → `/` 归一;在 POSIX 上**不得**替换 —— 形如 `a\b.txt` 的**合法文件名**若被吐成 `a/b.txt`,而**把出参原样喂回 `READ_FILE` / `MOVE` 会指向另一个路径**,那是**不可逆的往返破坏**。Windows 上替换**无损**(`\` 不可能出现在 Windows 文件名里)。
- **为什么分隔符要写死**:平台原生形态下 `PATH_JOIN("a","b")` 在 Windows 返 `a\b`、Linux 返 `a/b` ⇒ **同一份程序跨平台产出不同字符串** ⇒ 契约表**无法逐字节冻结**。而逐字节冻结是本规范所有契约表的立足点。
- **`PATH_DIR` 选 `""` 而不是 `"."`**:本语言里 `PATH_JOIN(PATH_DIR(x), PATH_BASE(x))` 是取回 `x` 的惯用写法,`""` 让它成立而不必特判。
- **`PATH_NORMALIZE` 是纯词法的**:它**不知道** `a/../b` 里的 `a` 是不是符号链接,所以「消 `..`」可能与真实文件系统不一致。这是刻意的 —— 一个会去 `canonicalize` 的 `NORMALIZE` 就有 I/O 副作用、且路径不存在时行为突变,那不是「归一化」。要真实解析用 `EXISTS` / `LIST_DIR`。
- ⚠ **与 `WALK_DIR` 的相对路径坐标系不同** —— `LIST_DIR` 的每项是**以 `p` 为前缀的完整路径**,`WALK_DIR` 的每项是**相对 `p`** 的路径 ⇒ 两者的结果**不能直接比较**。跨成员比较前先归一(`LIST_DIR` 的每项去掉 `p` 前缀即得相对路径)。
- **符号链接**:`LIST_DIR` **列出**链接条目(你有权知道它存在)但**不跟随**;`WALK_DIR` **默认不下降进链接目录**(`follow = FALSE`),因为**成环的链接目录会让递归永不终止**。`follow = TRUE` 时**下降进**链接目录,并记 **visited 集合**(按 `canonicalize`)防环;**此语义在 POSIX 与 Windows 上相同**。
- **`MOVE` 的跨设备回退**(复制 + 删除)按 `WALK_DIR(follow = TRUE)` 的纪律展开符号链接并记 `visited` 防环;**命中环返 `ERR` 而非跳过**。返 `ERR` 是刻意的:跳过会让随后的删除步骤**把源侧链接删掉** —— 搬完少一个链接,比直接报错更坏。
- 🔴 **`MOVE` 对符号链接的处理**随**源与目标是否同一设备**而变,这是**实测**结论,不是设计意图:

| 场景 | 走的路径 | 链接在目的地的结果 |
|---|---|---|
| **同设备** | `rename` | **链接原样保留**(符号链接仍是符号链接) |
| **跨设备**(回退) | 复制 + 删除 | **按内容展开** —— 目录链接变成实体目录,文件链接变成目标文件的内容 |

- ⚠ **为什么跨设备是「按内容展开」而不是「原样重建链接」**:「原样重建」在 POSIX 上要 `symlink`,在 Windows 上要**特权或开发者模式**;没有那些条件时它**根本没有定义**(退化成展开,或直接失败)⇒ `MOVE` 的结果**不应该取决于「这台机器能不能建符号链接」这种环境事实**。「跳过并报错」则是功能倒退(带链接的目录就搬不动)。⇒ 本规范**规定现状**:跨设备回退按内容展开,同设备保持链接。⚠ 调用方若依赖「搬过去的东西仍是链接」,**必须**自己确认同设备。
- **`WALK_DIR` 的 `pattern` 是 glob**:`*` **不跨分隔符**、`**` 跨目录、`?` 匹配单个字符。pattern **含 `/`** 时匹配整条相对路径,**否则只匹配文件名**。缺省 = 全中。
- ⚠⚠ **写得出 ≠ 读得回** —— 两个成员的档位**不同**:`WRITE_BYTES` 一次最多写 **64 MiB**,而 `READ_BYTES` 一次最多读 **1 MiB** ⇒ **大于 1 MiB 的文件是 `WRITE_BYTES` 写得出来、`READ_BYTES` 读不回来的**。⚠ 这**不是缺陷**,是两个成员各自的策略上限;**任何 > 1 MiB 的写上限都无法建立「写出来的读得回来」**(该方向性契约只有把写上限压到 ≤ 1 MiB 才成立,而那会**删掉「写大文件」这个能力** —— `WRITE_BYTES` 是本语言**唯一**能写出文件内容的成员)。⇒ **大载荷的正解是让它待在文件里**:压缩 / 拷贝都在 R2 侧走字节流(`std.compress`),绕语言值搬一趟会重新踩上解释器侧数组构建的超线性证据。⚠ **流式写 / 分段读成员本册不做** —— 它们要动的是成员面(新增成员 ⇒ 附录 A 与章号都要跟着动),而「写得出 ≠ 读得回」本身**不是缺陷**、是两个成员各自的策略上限。⇒ 记为**已知边界**,不作为待修缺陷。

### 2.3 失败口径

本章**只有一套 IO 失败口径**:**`ERR` 值**。

- **IO 失败**(文件不存在 / 读不出 / 是目录 / 写不进 / 权限不足)⇒ 返 `ERR([kind: "FsError", op: <成员名>, reason: <路径与 OS 原因>])`。理由是这些是**可预期的运行期结果**,调用方多半要 `IS_ERR` 分支;做成终止整个运行的诊断,调用方连分支都写不了。⇒ **进程不因此终止。**
- **元数 / 类型错** ⇒ 原生诊断 `E0022` / `E0030`(程序员错误,与运行期结果分属两事)。
- `EXISTS` **没有**失败面:读不到元数据一律当作「不存在」⇒ 它返回 `BOOLEAN`,**不**返回 `ERR`。

⚠ **读侧与写侧是两个入口**:`READ_FILE` 与 `WRITE_FILE` 的 `reason` **必须**分得开 —— 父目录不存在在 OS 层同样落进「不存在」,共用一句会把「写不进」说成「文件不存在」,调用方就分不出「读不到」与「写不进」。

#### 2.3.1 v1.0.2 的破坏性变更:IO 失败由原生诊断改 `ERR` 值

v1.0.1 及更早版本里,`READ_FILE` / `WRITE_FILE` 的 IO 失败走**原生诊断**(`E0061` / `E0062`,终止运行),而本章其余成员走 `ERR` 值 ⇒ **同一命名空间两套失败语义**。一次读失败就**打死整个进程**,调用方连重试与降级都做不到。

> **定性**:按一致性册 §3.4,本项落在**例外 2(规范缺陷修复)**之内 —— 本章的失败口径表与「v0.3 的三个冻结成员用原生诊断」两套语义**自相矛盾**(同一个 `std.fs` 章里,「文件不存在」既是可预期的运行期结果、又是终止整个运行的诊断);修复方向是**消除两套语义**,**不**引入新的自由度。`E0061` / `E0062` 自 v1.0.2 起**退役**(语言核心册 §11.2)—— ⚠ 这两个码**本身不被删掉**,只是**不再由 `std.fs` 产生**。

**迁移写法**:原先依赖 `E0061` / `E0062` 终止运行的代码,改用 `IS_ERR` 判别 + `ERR_PAYLOAD` 取载荷,并**自行处置**(下块是**形状**,**不是**可运行示例 —— 参考实现 v0.11.4 仍走诊断,实现侧 v0.12.0 起才落地本口径):

```
LET(r, READ_FILE(path));
IF(IS_ERR(r),
    (LET(p, ERR_PAYLOAD(r)); PRINT("caught:", AT_K(p, "reason", "?"))),
    (PRINT(r))
);
```

⚠ `IS_ERR` 只是**观察**(语言核心册 §8.6.1):只判别而**不**取载荷 ⇒ 那个 `ERR` 仍未被消费 ⇒ 作用域结束时照报 `E0103`(语言核心册 §8.6.2)⇒ **判别 + 取载荷两步都必须写**;`std.result::TAKE_ERR`(标准库·核心册 §22)把两步合成一步。

**相对路径按进程 CWD 解析**:程序的 base dir(用于 `IMPORT` 解析相对模块路径)**不影响**文件操作 —— `LIST_DIR(".")` 列的是**当前工作目录**。推论:测试里做文件操作**必须**用绝对路径,否则会把文件写进工作树。

### 2.4 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `READ_FILE` | 成员**必须**在返回前关闭它打开的文件句柄;成员不返回句柄,调用方**没有**可释放的资源。 |
| `WRITE_FILE` | 同 `READ_FILE`:写完即关闭;失败路径**必须**同样关闭,**不得**泄漏句柄。 |
| `EXISTS` | 无外部资源。 |
| `PATH_JOIN` / `PATH_DIR` / `PATH_BASE` / `PATH_EXT` / `PATH_NORMALIZE` | 纯函数,**不**打开任何文件,**不得**产生 I/O 副作用。 |
| `LIST_DIR` | 成员**必须**在返回前关闭它打开的目录句柄;结果数组里的每一项是**值**,不是打开的句柄。 |
| `WALK_DIR` | 遍历期间打开的目录句柄**必须**逐个关闭,包括被**静默跳过**的子目录;返回后**不得**留下任何打开的目录。 |
| `MKDIR` / `MKDIRS` | 无需释放(只创建目录项)。 |
| `REMOVE` | 无需释放;`recursive = TRUE` 时展开出的每一项**必须**在删除前关闭。 |
| `COPY` / `MOVE` | 成员**必须**在返回前关闭源与目标两侧的句柄;跨设备回退的「复制 + 删除」路径同样如此。 |
| `FILE_SIZE` | 成员**必须**在返回前关闭它打开的句柄。 |
| `READ_BYTES` | 成员**必须**在返回前关闭它打开的句柄;返回的是字节数组,不是句柄。 |
| `WRITE_BYTES` | 成员**必须**在返回前关闭目标文件的句柄;超限路径**必须**在**落盘之前**判出上限,目标文件**必须**保持原封不动(落盘会截断目标文件,判晚了就是把原文件清空)。 |

### 2.5 示例

```wlwl
IMPORT("wlwl:std.fs", ["PATH_JOIN", "PATH_DIR", "PATH_BASE", "PATH_EXT", "PATH_NORMALIZE"]);
PRINT(PATH_JOIN("a", "b", "c"));          // a/b/c
PRINT(PATH_DIR("a/b/c.txt"));             // a/b
PRINT(PATH_BASE("a/b/c.txt"));            // c.txt
PRINT(PATH_EXT("a/b/c.tar.gz"));          // gz
PRINT(PATH_NORMALIZE("a/./b/../c//d"));   // a/c/d
```

## 15 `std.time` —— 墙钟与单调钟

时间能力分四片推进:**A1 纯读** + **A2 阻塞睡眠** + **可挂起睡眠**(`SLEEP_ASYNC`,§15.5)、**B 假时钟气泡**。范围与裁决见 `ADR-0024`。**别把本章读成「时间能力齐了」**。

### 15.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `NOW() -> INTEGER` | **墙钟**:Unix 纪元起的**毫秒**。**可能因系统时间调整而向后跳**(NTP 校时 / 手动改表 / 夏令时),所以**不要**用它测时间差 | 元数错 `E0022`。**无其它失败** —— 读时钟不会失败 | — | R2 |
| `MONOTONIC() -> INTEGER` | **单调钟**:**进程启动起**的毫秒。单调不减,且**不受系统时间调整影响**。⚠️ **绝对值无意义、跨进程不可比 —— 只有差值有效** | 同上 | — | R2 |
| `SLEEP(ms) -> NULL` | **阻塞原语**:调用线程停住 `ms` 毫秒,期间**不调度任何其他任务**。`ms` **必须**是非负整数(`0` 合法 = 让出一次时间片)。⚠️ **气泡内它只拨钟不阻塞**(见 §15.6) | 元数错 `E0022`;非整数 `E0030`;`ms < 0` `E0030` | — | R2 |
| `TEST_BUBBLE(body) -> v` | 在**假时钟气泡**内跑 `body`:期间 `NOW` / `MONOTONIC` 走虚拟钟、`SLEEP` 只拨钟。body 的返回值原样传出。**气泡不再嵌套**;气泡内 `SPAWN` 的任务**归气泡且无法逃逸** | 元数错 `E0022`;非函数 `E0030`;已在气泡内 `E0030` | — | R2 |
| `ADVANCE(ms) -> NULL` | **仅气泡内**:把虚拟钟拨快 `ms` | 气泡外 `E0030`;元数错 `E0022`;非整数 / 负值 `E0030` | `O(1)` | R2 |
| `TIMEOUT(d, body)` -> `v` \| `ERR` | 跑 `body`,虚拟钟走过 `d` 毫秒仍未返回就**放弃**它,返回 `ERR([kind: "Timeout"])`。**只在气泡内可用** | 元数错 `E0022`;非函数 / 负预算 `E0030`;气泡外 `E0030` | — | R2 |
| `SLEEP_ASYNC(ms) -> NULL` | **可挂起**的睡眠:挂起当前任务并让出调度,到期醒来后继续;等待期间**其它任务可以运行**。⚠ **它不是 `SLEEP` 的另一种形态** —— `SLEEP` 仍是阻塞原语(§15.5)。⚠ 挂起点与重放语义按并发册 §17 的「宿主挂起」规定办理。⚠ **气泡内是例外**:它**等同 `SLEEP`**(拨快虚拟钟、立即返回、**不**挂起)—— 见 §15.6 | 元数错 `E0022`;非整数 `E0030`;`ms < 0` `E0030` | — | R2 |

**本章的共享失败口径**:元数 / 类型错是**程序员错误**,走原生诊断 `E0022` / `E0030`;读时钟**没有**运行期失败(读不到时钟就报错是荒谬的)。本章唯一的 `ERR` 值来自 `TIMEOUT`,载荷是 `[kind: "Timeout"]`。

除 `ADVANCE` 外,本章成员的耗时都由宿主的时钟与调度决定,规范**不**给上界(语言核心册 §18.5);`ADVANCE` 只动一个虚拟计数器,故是 `O(1)`。

**为什么是两个而不是一个**:「现在几点」要问 `NOW`,「过了多久」要问 `MONOTONIC`。后者用单调时钟(系统时间怎么改都动不了它);前者用墙钟才能给出绝对时刻。**两者单位相同(毫秒)但起点差着四十多年** —— 把它们混用是最容易犯的错,契约表有一条专门钉这件事。

### 15.2 三条口径

1. **单位是毫秒,不是秒。** 取秒会带来 ±1 s 的量化误差,直接污染「缓存 5 秒过期」这类真实语义。两个成员单位统一为 ms 也是刻意的:这样 `SLEEP(ms)` 与时钟差值能直接对齐,不必在每个调用点换算。
2. **本命名空间不做 ISO-8601 字符串。** 要写人类可读的时间戳是**格式化层**的事 —— `std.format` 归标准库·核心册 §4,本册**不**扩它的成员面。`NOW()` 给的是整数,不是字符串。
3. **不支持亚毫秒测量。** 记为**已知限制**,不是疏漏。

### 15.3 可复现性:使用 `NOW()` 会让程序不可复现

本语言的卖点是「同一输入 ⇒ 同一行为」。**用了 `NOW()` 的程序不再满足它** —— 而且是**静默地**不再满足(没有诊断、没有警告)。

⇒ **规范不检测这件事**(运行时检测不到「你有没有用它」),只在成员表上声明。**测试代码尤其要用 `MONOTONIC` 而不要用 `NOW`** —— 测试的可复现性比断言的直观更重要。假时钟气泡正是为了把这件事在**测试里**变回可复现(而生产代码里用真实时间是使用者的明确选择)。

### 15.4 层与来源

R2(触系统资源,本册 §0.7 机械规则第 1 条)。**成员在 `wlwl-std` 内直接读系统时钟,不经宿主** —— 与 `std.encode` 的 `RANDOM_BYTES` 直读 `getrandom` 同款理由:`std.time` 是**时间的源**。

⚠️ **绝不能给本命名空间的成员加「可注入时钟」形参。** 那等于让调用方能把它降级成可预测源 —— 与「给 CSPRNG 加后门」是同一条错误。虚拟时钟**只走宿主**(`StdHost` 加方法),且**必须**如此:全局可变状态会让测试之间互相污染、结果顺序相关(违反「无隐藏全局状态」纪律)。

### 15.5 `SLEEP` 是**阻塞原语** —— 这条代价写明

**`SLEEP` 期间不调度任何其他任务。** 顶层如此,**任务体内调用同样如此**。

这不是「实现图省事」,而是一条**语言级语义**,理由与代价都写在这里:

- **原本的设计是「任务内挂起、到点唤醒」。** 实现时撞上一个**运行时能力缺口**:wlwl 的「中途挂起后**原地续跑**」能力**只有 `YIELD()` 有** —— 它由分段 + 保存运行环境两件事共同实现,而**分段器只认 `YIELD()` 这一个名字**。任何**非分段**任务体一旦被挂起再唤醒,重入走整段重跑(绑定从头重来、副作用重放)。⇒ 挂起路线下,唤醒会**再次执行同一个 `SLEEP`**,**无限循环**(实测 8 秒 79 次仍不终止)。
- **因此改为阻塞。** 这条代价**早已被接受**:候选方案的原话就是「**`SLEEP` 期间不调度其他任务**」,当时选它就是为了它**可被文档化成一条确定性规则**。改为阻塞只是把它从「运行队列排空后才阻塞」提前到「调用点即刻阻塞」,**没有新增一类代价**,反而省掉了挂起 / 唤醒两套机制。
- **⚠️ 与阻塞式 IO 的冲突照旧**:本语言有阻塞式 IO(官方包 `ai` / `agent` 的 HTTP 后端),`SLEEP` 与它**不可同时依赖其及时性** —— 这是语言级取舍,不是实现细节。
- **契约表有一条专门的反向守卫**:任务体里 `SLEEP` 之后**必须**继续执行并交出结果。它红了的形式是**测试超时** —— 而超时恰恰就是「挂起路线被重新引入」的特征读数。

**`SLEEP_ASYNC` 是另一个成员,不是 `SLEEP` 的另一种形态。** 本节(以及上面四条理由)只约束 `SLEEP`;`SLEEP_ASYNC` 的等待是**可挂起**的:挂起当前任务、让出调度,到期醒来后继续,期间**其它任务可以运行**。⇒ 本节那句「`SLEEP` 期间不调度任何其他任务」**不**适用于 `SLEEP_ASYNC`。⚠ **气泡内是例外** —— 见 §15.6(气泡内它**等同 `SLEEP`**)。

⚠ **`SLEEP` 的阻塞语义一字未改** —— 它的代价、理由与上面四条全部照旧;`SLEEP_ASYNC` 是**新增**成员,不改 `SLEEP` 的任何可观察行为。

### 15.6 假时钟气泡:能给什么、给不了什么

`TEST_BUBBLE(body)` 内:虚拟单调钟**从 0 起算**,虚拟墙钟 = **写死的起点** `1_700_000_000_000`(2023-11-14T22:13:20Z)+ 已流逝毫秒。起点写死是「可复现」这条承诺的**全部** —— 起点一旦含真实时间,同一程序两次运行读到的 `NOW` 就不同,气泡的意义当场消失。⚠️ 气泡内的 `NOW()` **不是真实时刻**;要真实时刻用气泡外的 `NOW()`。

| 气泡**能给** | 气泡**给不了** |
|---|---|
| `SLEEP(3600000)` 墙钟耗时 **< 1 s** | 「虚拟时钟**只在全员阻塞时**推进」 |
| 同一程序跑两次,气泡内时间序列**逐字节相同** | 「A 睡 1 s,B 能看到 +500 时刻」 |
| 超时(`TIMEOUT`)是一个**确定性事件** | `SLEEP` 期间让别的任务插进来(任务间交错)—— **那个形态是 `SLEEP_ASYNC`**,不是 `SLEEP`(§15.5);⚠ **气泡内连它也给不了** —— 气泡内 `SLEEP_ASYNC` **等同 `SLEEP`**(见下面那条) |

**为什么给不了后两条**:那需要**挂起**睡着的任务、让别的任务跑完再推进时钟。本语言的中途续跑能力**只有 `YIELD()` 有**(分段器只认 `YIELD()` 这一个名字,非分段任务体被唤醒后**整段重跑**),而运行时是**单线程协作式**的(没有工作线程,调度是一个 run queue)⇒ 「`SLEEP` 真阻塞线程」也不可能:阻塞了就没有别的代码去推进虚拟时钟。⇒ 气泡内 `SLEEP` 只能「**立即推进虚拟时钟并返回**」,时钟在 `SLEEP` 的**调用点**就跳。

**要拿到那两条,必须先补「任意挂起原因的中断续跑」这一运行时能力** —— 那是独立立项,不是本成员的待办。

⚠ **本节各条针对的是 `SLEEP`**。`SLEEP_ASYNC`(§15.5)在**气泡内等同 `SLEEP`** —— 拨快虚拟钟、**立即返回**、**不**挂起。

**为什么不是「挂起点」**:气泡的虚拟钟**只在 `SLEEP` 时前进**(本节「给不了」那栏)⇒ 气泡内若真把 `SLEEP_ASYNC` 挂起,**没有任何代码会推进时钟** ⇒ 它**永远醒不来**(并发册 §17.0 的「恢复后**不得**再次挂起(否则任务原地活锁)」正好命中这个形态)⇒ **那不是一条能交付的行为**。⇒ 气泡内它**等同 `SLEEP`**。

⇒ **气泡内「`SLEEP` 期间让别的任务插进来」这个形态也给不了** —— 与本节「给不了」那栏的其它两条同源:要它,得先补「任意挂起原因的中断续跑」那一项运行时能力(见上面那段「要拿到那两条」)。**气泡外**才有这个形态(`SLEEP_ASYNC` 可挂起 ⇒ 别的任务照跑)。

⚠ [v1.0.2 订正 / 2026-10-25] 本条原文写「`SLEEP_ASYNC` 在气泡内是**挂起点**,醒来与否按并发册 §17 的规定办理」—— 该写法与本节「虚拟钟只在 `SLEEP` 时前进」**自相矛盾**(按字面实现 ⇒ 挂起者永醒不来)⇒ 属一致性册 §3.4 **例外 2(规范缺陷修复)**:修复方向是**消除两套语义**(取唯一能交付的那一种),**不**引入新的自由度。**受影响条款**:本节 + §15.1 的 `SLEEP_ASYNC` 行 + §15.5 末段;**迁移写法**:原先指望「气泡内 `SLEEP_ASYNC` 会挂起」的程序**要改** —— 它现在**立即返回**(且**不**让别的任务插进来);总纲 §0.9 的 **D-19** 登记了这一行。

**`TIMEOUT` 的中断粒度**:超时触发时,`SLEEP` 置「已放弃」标志并返回 `ERR`。实测粒度:**从最内层闭包返回**,且不逸出 `TEST_BUBBLE` / 顶层。⇒

- `SLEEP` **直写在** `TIMEOUT` 的 body 里 ⇒ body 被**完全放弃**;
- `SLEEP` 藏在 body 内**更深的函数调用**里 ⇒ 只中断到那一层,外层继续跑完。

⚠ 但 **`TIMEOUT` 的返回值永远正确**:它查那个标志,只要置过就返回 `ERR([kind: "Timeout"])`,哪怕 body 最终跑完了。⇒「超时了没有」这个问题永远有确定答案,「省了多少时间」取决于 `SLEEP` 位于多深的调用里。

**嵌套**:气泡**不再嵌套**(已在气泡内 → `E0030`),但 **`TIMEOUT` 可以嵌套**;此时取**最紧的未放弃** deadline(不是栈顶)。被放弃过的那一项会退出计算,否则它会永久触发后续每一次 `SLEEP`。

### 15.7 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `NOW` | 无外部资源(读时钟不持有句柄)。 |
| `MONOTONIC` | 同 `NOW`。 |
| `SLEEP` | 不持有资源;返回时**不得**留下未完成的等待(阻塞语义下不存在「挂起后唤醒」的待释放状态)。 |
| `SLEEP_ASYNC` | 不持有外部资源;挂起与唤醒由运行时负责(并发册 §17)—— 成员返回时**不得**留下一个无人认领的挂起。 |
| `TEST_BUBBLE` | 气泡内的虚拟时钟状态**必须**在 `TEST_BUBBLE` 返回时**全部销毁**;气泡内 `SPAWN` 的任务**归气泡且无法逃逸**,因此气泡**必须**在返回前终止它们(并发册 §17.1)—— 任务句柄由气泡负责关闭,**不得**逸出到调用方。 |
| `ADVANCE` | 无外部资源。 |
| `TIMEOUT` | 超时被触发时,被放弃的 body **不得**逸出 `TEST_BUBBLE` / 顶层(中断粒度见 §15.6);`TIMEOUT` 返回后,那个「已放弃」标志**必须**随本次超时一起失效,**不得**影响后续的 `SLEEP`。 |

### 15.8 示例

```wlwl
IMPORT("wlwl:std.time", ["NOW", "MONOTONIC", "SLEEP", "TEST_BUBBLE", "ADVANCE", "TIMEOUT"]);
PRINT(TEST_BUBBLE(FUN((), ADVANCE(1000))));   // NULL
PRINT(TEST_BUBBLE(FUN((), MONOTONIC())));      // 0
PRINT(IS_ERR(TEST_BUBBLE(FUN((), TIMEOUT(10, FUN((), SLEEP(100)))))));  // TRUE
```

**本节为非规范的追溯材料,不构成一致性要求。**

范围与裁决见 `ADR-0024` §6 与 `docs/history/addendum-01-std-time.md` §3.7;`SLEEP` 的阻塞代价来自「中途挂起后原地续跑」只有 `YIELD()` 一条路这个**运行时能力缺口**。

## 17 `std.rand` —— 显式播种的随机数

本语言**不**隐式提供随机数:随机数**必须**经**显式播种**取得。`SEED` 收**显式熵**、抽签成员返回**新状态**,这两条合起来是本章全部的形状。

⚠️ **过渡形态**:本命名空间仍放在 `wlwl:std.*` 里,而 `ai` / `agent` 降级为官方包、移出 `wlwl:std.*` 的方向已登记在标准库·官方包册。同一条逻辑适用于 `std.rand` —— ⚠ 但前提是「**原生包注册通道**」存在,而它当前不存在(⚠ 「官方包」这个**称谓**只指「原生静态链接的命名空间」;它**不**意味着已有独立的包分发机制)⇒ 现实选择只有「先放 std」。**该通道一旦存在,`std.rand` 按同一条方向降级。** 这一句**必须**留着:**不写它,现状就变成永久事实**。

### 17.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `SEED(entropy) -> DICT` | 从**显式熵**造一个 RNG 状态:`["s0": …, "s1": …, "s2": …, "s3": …]`。熵收 `STRING`(按 **UTF-8 字节**)或 `ARRAY`(字节数组,即 `RANDOM_BYTES(n)` 的返回) | 元数错 `E0022`;熵类型错 / 字节超 `0..=255` → `E0030` | `O(n)` | R2 |
| `UNIFORM(rng) -> [FLOAT, DICT]` | `[0, 1)` 上的均匀浮点 | 元数**必须是 1 或 3**(2 个实参是 `E0022`,**不是**「`a` 取默认」);`a >= b` 空区间 → `E0030` | `O(1)` | R2 |
| `UNIFORM(rng, a, b) -> [FLOAT, DICT]` | **`[a, b)`**(左闭右开)。端点收 `FLOAT` 或 `INTEGER`(内部提升) | 同上 | `O(1)` | R2 |
| `INT_RANGE(rng, lo, hi) -> [INTEGER, DICT]` | 整数区间 `[lo, hi)`,**无偏**。可跨负数 | 元数错 `E0022`;`lo >= hi` → `E0030` | `O(1)` 期望 | R2 |
| `CODEPOINT(rng) -> [STRING, DICT]` | 一个 Unicode **标量值**,返**恰好一个字符**的字符串。排除 UTF-16 代理区 `0xD800..=0xDFFF` 与**永久非字符**(`0xFDD0..=0xFDEF`、尾数位非零的 `U+xFFFE` / `U+xFFFF`) | 元数错 `E0022` | `O(1)` 期望 | R2 |

**成员数是承诺**:恰好 4 个 —— `SEED` / `UNIFORM` / `INT_RANGE` / `CODEPOINT`;表里 `UNIFORM` 的两行是**同一个成员**的两个元数形态。

**非目标(成员数守卫把这条钉住)**:**不提供** `NORMAL` / 泊松 / 指数等**分布族** —— 需要别的分布的调用方自己从均匀分布构造(极坐标法 / 逆变换法),那是调用方的算法选择,不是标准库该替他定的。**没有 `SET_SEED()`,没有「全局当前 RNG」,没有任何隐藏状态。** `INT_RANGE` 不是「一种分布」,它是均匀分布在整数域上的成员。

本节 `n` = 熵的字节数。**本章的共享失败口径**:元数 / 类型错与状态非法都是**程序员错误**,走原生诊断 `E0022` / `E0030`;本章**不**产生 `ERR` 值。`INT_RANGE` 与 `CODEPOINT` 的期望代价是 `O(1)`(语言核心册 §18.1),最坏情形无界,见 §17.5。

### 17.2 抽签成员返回 `[值, 新状态]`

**这一节是本成员最容易踩空的地方**,所以它写进规范而不只是 ADR。

**`DICT` 是不可变的**(语言核心册 §2.1),而 `SET_PROP` / `INDEX_SET` 对字典也是「返回**新**字典、**接收者不变**」。⇒ 若抽签成员只返回标量,**状态永不前进**:同一个 `rng` 值反复调用拿到的是**同一个数**(实测 2000 次全部相同)。

所以状态与值**一起**返回,用语言**已有**的数组模式绑定消费(示例见 §17.7)。

**收益是「忘了推进状态」不再是可能的惯用写法** —— 拿不到值,除非同时拿到新状态。契约表 `two_draws_advance_the_state` 是这条的守卫。

### 17.3 算法(第三方**必须**能复现冻结向量)

- **播种**:熵字节 → **FNV-1a-64** 折叠成一个 `u64` → **SplitMix64** 展开成 **256 bit 状态**(4 × `u64`)。⚠️ 展开后**四字全零**则按固定常数 `0x9E3779B97F4A7C15` 再展开一次 —— xoshiro 的**全零态是吸收态**(恒输出 0),不守卫就会**静默**退化成一条无意义序列,而冻结向量照样绿。读状态时**再挡一次**(调用方手写的状态字典同样要挡),报 `E0030`。
- **生成**:**xoshiro256++**。
- **浮点**:`UNIFORM` 取 `(next_u64() >> 11) as f64 * 2^-53`。右移 11 位拿到**恰好 53 bit** 尾数 ⇒ 结果**可被保证**落在 `[0, 1)`,而不是「恰好不会返 1.0」。`[a, b)` 的右端不包含也是**被保证**的:实现夹一次(当 `a` 远大于区间宽度时,`(b - a)` 的量级会低于半个 ulp,浮点舍入会把结果顶到 `b`)。
- **整数**:走**无偏取模拒绝**(截断点 `2^64 - (2^64 mod range)`,抽到以上就重抽),**绝不经过 `FLOAT`** —— 浮点只有 53 bit 尾数,中转会引入舍入偏差,且对大区间**静默收窄上界**(不报错、只给偏斜序列)。
- ⚠️ **状态字按 `i64` 位模式存放**:xoshiro 状态是 `u64`,而 wlwl 的 `INTEGER` 是 **`i64`** ⇒ 显示为**有符号数**(多数是负数),读回时按**位**重解释。逐字节往返无损,用户手写正数状态(`42` → `42`)同样合法。这是「不加内建类型」唯一的代价。

**冻结向量是本节的规范性要求**:同一熵的前若干个输出**逐字节**由契约表冻结,期望值取自**独立的第二实现**,**不是**从本实现导出。⇒ **第三方实现必须能复现同一组冻结向量** —— 算法换掉那条就红,**必须**同批更新向量并在 CHANGELOG 显式记录,**不能悄悄换**。

### 17.4 可复现性与熵源归属

- **熵源是操作系统,但依赖必须写在程序文本里**:`SEED` **内部不读 OS 熵源**。要真随机就去 `std.encode` 的 `RANDOM_BYTES` / `RANDOM_HEX` 取,显式传进来 —— `std.encode` 是源、`std.rand` 单向消费它。**对一个把可复现当卖点的语言,「依赖可见」本身就是功能。**
- **`std.rand` 不做密码学随机**:那是 `RANDOM_BYTES` 的活。两个命名空间、两套用途,**不合并**。口令 / 密钥材料一律走 `std.encode`。
- **换算法是 breaking**:见 §17.3。

### 17.5 已知限制

- **亚毫秒 / 非 64 位状态**:状态固定 4 × `u64`,不可配置。
- **`CODEPOINT` 返回 `STRING` 而不是码点数值**:语言层没有「码点 → 字符串」的成员,返回数值形态要用户自己处理,而调用方几乎总要用它拼字符串。
- **`SEED` 的熵用 FNV-1a-64 折叠变长熵**:熵**已经均匀**之后的一次归一化,不承担安全职责(真熵来自 OS)。它让「同一个熵」在 `STRING` 与 `ARRAY` 两种字面量下**各有一种确定解释**,而不是取决于偶然。
- **分布统计不在契约表里**:它们是多项分布,写进 `cargo test` 只会得到一条必然偶尔变红的假门禁;统计断言在 `wlwl-std` 单测里用 4σ 容差,「无偏」的**确定性**证明(`2^64 mod 7 = 2` ⇒ 最高两个 `u64` 必然被拒)也在那里。
- **拒绝采样没有最坏上界**:`INT_RANGE` 单次取样的重抽次数在数学上无界(最坏情形与 `2^64` 同阶);规范只承诺**期望**代价 `O(1)`(语言核心册 §18.1)。

### 17.6 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `SEED` | 不持有外部资源;返回的状态字典是**值**,不含任何需要关闭的句柄。 |
| `UNIFORM` / `INT_RANGE` / `CODEPOINT` | 同 `SEED`:**不**持有资源,返回的 `[值, 新状态]` 是纯值。抽签成员**不得**在内部保留任何「上一次的状态」—— 状态只经返回值传递(§17.2)。 |
| 状态字典 | 状态是**不可变**的值(语言核心册 §2.1),**没有**释放点:它的生存期由持有它的绑定决定(语言核心册 §19.1)。 |

### 17.7 示例

```wlwl
IMPORT("wlwl:std.rand", ["SEED", "INT_RANGE"]);
LET(r0, SEED("fixed-seed"));
LET([v1, r1], INT_RANGE(r0, 0, 100));
LET([v2, r2], INT_RANGE(r1, 0, 100));
PRINT(v1, v2);        // 15 99
```

**本节为非规范的追溯材料,不构成一致性要求。**

## 18 `std.env` —— 进程环境与命令行参数

### 18.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `ENV_GET(name, default?)` -> `STRING` \| `NULL` | 取环境变量。**不存在且无缺省 → `NULL`** | 元数 > 2 / 类型错 → `E0022` / `E0030` | `O(m)` | R2 |
| `ENV_SET(name, value) -> NULL` | **仅本进程可见,不写磁盘** | 同上 | `O(m)` | R2 |
| `ENV_KEYS() -> ARRAY[STRING]` | 全部键名,**排序后返回** | 元数 ≠ 0 → `E0022` | `O(k log k)` | R2 |
| `ARGS() -> ARRAY[STRING]` | 命令行参数,**含 `argv[0]`** | 元数 ≠ 0 → `E0022` | `O(n)` | R2 |
| `SCRIPT_PATH()` -> `STRING` \| `NULL` | **被运行脚本的路径**,且**必须是绝对路径**。⚠ **无入口脚本时返回 `NULL`** —— 不是诊断,也不是字面 `"<runtime>"`。相对路径的基准是**当前工作目录(CWD)** | 元数 ≠ 0 → `E0022` | `O(m)` | R2 |

**本章的共享失败口径**:元数 / 类型错是**程序员错误**,走原生诊断 `E0022` / `E0030`;「变量不存在」**不是**失败,而是 `NULL` 这个正常返回值 —— 本章**不**产生 `ERR` 值。

本节 `m` = 字符串长度,`k` = 键数,`n` = 参数个数。

### 18.2 值形状与边界

- **`ENV_KEYS()` 排序是规范性要求,不是实现偏好**:宿主环境表的迭代序**逐次可能不同**,而**可复现是本语言卖点第一条** ⇒ 不排序就等于把一个不稳定值暴露给调用方。契约表钉死「两次调用逐字节相同」。
- **「没设」与「设为空串」是两件事** ⇒ `ENV_GET` 缺省返 `NULL` 而不是 `""`;分不开就没法读 `.env` 覆盖后的真实状态。给了 `default` 时,变量不存在**必须**返 `default`(不是 `NULL`)。
- 🔴 **`ENV_SET` 的写入不会到达 `PROCESS_RUN` 的子进程**。本命名空间的环境是**启动时由宿主交给程序的那份快照**,而子进程继承的是**操作系统那份真环境**(§19.2 的「追加到继承来的环境」说的就是后者)。⇒ `ENV_SET("FOO", "bar")` 之后 `PROCESS_RUN([…, "printenv", "FOO"])` **读不到** `FOO`;要把值传下去只能走 `PROCESS_RUN` 的 `opts.env`。⚠ **这是「如实成文」而不是「实现继承」**:让子进程继承本节的环境是**行为变更** —— 既有程序的子进程环境会突然多出变量,且子进程的环境会变成「**此前 `ENV_SET` 了多少次**」的**隐式函数**;而本语言明写「**显式值传递、无隐藏状态**」,`opts.env` 正是那条**显式**通道。⇒ 是否改为继承,留作独立的产品裁决。缺陷 D13-067。
- `ARGS()` **含程序自身路径**(`argv[0]`),与 Go `os.Args` / Python `sys.argv` 同款;要「用户传进来的参数」就 `SLICE(ARGS(), 1)`。
- **`SCRIPT_PATH()` 给的是绝对路径**:相对路径的基准是**当前工作目录(CWD)** —— 与 §2.3 的文件操作**同一基准**(程序的 base dir 只管 `IMPORT` 的相对模块路径)。⇒ 同一份程序在不同 CWD 下拿到**不同的绝对路径**,它**不是**可复现值。
- ⚠ **无入口脚本时返回 `NULL`**:以标准输入 / 表达式求值这类**没有入口脚本**的方式运行时,「被运行的脚本」根本不存在 ⇒ 返回 `NULL`。⚠ **不是**诊断,也**不是**字面 `"<runtime>"` —— 后者是一个**看起来像路径**的字符串,调用方会拿它去开文件,失败时还分不清是「路径不存在」还是「本来就没有脚本」。
- 与 `std.time` 的立场差异(写明免得下一个人「顺手统一」):`std.time` **直读系统时钟**,因为本语言**就是**时间的源;而环境的源是**启动时由宿主交给程序的** —— 它已经是「传进来的值」,所以本命名空间只读宿主的一个字段,不碰 OS API。

### 18.3 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `ENV_GET` | 无外部资源;读的是宿主在启动时交给程序的那份快照,成员**不得**关闭或替换宿主的环境表。 |
| `ENV_SET` | 无需释放:写入的是**本进程内**的那份快照,既不写磁盘也不产生外部资源。快照随进程终止而消失,实现**不得**把它写回宿主环境或落盘。 |
| `ENV_KEYS` | 无外部资源;返回的是键名的**新数组**,调用方持有它不构成资源。 |
| `ARGS` | 无外部资源;参数列表由宿主在启动时交给程序,成员只读不接管,实现**不得**释放或改写它。 |
| `SCRIPT_PATH` | 无外部资源;返回的是**路径字符串**,不是可释放的句柄。 |

### 18.4 示例

```wlwl
IMPORT("wlwl:std.env", ["ENV_GET", "ENV_SET", "ENV_KEYS", "ARGS"]);
ENV_SET("WLWL_PROBE_KEY", "v1");
PRINT(ENV_GET("WLWL_PROBE_KEY"));     // v1
PRINT(ENV_GET("WLWL_PROBE_MISSING"));  // NULL
PRINT(>(LEN(ENV_KEYS()), 0));          // TRUE(键的个数随宿主环境而变)
PRINT(>=(LEN(ARGS()), 1));             // TRUE(含 argv[0])
```

### 18.5 设计依据

**本节为非规范的追溯材料,不构成一致性要求。**

本命名空间的形状来自 `ADDENDUM-06`(2026-10-08 裁决)。缺陷 D13-067(`ENV_SET` 不被子进程继承)。

**「`ENV_SET` 不继承」的论证**:不继承的理由是**隐式状态** —— 若子进程继承本节的环境,子进程的环境会变成「此前 `ENV_SET` 了多少次」的隐式函数,与本语言「显式值传递、无隐藏状态」的纪律冲突。此前把理由写成「与可复现冲突(语句执行顺序)」是不成立的:确定性程序的语句顺序固定,跨次运行仍然可复现。`opts.env` 是那条**显式**通道。

## 19 `std.process` —— 不经 shell 跑子进程

### 19.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `PROCESS_RUN(argv, opts?) -> DICT` | 返 `[code: INTEGER, stdout: STRING, stderr: STRING]`。🔴 **`stdout` / `stderr` 是 `from_utf8_lossy` 的结果 —— 非 UTF-8 字节被换成 `U+FFFD`,不可逆**。⚠ 这与本册的「不做有损替换」**冲突**:成员表把这两个键定为 `STRING`,改成 `ARRAY[INTEGER]` 并集属**破坏性变更**。**要拿无损字节就走文件**:`WRITE_BYTES` + `READ_BYTES`。**不经 shell** | 元数 / 类型错 → `E0022` / `E0030`;起不来 / 超时 → `ERR([kind: "ProcessError", op, reason])` | — | R2 |
| `PROCESS_ID() -> INTEGER` | 本进程 id | 元数 ≠ 0 → `E0022` | `O(1)` | R2 |

**本章的共享失败口径**:元数 / 类型错是**程序员错误**,走原生诊断;「子进程起不来」与「超时」是**运行期可预期的结果**,返 `ERR([kind: "ProcessError", op, reason])`。⚠ **非零退出码不是失败** —— 它就是 `code` 字段里的一个整数,成员**正常返回**。

`PROCESS_RUN` 的耗时由子进程决定,规范**不**给上界(语言核心册 §18.5);`PROCESS_ID` 只读一个整数,是 `O(1)`。

### 19.2 值形状与边界

`opts` 可含 `timeout`(毫秒)、`cwd`、`env`(**追加**到继承来的环境,同名键覆盖 —— 不是「替换整份环境」)。未知键(如 `shell`)→ `E0030`,**显式拒绝而不是忽略**:「忽略」与「禁止」在安全上是两件不同的事。

⚠️ **`argv` 必须且只接受 `ARRAY[STRING]`。规范显式禁止字符串形态。** 拼一个字符串再让系统解析就是**命令注入**(`; rm -rf /` 会真的被执行)⇒ 本规范**没有** `SYSTEM` / `exec("sh -c")` 这种形态。这条是本成员存在的**安全理由**,契约表有一条「元字符不被解释」的守卫钉它。

⚠️ **它是阻塞的(与 `std.time::SLEEP` 同源)。** 运行时是**单线程协作式**(eval 侧无 `thread::spawn`,调度是一个 run queue)⇒ `PROCESS_RUN` 等子进程期间**不调度任何其他任务**,等价于把整个作用域停住。这条**语言级事实必须成文**,因为调用方若在气泡 / `SCOPE` 里用它,会以为别的任务还能跑。`std.net` 的阻塞式 HTTP 是**同源隐忧**。

**没有 `PROCESS_EXIT_CODE` 成员**:它需要「上一条 `PROCESS_RUN` 的退出码」—— 那是**跨调用隐藏可变状态**,与本语言「显式值传递、无隐藏状态」的纪律冲突;而 `code` 字段**已经在返回值里**。

### 19.3 超时的两半

🔴 **`timeout` 的两半必须分开说**:

- **杀掉谁**:Windows 上杀**整棵后代树**(`taskkill /T /F`);**POSIX 上只发信号给直接子进程**,**后代不被杀**。本规范**不承诺**「杀掉整棵进程树」。
- **多久返回**:**有界** —— 杀掉子进程后**至多等一个宽限期**,读取线程仍未结束就**丢弃句柄**(分离线程)并返回 `ERR`。⚠ 这一半**两个平台都兑现**,而且**恰恰因为它不兑现,超时在 POSIX 上就等于「等到孙进程自己结束」**:孙进程握着管道写端 ⇒ 管道不 EOF。⚠ Windows 上这条曾被 `taskkill /T /F` **掩盖**,所以既有的两个超时契约在 Windows 上对该缺陷完全无感。缺陷 D13-061 / D13-037。

### 19.4 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `PROCESS_RUN` | 成员**必须**收割它启动的子进程(等待其退出并取走退出码);**必须**关闭 stdout / stderr 的管道两端;超时路径上**必须**丢弃读取线程的句柄(分离线程),**不得**让它阻塞返回。⇒ 成员**不得**在返回后留下未收割的子进程或未关闭的管道。 |
| `PROCESS_ID` | 无外部资源;返回的是本进程 id,不是可释放的句柄。 |

### 19.5 示例

```wlwl
IMPORT("wlwl:std.process", ["PROCESS_RUN", "PROCESS_ID"]);
PRINT(PROCESS_ID());   // 本进程 id(具体值随进程变化)
```

`argv` 的元素是**可执行文件路径**与**参数**,**不经 shell 解析** —— 因此可执行文件的路径是平台相关的,示例只给与平台无关的部分。

### 19.6 设计依据

**本节为非规范的追溯材料,不构成一致性要求。**

本命名空间的形状来自 `ADDENDUM-06`(2026-10-08 裁决);阻塞形态来自「单线程协作式调度」这一运行时事实。缺陷 D13-037(POSIX 超时不杀后代)、D13-061(timeout 两半)、D13-064(`stdout` / `stderr` 的有损替换)。

## 20 `std.compress` —— Zstandard 与 DEFLATE 家族

### 20.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `ZSTD_COMPRESS(data, level?) -> ARRAY[INTEGER]` | RFC 8878。`level` 缺省取库默认(3),范围 `-131072..=22`(负数 = 更快、压缩比更低) | 元数错 `E0022`;非字节数组 / `level` 越界 `E0030` | — | R2 |
| `ZSTD_DECOMPRESS(data) -> ARRAY[INTEGER]` | ⚠ 输出上限 `MAX_DECOMPRESSED` = **64 MiB** | 帧非法 / 截断 / **超上限** → `ERR` | `O(n)` | R2 |
| `ZLIB_COMPRESS(data, level?) -> ARRAY[INTEGER]` | RFC 1950(zlib 包装,Adler-32)。`level` 缺省库默认(6),范围 `0..=9` | 同上 | — | R2 |
| `ZLIB_DECOMPRESS(data) -> ARRAY[INTEGER]` | 校验和不符 → `ERR` | 同上 | `O(n)` | R2 |
| `GZIP_COMPRESS(data, level?) -> ARRAY[INTEGER]` | RFC 1952(CRC32)。`level` 同上 | 同上 | — | R2 |
| `GZIP_DECOMPRESS(data) -> ARRAY[INTEGER]` | CRC32 不符 → `ERR`。🔴 **多成员全解 + 流后尾随字节 `ERR`**(RFC 1952 §2.2) | 同上 | `O(n)` | R2 |
| `DEFLATE_RAW_COMPRESS(data, level?) -> ARRAY[INTEGER]` | RFC 1951 **裸流**(无容器、无校验和),给自定义容器用 | 同上 | — | R2 |
| `DEFLATE_RAW_DECOMPRESS(data) -> ARRAY[INTEGER]` | ⚠ **没有校验和 ⇒ 数据损坏不可检测**,截断输入可能解出一段前缀正确的垃圾而不报错 | 同上 | `O(n)` | R2 |

`data` 的形状是 **`ARRAY[INTEGER]`**(元素 `0..=255`)—— **继承 §2.2 的裁决,本节不重新裁决**。两份各定一次就是 std 里两种字节表示,那是最难还的债。

⚠ **`level` 越界是 `E0030`,绝不静默 clamp** —— clamp 会让「我传了 9」和「我传了 999」产出同一个结果,那是在骗调用方。

**本章的共享失败口径**:元数 / 类型错是**程序员错误**,走原生诊断 `E0022` / `E0030`;数据层面的失败(帧非法、截断、校验和不符、输出超上限)返 `ERR([kind: "CompressError", op, reason])`。本章**不**做有损替换。

本节 `n` = 解压输出的字节数。**压缩侧不约束耗时**:压缩输出的大小与耗时由所选算法与数据决定,规范**不**给上界(语言核心册 §18.5);**解压侧的 `O(n)` 只承诺输出数组的构造是线性的**。

**压缩不是加密**:压缩**不提供机密性**,任何拿到输入的人都能解开。调用方若把 gzip 当「藏起来」用,那是**安全缺陷**而不是用法。机密性走传输层加密。

### 20.2 解压输出上限是硬边界

压缩炸弹(几十字节压缩出几 GB)是**真实攻击面**:不设上限等于把调用方的内存交给攻击者。⇒ 解压成员输出超过 **`MAX_DECOMPRESSED` = 64 MiB** 时返回 `ERR([kind: "CompressError", op, reason])`,**不是** OOM、**不是** panic。

⚠ **它同时是一条已知限制**:本册明确**不做流式 API**,所以 > 64 MiB 的单个载荷**没有解压路径** —— 要处理它得先解压到文件,或等流式成员落地。

🔴 **闸封的是 `len` 不是 `capacity`**:读取缓冲的 `capacity` 与 `len` **必须**同阶(定步增长),否则合法载荷压在 64 MiB 上限时实测峰值约为文档上限的 **2×**。⚠⚠ **编号串号**:本条原先登记为 `D13-049`,而台账的 `D13-049` 是**炸弹护栏零执行覆盖**(另一条,已修 2026-10-15)⇒ 本条另编 **`D13-074`**。

### 20.3 确定性口径:往返与交叉核对,而**不是**冻结输出字节

**压缩输出的字节是实现定义的** —— 同一份输入,zlib / miniz_oxide / zlib-ng 的 DEFLATE 流**互不相同**(块划分、lazy matching、熵编码选择都是实现自由)。⇒ 规范与契约表**不**冻结本实现的输出字节:那样只会冻结某个后端的内部选择,且**没有任何独立实现能产出同样的字节**。

真正成立、且被契约表钉住的是三条:

1. **往返**:`COMPRESS` → `DECOMPRESS` 恒等于原输入(逐字节);
2. **独立向量交叉核对**:契约表用 **Python 标准库**(`gzip.compress(mtime=0)` / `zlib.compress`)产出的向量喂给我们的解码器 —— 证明解码器是**按 RFC 实现**的,而不是「只会解开自己写的东西」(后者是一种常见的自证循环缺陷:用本成员压再解,永远「通过」);
3. **确定性**:同 `(data, level)` 两次压缩产出**逐字节相同**。

### 20.4 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `ZSTD_COMPRESS` / `ZLIB_COMPRESS` / `GZIP_COMPRESS` / `DEFLATE_RAW_COMPRESS` | 纯内存计算,**不**打开任何文件或网络资源;返回的是字节数组,没有可释放的句柄。 |
| `ZSTD_DECOMPRESS` / `ZLIB_DECOMPRESS` / `GZIP_DECOMPRESS` / `DEFLATE_RAW_DECOMPRESS` | 同上。⚠ 解压缓冲**必须**在成员返回前交还(定步增长使 `capacity` 与 `len` 同阶),**不得**在超上限路径上**保留**已分配的大缓冲 —— 炸弹护栏的收益正在于此。 |

### 20.5 示例

```wlwl
IMPORT("wlwl:std.compress", ["ZSTD_COMPRESS", "ZSTD_DECOMPRESS", "ZLIB_COMPRESS", "ZLIB_DECOMPRESS", "GZIP_COMPRESS", "GZIP_DECOMPRESS", "DEFLATE_RAW_COMPRESS", "DEFLATE_RAW_DECOMPRESS"]);
LET(data, [104, 101, 108, 108, 111]);
PRINT(LEN(ZSTD_COMPRESS(data)));        // 14
PRINT(ZSTD_DECOMPRESS(ZSTD_COMPRESS(data)));  // [104, 101, 108, 108, 111]
PRINT(ZLIB_DECOMPRESS(ZLIB_COMPRESS(data)));  // [104, 101, 108, 108, 111]
PRINT(GZIP_DECOMPRESS(GZIP_COMPRESS(data)));  // [104, 101, 108, 108, 111]
PRINT(DEFLATE_RAW_DECOMPRESS(DEFLATE_RAW_COMPRESS(data)));  // [104, 101, 108, 108, 111]
```

**本节为非规范的追溯材料,不构成一致性要求。**

## 21 `std.net` —— 网络

**只支持明文 `http:`**,**不做 TLS** —— 调用方自备隧道 / 反代。**零新增第三方依赖**:分组件走 RFC 3986 通用语法,解析与引用求解全部手写。

本章有**两半**:§21.1–§21.4 的五个成员是**三个 HTTP 客户端**与**两个 URL 纯函数**;**传输层**(§21.6,`TCP_*` 族)是**服务端**那一半 —— 它**只搬字节**,不认识任何协议(§21.6)。⚠ 传输层同样**只做明文连接**,**不做 TLS**。

### 21.1 成员表

**URL 与 HTTP 客户端族**:

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `URL_PARSE(url) -> DICT` | 拆成 `{scheme, userinfo, host, port, path, query, fragment}`。**纯解析,不发请求** | 不满足 `URI-reference` 的 ABNF → `E0030` | `O(n)` | R2 |
| `URL_JOIN(base, rel) -> STRING` | 相对引用 → 绝对引用(RFC 3986 §5,**strict 模式**) | 同上 | `O(n + m)` | R2 |
| `HTTP_GET(url, headers?, timeout?) -> DICT` | `{status, headers, body}`。**明文 `http:` only**。🔴 **`body` 的形状随内容走**:合法 UTF-8 ⇒ `STRING`;否则 ⇒ `ARRAY[INTEGER]`(元素 `0..=255`,逐字节无损,继承 §2.2 的字节裁决)。⚠ 8 MiB 的非 UTF-8 体会展开成约 840 万元素(与 `READ_BYTES` 同族放大)。**大载荷的正解仍是让它待在文件里**。🔴 **响应的 body 按状态码定界**(§21.4)—— `204` / `304` / `HEAD` 的 body **恒空**且**忽略 `Content-Length`**;`1xx` 被**跳过**、继续读下一个响应 | 网络失败 → `ERR([kind: "HttpError", op, reason])` | — | R2 |
| `HTTP_POST(url, body, headers?, timeout?) -> DICT` | 同上(含「body 按状态码定界」那一条) | 同上 | — | R2 |
| `HTTP_REQUEST(method, url, body?, headers?, timeout?) -> DICT` | 其余动词的通用形态;`method` 为 `HEAD` 时响应 **body 恒空**且**忽略 `Content-Length`**(§21.4) | 同上 | — | R2 |

**传输层族**(契约见 §21.6):

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `TCP_LISTEN(host, port) -> INTEGER` | 绑定并监听,返回**监听句柄**。`port` = **0** ⇒ 由宿主分配临时端口(实际端口**只**能用 `TCP_LOCAL_ADDR` 读回) | 端口不在 `0..=65535` → `E0030`;绑定 / 解析失败 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 → `E0022` / `E0030` | — | R2 |
| `TCP_ACCEPT(listener, timeout_ms) -> INTEGER` | 接受一个连接,返回**连接句柄**。⚠ **超时 ⇒ `NULL`** —— 那是**正常值**,**不是** `ERR`(§21.6) | 句柄不存在 / 不是监听句柄 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 / 负超时 → `E0022` / `E0030` | — | R2 |
| `TCP_RECV(conn, max_bytes, timeout_ms) -> DICT` | 读至多 `max_bytes` 个字节,返回 `{bytes, text, eof}`。`bytes` 是 `ARRAY[INTEGER]`(逐字节无损);`text` 是同一批字节的 UTF-8 解读;`eof` = 对端已关闭。⚠ **超时 ⇒ 空字节且 `eof = FALSE`**(§21.6) | 句柄不存在 / 不是连接句柄 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 / 负值 → `E0022` / `E0030` | — | R2 |
| `TCP_SEND(conn, payload) -> INTEGER` | 写 `payload`,返回**写入的字节数**。`payload` 是 `STRING`(按 UTF-8 编码)或 `ARRAY[INTEGER]`(原样逐字节) | 句柄不存在 / 不是连接句柄 / 写失败 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 / 字节越界 → `E0022` / `E0030` | — | R2 |
| `TCP_PEER(conn) -> DICT` | 对端地址 `{host, port}` | 句柄不存在 / 不是连接句柄 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 → `E0022` / `E0030` | — | R2 |
| `TCP_LOCAL_ADDR(listener) -> DICT` | **本地绑定地址** `{host, port}` | 句柄不存在 / 不是监听句柄 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 → `E0022` / `E0030` | — | R2 |
| `TCP_SET_TIMEOUT(conn, ms) -> NULL` | 设该连接的**读超时**(`ms` 毫秒);`0` = 无限 | 句柄不存在 / 不是连接句柄 → `ERR([kind: "SocketError", op, reason])`;元数 / 类型错 / 负值 → `E0022` / `E0030` | — | R2 |
| `TCP_CLOSE(conn) -> NULL` | 关闭连接。**幂等**:重复关闭 / 关闭不存在的句柄**都**返回 `NULL`,**不**产生诊断(§21.6) | 元数 / 类型错 → `E0022` / `E0030` | — | R2 |
| `TCP_CLOSE_LISTENER(listener) -> NULL` | 关闭监听。**幂等**(同上) | 元数 / 类型错 → `E0022` / `E0030` | — | R2 |

**本章的共享失败口径**:URL 侧的失败是**程序员错误**(不满足 `URI-reference` 的 ABNF)→ 原生诊断 `E0030`;网络侧的失败(不通、超时、协议越界)是**运行期可预期的业务分支** → `ERR([kind: "HttpError", op, reason])`。**网络不通**做成原生诊断会让整个运行**终止**,调用方连重试都做不到。⚠ 传输层族是**同款口径**:`ERR([kind: "SocketError", op, reason])` **值** + `E0022` / `E0030` 诊断;⚠ 但「**暂时没有**」是**正常值**(超时 ⇒ `NULL` / 空字节),**不是** `ERR`(§21.6)。

本节 `n` = URL 的字符数,`m` = 求解结果的长度。`HTTP_*` 的耗时由网络决定,规范**不**给上界(语言核心册 §18.5);传输层成员的耗时同样由网络决定,**不**给上界。

**`URL_PARSE` 的返回值**:

- **七个键恒定存在**。某组件**未出现**时取值为 `NULL`,**出现但为空**时取值为 `""` —— 这个区别是 RFC 3986 §5.3 末段的**规范性**要求:分隔符没出现是 undefined,分隔符出现但后面立刻是下一个分隔符或结尾是 empty。混同两者就分不开 `query` 与 `path`,`remove_dot_segments` 会去动 `query` 里的 `/./`(RFC §5.2.4 末段的 Note 明写这个坑)。
- `port` 是 **INTEGER**(便于直接比较),`NULL` 表示未指定或为空端口。
- `host` 对 IPv6 literal **保留方括号**(`"[::1]"`),好让调用方能无损拼回。

⚠ **`userinfo` 必须单独拆出,不得丢弃。** RFC 3986 §7.6 用 `ftp://cnn.example.com&story=breaking_news@10.0.0.1/` 证明:丢掉这一段会让人以为 host 是 `cnn.example.com`,而它实际是 `10.0.0.1`。解析器替调用方吃掉 userinfo,等于**藏起一个已知的语义攻击面**。

### 21.2 「非法 URL」的边界

RFC 3986 的解析是**宽容**的 —— 绝大多数字符串都能解析成某种引用。所以「非法 → `E0030`」**必须**有能写进契约表的边界。判据是 **不满足 `URI-reference` 的 ABNF(RFC 3986 Appendix A)即非法**:

| 情形 | 结果 |
|---|---|
| 任何 ASCII 控制字符或空格 | `E0030` |
| `:` 出现在首个 `/?#` 之前,但其前缀不是合法 `scheme` | `E0030` |
| 裸 `%`(后面不是两个十六进制数字) | `E0030` |
| 组件里有超出该组件字符集的字符 | `E0030` |
| `[` / `]` 不成对,或出现在 authority 之外 | `E0030` |
| `port` 非 `*DIGIT`,或数值 > 65535 | `E0030` |
| **空 host**(如 `http://`) | **接受** |
| **无 scheme**(如 `//g`、`a/b`) | **接受** |

最后两行是**刻意宽松**的:判成非法会让 `URL_JOIN` 无法处理 RFC §5.4 里 `//g`、`""` 这类正常输入。

**明确不校验 IPv6 地址的完整文法** —— RFC 3986 §3.2.2 自己说 IPv6 文法「很难指定」并把它委派给 RFC 3513。本实现只做保守检查(方括号内非空且字符集合理),不解析成二进制地址。**这是已知限制,不是遗漏。**

### 21.3 `URL_JOIN` 的 strict 模式

RFC 3986 §5.4.2 的 `http:g` 一行给了**两个**结果:strict 解析器得 `http:g`,向后兼容的解析器得 `http://a/b/c/g`。本实现取 **strict** —— RFC 自己把前者排在前面。⚠ **WHATWG URL 取的是另一个**,两者**不等价**,跨规范对照时不要互相套用。

`URL_JOIN` **不做**百分号解码、host 小写化、scheme 规范化 —— 那些是 RFC §6.2 的**语法 / scheme 规范化**,是**另一个语义**,不在本成员内。

### 21.4 `HTTP_*` 的形态

- **只支持明文 `http:`**,**不做 TLS**。`https://` 返回 `ERR`,不做「简易封装」。
- **超时必填且有保守默认**:缺省 **30 000 ms**,调用方可覆盖。⚠ 这条**不是建议而是契约** —— 阻塞时长由墙钟决定(不像 `SLEEP` 有虚拟时钟可测),忘写就是永久挂住整个程序。
- 🔴 **`timeout` 是「整条请求」的预算上限,不是每次 I/O 的时限**。拨号、重定向轮次、每一次 `read` 都从**同一份剩余预算**里扣,不再各拿一份完整的 `dur` —— 否则「多地址连接 + 慢速滴流响应」**可以**把总耗时放大成 `N × dur + Σ 每次读`。⚠ **DNS 解析不在闸内,且这是已知缺口不是疏忽**:域名解析是**不可中断**的阻塞系统调用(标准库无取消手段;另起线程解决不了「线程仍会挂住」,还会泄漏线程)。⇒ 闸**从 DNS 返回之后**才开始计;若 DNS 真的挂住,本函数仍会挂住。要真正覆盖只能换可取消的解析器,**那会引入第三方依赖**,与「零新增依赖」冲突 —— **需要一次独立裁决**。⚠ 实现在预算耗尽时**返回超时错误而不是把 socket 超时设成 0** —— 零值会让系统调用报 `EINVAL`,而调用点的 `LET(_, …)` 会把失败静默吞掉,「超时」就退化成「无超时」。
- **不自动跟随重定向**。3xx 原样返回,`Location` 在 `headers` 里,由调用方决定。自动跟随可能把请求带到非预期 host(SSRF 面)。
- **不支持的写法一律 `ERR`,绝不「尽力解析」**。请求走私 / 响应拆分的根因都是「宽容地解析有歧义的框架」:

| 情形 | 结果 |
|---|---|
| `Transfer-Encoding`(**含 `chunked`**) | `ERR` —— **不解码**,这是走私向量 |
| HTTP/1.1 既无 `Content-Length` 又无 `Connection: close` | `ERR`(不猜 body 长度)。**HTTP/1.0 不适用此条** —— 见下。**`204` / `304` / `HEAD` 除外** —— 它们的 body 恒空,见下条 |
| 重复的 `Content-Length`(即便值相同) | `ERR` |
| 响应头块 > **64 KiB** | `ERR`(**不是**无界分配) |
| 响应体 > **8 MiB** | `ERR`(**不是** OOM) |
| obs-fold(头行以空白开头) | `ERR`,**不合并** |
| 头值含裸 CR / LF | `ERR` |

- 🔴 **HTTP/1.0 的 close 定界是例外**。RFC 9112 §6.3 第 8 条其实**不分版本**,本规范**刻意只给 HTTP/1.0 开口子**:HTTP/1.0 没有别的定界手段,在那里拒绝等于零安全收益;而 **HTTP/1.1 无长度无 close 是真正的歧义**(请求走私向量),收紧是刻意的。⇒ 契约里 `/nolength`(1.1)与 `/close10`(1.0)**只差版本号**,这一条边界被配对夹具直接钉住。缺陷 D13-041。
- 🔴 **状态码定界的三条规则(规范性)** —— 按 RFC 9112 §6.3 第 1 条,响应**按状态码**定界,不是按 `Content-Length` 猜:

  - **`1xx` 是中间响应,不是终响应** ⇒ **跳过它,继续读下一个响应**。⚠ **不得**把 `100` / `103` 当终响应 —— 那会让 `103 Early Hints` 这类服务器把**中间响应**交回调用方。⚠ 跳过的 `1xx` 响应**必须**有**条数上限**,否则一个只会发 `100` 的服务端能把客户端变成永动机。
  - **`204` / `304` 是终响应,body 恒空** ⇒ **忽略 `Content-Length`**(哪怕头里写了非零值)。⇒ HTTP/1.1 的 `204` **不带 `Content-Length` 也不 `ERR`**。
  - **`HEAD` 请求的响应 body 恒空** ⇒ **忽略 `Content-Length`**。⚠ `HEAD` 与 `GET` 的响应头语义不同:头里的 `Content-Length` 描述的是「`GET` 会返回的实体有多长」,把它当本次 body 长度去读,就会读到**下一个响应**或一直挂住。

- ⚠ **这三条改变可观察行为**:`204` / `304` / `HEAD` 原先因「无 `Content-Length` 且无 `Connection: close`」而 `ERR` 的响应,现在**可读且 body 为空** ⇒ 属 **breaking**,CHANGELOG 已按 ADR-0023 申报。缺陷 `D13-050`。
- **失败是 `ERR` 值不是原生诊断**:网络不通是**运行期可预期的业务分支**(会重试、会降级、会记日志),做成原生诊断会让整个运行**终止**,调用方连重试都做不到。载荷是 `{kind: "HttpError", op, reason}`,与 `std.encode` 的 `DecodeError` 同款(把「参数错」与「网络不通」分成两种 kind,调用方才分得清)。
- **元数错 `E0022` / 实参类型错 `E0030`** —— 那两条是**程序员错误**,走原生诊断。头字段名不是合法 token、或头值含 CR/LF,也是 `E0030`(后者是头注入)。
- ⚠ **`HTTP_*` 是阻塞原语**:执行期间**不调度任何其他任务**,整个 `SCOPE` 冻结。**不要在同一个 `SCOPE` 里并发发多个 HTTP 请求** —— `SPAWN` 了也还是排队,那是**错的写法**不是低效的写法。
- ⚠ **阻塞形态是带条件冻结的**:冻结前提是「真 state-machine 续跑仍未落地」。前提一旦不成立,阻塞的代价就没有必要再承担,**必须重新裁决**(以及随它而来的 30 s 超时兜底)。守卫测试会在前提不成立时转红。

**明确不做**:TLS / WebSocket / SSE / gRPC / 连接池 / 重试策略 / 自动重定向 / 代理 / cookie jar / 流式响应体。

### 21.5 资源释放责任

语言核心册 §19.4 把文件 / 进程 / 网络的释放责任交给**各成员自己**规定;本章的规定如下。

| 成员 | 释放责任 |
|---|---|
| `URL_PARSE` | 纯计算,**不**打开任何连接;返回的是字典,不含任何需要关闭的句柄。 |
| `URL_JOIN` | 同 `URL_PARSE`。 |
| `HTTP_GET` / `HTTP_POST` / `HTTP_REQUEST` | 成员**必须**在返回前关闭它打开的 TCP 连接与读写缓冲;失败路径(超时、协议越界、`ERR`)**必须**同样关闭,**不得**留下半开的连接。⇒ 一次调用**不得**留下任何未关闭的 socket。 |
| `TCP_LISTEN` | 监听 socket 的释放责任**移交**给调用方:成员**必须**把监听句柄交出去(调用方**必须**在不再需要时调用 `TCP_CLOSE_LISTENER`);成员**不得**在返回前把它关掉。 |
| `TCP_ACCEPT` | 接受的连接**必须**在返回前完成移交(连接句柄交到调用方手里);失败路径**必须**关掉刚接到、尚未移交的 socket,**不得**泄漏。 |
| `TCP_RECV` | 不新开资源:读的是连接已有的缓冲。 |
| `TCP_SEND` | 不新开资源:写的是连接已有的流。 |
| `TCP_PEER` / `TCP_LOCAL_ADDR` | 无外部资源;返回的是地址**值**,不是可释放的句柄。 |
| `TCP_SET_TIMEOUT` | 无外部资源。 |
| `TCP_CLOSE` | 成员**必须**在返回前关闭该连接的 socket 与缓冲;重复关闭**不得**报错(幂等,§21.6)。 |
| `TCP_CLOSE_LISTENER` | 同 `TCP_CLOSE`,对象是监听 socket;重复关闭**不得**报错(幂等,§21.6)。 |

### 21.6 传输层(`TCP_*` 族)

传输层是本章的**服务端**那一半:§21.1–§21.4 的五个成员是**三个 HTTP 客户端**与**两个 URL 纯函数**,**没有任何成员能建立或接受连接** ⇒ 「用 WLWL 写一个网络服务器」在语言层面无路可走。本节规定服务端的**最小族**:监听 / 接受 / 收 / 发 / 对端地址 / 超时 / 关闭。

#### 21.6.1 句柄与字节的形状

- **句柄是不透明 `INTEGER`**。调用方**不得**解析它、**不得**假定它的取值范围或连续性、**不得**拿它做算术或比较;它**只**在同一次运行内有效。⚠ 本语言没有不透明类型(语言核心册 §2.1)⇒ 句柄与普通整数的区分靠**约定**,不靠类型 —— 这是本节的形状,不是实现细节。
- **字节是 `ARRAY[INTEGER]`(元素 `0..=255)`** —— 与 §2.2 的 `READ_BYTES` / `WRITE_BYTES` **同一形状**(标准库·安全册 §11.3 的字节条款同源)。⚠ 本册**不**引入第二种字节表示。
- ⚠ **`TCP_RECV` 的 `text` 不是无损的那一份**:`bytes` 才是逐字节无损的;`text` 是同一批字节按 UTF-8 的**解读**,字节**不是**合法 UTF-8 时它**不是**忠实还原(§2.2 的「不做有损替换」纪律在这里的落法是:**要字节就取 `bytes`**)。

#### 21.6.2 「暂时没有」是正常值,不是错误

| 情形 | 返回 |
|---|---|
| `TCP_ACCEPT` 在超时内**没有**待接的连接 | `NULL` |
| `TCP_RECV` 在超时内**没有**可读的字节 | `{bytes: [], text: "", eof: FALSE}` |

⚠ **这两条是正常结果,不是 `ERR`** —— 做成 `ERR` 会让轮询式服务器**每轮都走错误分支**,「正常结果」与「错误」就分不开了。⇒ 调用方**可以**直接拿返回值继续分支,**不**必先判 `IS_ERR`。

⚠ `eof = FALSE` 与 `eof = TRUE` 是两件事:前者是「**暂时**没有」(超时),后者是「对端已关闭,再读也是空」。⇒ 超时**不得**被当成 EOF —— 那会让服务器在对端还活着的时候关掉连接。

#### 21.6.3 失败语义的分界

| 类别 | 形态 |
|---|---|
| **运行期失败**(绑定失败 / 写失败 / 句柄不存在 / 句柄种类不对) | **`ERR` 值**,载荷是 `ERR([kind: "SocketError", op: <成员名>, reason: <原因>])` |
| **程序员错误**(元数错 / 实参类型错 / 端口越界 / 负超时 / 字节越界) | 原生诊断 `E0022` / `E0030`(语言核心册 §11.2) |

⚠ **网络不通是可预期的业务分支**(会重试、会降级、会记日志)⇒ 做成原生诊断会让整个运行**终止**,调用方连重试都做不到 —— 与 §21.4 的 `HTTP_*` 同款口径。

⚠ **句柄不存在**是**运行期失败**,**不是**程序员错误:句柄是运行期才产生的值,调用方拿着一个过期的句柄去调,是业务问题不是写法问题 ⇒ 它**必须**是 `ERR` 值,**不得**是诊断。

#### 21.6.4 等待必带超时,且等待期间**挂起当前任务**

- 每个等待(`TCP_ACCEPT` / `TCP_RECV`)**必须**带超时 —— `timeout_ms` 是**那一次等待的截止时间**;`0` = **无截止时间**(挂起直到条件满足)。⚠ **无截止时间时挂起的只是该任务**(见下条)—— **不是**挂住整个程序;但一个永不返回的服务端循环会把自己的任务永久停在挂起点 ⇒ 仍**应当**给一个正超时。
- ⚠ **等待期间挂起当前任务**(宿主挂起)—— 并发册 §17.0 的挂起点表**点名**「原生成员等待 socket / 定时器」正是这一类 ⇒ **别的任务照常运行**。⇒ **可以在同一个 `SCOPE` 里并发发多个连接**:`SPAWN` 出去的那些各自停在**自己的**挂起点上,谁先就绪谁先醒。⚠ **与 §21.4 的 `HTTP_*` 不同款**:HTTP 走的是阻塞式 IO(同源事实见 §19 的 `PROCESS_RUN` 那条),传输层走的是**宿主挂起**。
  - **挂起点的位置**按并发册 §17.0 办:恢复**从当前段首重跑**(不切段格),挂起点之前的代码**重放**;⚠ **循环体内的等待必须是循环体的第一条语句**(否则循环体前半重复、后半延后一轮)。
  - **恢复后不得再次挂起**:等待条件既已满足,它**必须**立即完成(否则任务原地活锁)。
- ⚠ `TCP_SET_TIMEOUT` 设的是**该连接上的读超时**(`0` = 无限);它**不**取消调用点的等待预算 —— `TCP_RECV` 的 `timeout_ms` 仍然限定那一次等待。⇒ **两个预算都生效**:该次读以「连接读超时」与「调用点 `timeout_ms`」中**先到者**为准(调用点为 `0` 时只看连接读超时;连接读超时为 `0` 时只看调用点)。

#### 21.6.5 协议隔离

- 原生层**只搬字节**。它**不认识** HTTP、**不认识**状态码、**不认识**头名 —— 不解析、不生成、不缓存任何协议语义。⇒ HTTP 的解析与响应构造是**调用方**(WLWL 侧)的事。
- ⚠ 这条是**规范性**的:传输层**不得**随协议演进而改写,也**不得**把某个协议的知识渗进原生层 —— 否则它就不可能被别的项目复用。

#### 21.6.6 关闭是幂等的

- `TCP_CLOSE` / `TCP_CLOSE_LISTENER` 对同一个句柄**重复调用必须**返回 `NULL` 且**不**产生诊断;关闭一个**从未存在**或**已经关闭**的句柄也**必须**返回 `NULL`(**不是** `ERR`)。⇒ 调用方**不必**自己记「关过没有」。
- ⚠ 两类句柄**各自独立**:关闭连接**不**关闭监听,关闭监听**不**关闭已接受的连接。

### 21.7 示例

```wlwl
IMPORT("wlwl:std.net", ["URL_PARSE", "URL_JOIN"]);
PRINT(URL_PARSE("http://u:p@example.com:8080/a/b?q=1#f"));  // [scheme: http, userinfo: u:p, host: example.com, port: 8080, path: /a/b, query: q=1, fragment: f]
PRINT(URL_JOIN("http://example.com/a/b", "../c"));           // http://example.com/c
```

⚠ 传输层族**没有**可运行示例:参考实现 v0.11.4 **不含**这九个成员(导入即报 `E0023`)⇒ 它们的可运行示例等实现侧 v0.12.0 落地后再补。

### 21.8 设计依据

**本节为非规范的追溯材料,不构成一致性要求。**

本命名空间的形状见 `ADR-0028`(**Accepted**)。零新增第三方依赖:明文 HTTP/1.1 走 `std::net::TcpStream` + 系统解析器。缺陷 D13-040(`timeout` 预算)、D13-041(HTTP/1.0 的 close 定界)、D13-043(`body` 形状随内容走)。

传输层(v1.0.2 新增)沿用 `ADR-0028` 的同一批外部依赖(系统 socket),同样**零新增第三方依赖**。落点是**扩 `std.net`** 而**不**另立命名空间:代价是 `std.net` 一个命名空间同时装「协议」与「字节」两件事,收益是附录 A 只**多一行成员**而不是多一整行命名空间。⚠ 「原生层只搬字节」这条有专门的机械守卫守着(协议词一旦出现在原生层就判红)。
