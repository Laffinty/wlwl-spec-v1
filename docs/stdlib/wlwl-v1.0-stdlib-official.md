## 0 导言与总则

### 0.1 本册的构成

本册定义 WLWL 标准库的**官方包**部分:`ai`(§9,AI 推理)、`agent`(§10,代理)。每章对应一个命名空间,每章含成员表(签名 / 语义 / 失败 / 复杂度 / 层)、共享失败口径、值形状与边界、示例与该章特有条款;附录 A 是**规范性**的成员注册镜像,由[标准库·注册镜像册](wlwl-v1.0-stdlib-registry.md)承载。

**成员数以附录 A 镜像为准**:本册各章的成员表与附录 A **逐项对拍**,两者**必须**集合相等。

全局内建(`PRINT` / `LEN` / `FORMAT` 等)**不在**本册重复定义,见语言核心册 §10.2–§10.5、§10.7、§10.9、§10.12 与其附录 G。

### 0.2 读者

本册面向三类读者:使用标准库的 WLWL 程序员、标准库实现者,以及需要判断某个成员行为是否合规的工具作者。

### 0.3 规范性用语

本册中的关键词 **必须**(MUST)、**不得**(MUST NOT)、**应当**(SHOULD)、**可以**(MAY)按以下含义使用:

- **必须 / 不得**:实现的硬性约束。违反时实现必须产生一个诊断(语言核心册 §11)并按 §11.4 终止或报告。
- **应当**:强烈推荐的行为;实现可以偏离,但偏离必须在本册或实现文档中说明。
- **可以**:真正的实现自由度。

标注为**非规范**(non-normative)的段落、注释与附录不构成一致性要求。

### 0.4 一致性

一个 WLWL 程序是符合本规范的,当且仅当它只使用本册定义的成员面,并按各章的语义与失败口径使用它们。一个实现是一致的,当且仅当它提供本册各章列出的全部成员,对每个成员给出规定的签名、语义、失败行为与边界,且不依赖任何标注为未定义、保留或实现定义的行为。

### 0.5 记法

成员表统一为**五**列:

| 列 | 含义 |
|---|---|
| 签名 | 成员名与形参;`?` 表示可选形参;`...` 表示变参 |
| 语义 | 正常路径的可观察行为 |
| 失败 | 失败时的可观察行为;`—` 表示**不因输入内容失败**。实参层诊断(元数错 `E0022`、类型错 `E0030`)适用于**全部**成员,由语言核心册 §8 与 §11.2 统一规定;各章**可以**重复列出以便查阅 |
| 复杂度 | 时间代价上界,记法见语言核心册 §18;`—` 表示规范不约束 |
| 层 | 实现分层(§0.7);R0 内建层 / R1 语言层 / R2 原生层 |

正文中的 `code` 样式表示词法记号、字面代码或诊断码。示例代码以 `//` 注释标出其求值结果。值形状用 `json` 标记的代码块给出。

**标点约定**:逗号 `,`、冒号 `:`、分号 `;`、圆括号 `()`、方括号 `[]` 一律用**半角**;句号 `。`、顿号 `、`、引号 `「」`、破折号 `——` 用**全角**。

**围栏约定**:文法块用**无标记**围栏;示例代码块用 **`wlwl`** 标记的围栏,且**必须**能在参考实现上运行且退出码为 0。

**失败示例的记法**:预期产生诊断的片段**不**写成 `wlwl` 围栏 —— 它们以非零退出码终止,不是可运行示例。本册用表格列出失败形态与预期诊断码。

**引用**:同册内写 `(§5.2)`;跨册写册名加节号,例:"语言核心册 §8.2"、"并发册 §17.3"、"一致性册 §3"。

**规范性标注**:本册**全部**为**规范性**;各章的「设计依据」小节是**非规范性**的追溯材料,不构成要求。

### 0.6 调用面

标准库的调用面只有两种形式,与实现层无关:

- **全局内建**(R0 内建层):无须导入;契约见语言核心册 §10.2–§10.5、§10.7、§10.9、§10.12 与其附录 G。本册不重复、不镜像全局内建。
- **命名空间成员**:`IMPORT("wlwl:std.X", [names])` 导入后调用;成员契约见本册各章。官方包 `ai` / `agent` 的导入路径分别是 `ai:ask` 与 `agent:task`。

**本语言没有「命名空间限定调用」表达式**:文法里没有 `ns.MEMBER(...)` 这种形式,冒号只出现在 `IMPORT` 的路径字符串与改名处。成员只能经 `IMPORT` 取裸名;需要避开与类型名同名时,在 `IMPORT` 时改名。

### 0.7 实现分层

| 层 | 实现语言 | 内容 |
|---|---|---|
| R0 内建层 | 纯 Rust(编译器/运行时内部) | 语言自身无法表达或与编译器强耦合的原语;即语言核心册附录 G 全部条目 |
| R1 语言层 | 纯 wlwl(`.wll` 源码,`include_str!` 嵌入二进制) | 不触系统调用且非性能敏感的库;**非敏感库的默认归宿** |
| R2 原生层 | 纯 Rust(`wlwl-std`) | 触系统调用、性能敏感、或需复用成熟 Rust crate 的库 |

**归属判定**(机械执行):

1. 触系统调用 / OS 资源 / 进程·网络·时间·随机 → R2;
2. 语言核心语义 → R0;
3. 其余 → R1;仅当基准数据证明热点且解释器短期无优化空间时下沉 R2;
4. R2 成员**必须**有不依赖实现细节的语义描述,保证可被 R1 等价替换。

**层间规则**:R1 **可以**调用 R0 与 R2;R2 **不得**调用 R1(确需时走白名单并登记偏差)。混合模块以门面(R1 侧)为对外契约层。层归属变更(下沉/上浮)**不算**破坏性变更,但**必须**附基准数据并登记。

**R0 / R1 / R2 是实现分层,不是规范层级。** 成员的规范强度与它落在哪一层**无关** —— 一个 R1 成员与一个 R2 成员承担同样的规范性义务(总纲 §0.6 规则 1)。

### 0.8 与语言规范的依赖与差异登记

本册以语言核心册 的值域、错误模型、模块机制、诊断码表、并发语义、复杂度保证与内存模型为前提,不重复定义。两册冲突时**以语言核心册为准**。

本册**唯一**的跨册差异登记是:`ERR` 的产生与消费规则。语言核心册 §8.6 规定"未消费的 `ERR` **不得**被丢弃",本册各章的「失败」列**只**描述成员自身在失败时**返回什么**,**不**复述 §8.6 —— `ERR` 值的丢弃与报告一律由 §8.6 承担。

## 9 `ai` —— AI 推理(官方包)

`ai` 是**官方包**:以原生(R2)形态静态编入 `wlwl` 二进制的命名空间,提供单次推理、嵌入、代码补全与批量推理共五个成员。

**「官方包」与 `wlwl:std.*` 的区别在前缀与命名空间归属,不在机制**:两者的调用方式相同(经 `IMPORT` 取裸名),层归属各按本册 §0.7 判定。`ai` **不是** `wlwl:std.*` 命名空间:

- 导入路径**必须**写 `"ai:ask"`。`IMPORT("wlwl:std.ai", [...])` **不再解析**,报 `E0040` —— 不是空壳,空壳会让「搬没搬」看不出来。
- `IMPORT("wlwl:ai", [...])` 同样不解析:`wlwl:` 是标准库的**保留前缀**,解析器对以 `wlwl:` 开头的路径直接返回 `None`,该路径落进「裸模块名」分支、被当成文件名查找,最终报 `E0040`。可用前缀**只有** `ai:` 与 `agent:` 两种形态。
- 成员只能经 `IMPORT` 取**裸名**。本语言**没有**「命名空间限定调用」表达式,`ai:ask.ASK(…)` 与 `ai.ASK(…)` 一律是解析错误(`E0011`)(语言核心册 §10.11)。

### 9.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `ASK(model, prompt, opts?) -> STRING` | 单次推理;`model` 与 `prompt` **必须**是 `STRING`;`opts` **必须**是 `DICT` 或 `NULL` | 元数错 → `E0022`;类型错 → `E0030`;推理侧失败 → `E0080`–`E0083` | — | R2 |
| `EMBED(text, model?) -> ARRAY` | 嵌入向量;`model` 缺省取环境变量 `WLWL_AI_DEFAULT_MODEL` | 元数错 → `E0022`;类型错 → `E0030`;推理侧失败 → `E0080` | — | R2 |
| `COMPLETE(context, language?, opts?) -> STRING` | 代码补全;`language` 缺省取环境变量 `WLWL_AI_DEFAULT_MODEL` | 元数错 → `E0022`;类型错 → `E0030`;推理侧失败 → `E0080` | — | R2 |
| `ASK_STREAM(model, prompt, callback, opts?) -> STRING` | 流式推理;`callback` 当前**必须**是 `NULL`;实现侧当前**整收集为单块**,返回整段文本 | 元数错 → `E0022`;类型错 → `E0030`;推理侧失败 → `E0080` | — | R2 |
| `ASK_ALL(prompts, opts?) -> ARRAY` | 多提示批量;`prompts` **必须**是 `ARRAY`,元素**必须**是 `STRING` | 元数错 → `E0022`;类型错 → `E0030`;推理侧失败 → `E0080` | — | R2 |

本包五个成员的复杂度列一律是 `—`:**单次调用的代价由外部推理服务与网络决定,规范不约束上界**。本语言侧的开销只有参数校验与结果构造,不构成可观察的复杂度承诺。

### 9.2 共享失败口径

本包全部失败都是**原生诊断**,不产生 `ERR` 值:元数错 → `E0022`,实参类型错 → `E0030`,推理侧失败 → `E0080`–`E0083`。`ERR` 的产生与消费规则由语言核心册 §8.6 承担,本册不复述。

诊断码语义:`E0080` 请求失败;`E0081` 协议错误;`E0082` 工具错误;`E0083` 上下文错误。

模型名缺少 `provider/` 前缀产生 `W0052`(语言核心册 §11.3):**警告不改变程序语义**,运行不因此中止。

传输与供应商细节(端点、鉴权方式、请求体形状)属实现文档,不在本规范内。

| 失败形态 | 预期诊断 |
|---|---|
| `ASK` 的实参个数不在 2–3 之间 | `E0022` |
| `ASK` 的 `model` 或 `prompt` 不是 `STRING` | `E0030` |
| `ASK` 的 `opts` 既不是 `DICT` 也不是 `NULL` | `E0030` |
| `ASK_STREAM` 的 `callback` 传入函数值 | `E0030` |
| `ASK_ALL` 的 `prompts` 不是 `ARRAY`,或某个元素不是 `STRING` | `E0030` |
| 推理请求失败(**含** HTTP 401 / 403 被拒) | `E0080` |
| 响应协议不符(响应体不是合法 JSON,或缺 `choices[0].message.content`) | `E0081` |
| 工具或凭据**缺失**(端点 / 密钥未配置) | `E0082` |
| 上下文构造失败 | `E0083` |
| 模型名缺少 `provider/` 前缀 | `W0052`(警告) |

**传输侧与响应层的归类**(真实后端;HTTP 状态码 → 诊断码):

| 失败形态 | 预期诊断 |
|---|---|
| 推理请求被拒(HTTP 401 / 403) | `E0080` |
| 其余 HTTP 4xx(含 404 模型不存在) | `E0093` |
| HTTP 5xx | `E0094` |
| 连接失败 | `E0090` |
| DNS 失败 | `E0091` |
| TLS 错误 | `E0092` |
| 响应体不是合法 JSON,或缺 `choices[0].message.content` | `E0081` |

⚠ **401 / 403 的消歧(本册规定,不再两解)**:它们**既是**「HTTP 4xx」(网络梯 `E0093`)**又是**「推理请求失败」(`E0080`)⇒ **归 `E0080`** —— 被拒是**请求失败**,不是协议问题;`E0093` 只覆盖**其余** 4xx。

⚠ **`E0082` 的边界**:它只覆盖**我方**的端点 / 凭据**缺失**(未配置);**不**覆盖服务端拒绝(那是 `E0080`)。

⚠ 网络错误码(`E0090`–`E0094`)的**含义**由标准库册 §10.2 给出(那一节列的是**码的含义**,与本节的**归类**是两件事)。

⚠ 上表描述的是**真实后端**的归类。**mock 后端**(默认构建)不联网 ⇒ 这些形态**不产生**;mock 后端可触发的失败由各成员的 `opts` / 模型名约定的保留 token 决定,那是**实现注**范围(§9.4)。

**实现注(非规范)**:参考实现目前把 `E0081` 用作**认证失败**(HTTP 401 / 403)、把 `E0083` 用作**响应解析失败**(成功体的 JSON 解析不了 / 缺 `choices[0].message.content`)、把 404 映射为 `E0083`,与本节的归类(`E0080` 请求失败 / `E0081` 协议错误)**错位一格**;⚠ **401 / 403 的两解已在本册消歧**(归 `E0080`,见 §9.2 的传输侧表),剩下的只是**实现侧映射未跟上**,登记在一致性册 §5.4(**X-11**,实现待收敛)。

### 9.3 值形状与边界

**`opts` 的形状**:`opts` **必须**是 `DICT` 或 `NULL`,`NULL` 与缺省等价。`DICT` 的键集由实现解释,规范**不**约束其集合。

**`EMBED` 的返回值**:`ARRAY`,元素**必须**是 `FLOAT`。**向量维数由实现固定**,规范不约束(参考实现为四维)⇒ 调用方**不得**假定维数;需要固定维数时**必须**自行校验长度。

**`COMPLETE` 的缺省语言**:`language` 缺省取环境变量 `WLWL_AI_DEFAULT_MODEL`;该变量未设置时缺省值由实现决定,规范不约束。

**`ASK_ALL` 的返回值**:`ARRAY`,与 `prompts` **等长**、**同序**,每个元素是 `STRING`;`prompts` 为空数组时返回空数组。

**`ASK_STREAM` 的返回值**:`STRING`,内容是**整段**文本。当前不按块回调,`callback` 是为真流式预留的占位(§9.5)。

**模型名的 `provider/` 前缀**:`provider/model` 是推荐写法。缺前缀时产生 `W0052`,但调用**仍然成功** —— 前缀只影响路由,不构成类型或形状约束。

### 9.4 示例

下列注释是**参考实现的 mock 后端**输出;接入真实后端时,文本内容由外部服务决定,规范不约束。

```wlwl
IMPORT("ai:ask", ["ASK", "EMBED", "COMPLETE", "ASK_ALL"]);
PRINT(ASK("openai/gpt-4", "hello"));            // [mock:openai/gpt-4] echo (h=0x4f9f2cab) :: hello
PRINT(EMBED("hello", "openai/text-embed-3"));   // [0.17448691538872357, 0.31102464332036317, 0.5540703440909438, 0.28747997253376056]
PRINT(COMPLETE("fn main() {}", "rust"));        // // mock completion for (rust): fn main() {}…
PRINT(ASK_ALL(["a", "b"]));                     // [[mock-batch:0] echo (h=0xe40c292c) :: a, [mock-batch:1] echo (h=0xe70c2de5) :: b]
```

### 9.5 本章特有条款

1. **模型名的 `provider/` 前缀**:`provider/model` 形态是推荐写法。`ASK` / `EMBED` / `COMPLETE` 在模型名缺前缀时产生 `W0052`;警告不改变结果,调用照常成功。
2. **`ASK_STREAM` 的 `callback` 是占位形参**:当前**必须**是 `NULL`,传函数值产生 `E0030`。真流式(逐块回调)尚未落地,本形态**不**承诺块边界。
3. **本包的可见面只有一条路径**:`ai:ask`。旧路径 `wlwl:std.ai` 不再解析,本册不提供兼容层。

**实现注(非规范)**:参考实现(`Laffinty/wlwl` 基线 `46b153b`)的 mock 后端把 `opts` 解析为 `system`(STRING)、`max_tokens`(INTEGER)、`temperature`(FLOAT)三个键,其余键被忽略;`EMBED` 的缺省模型未设置环境变量时取 `"default"`,`COMPLETE` 的缺省语言取 `"wlwl"`。

**实现注(非规范)**:参考实现在真实后端下把 HTTP 状态码映射为诊断码:401 / 403 → `E0080`,其余 4xx(含 404)→ `E0093`,5xx → `E0094`;连接失败 → `E0090`,DNS 失败 → `E0091`,TLS 失败 → `E0092`;端点或凭据缺失 → `E0082`;响应体解析失败(不是合法 JSON / 缺 `choices[0].message.content`)→ `E0081`。⚠ 这些路径在 `real-ai` feature 之内 ⇒ **默认构建与 CI 跑不到** ⇒ 本仓的 CI **不能**给它们作证。

**实现注(非规范)**:本包仍以 `wlwl-std` 的 `real-ai` feature 编译,没有独立 crate 边界与独立分发产物;`real-ai` 门控的是 HTTP 传输层,不是成员 —— 默认构建下五个成员全部可见可导入。

### 9.6 设计依据

**本节为非规范的追溯材料,不构成一致性要求。**

本包由 `wlwl:std.ai` 降级为官方包,前缀取 `ai:`,成员面(名字 / 语义 / 错误码)一字未改,变的是可见面 —— 属须申报的可见面变更(一致性册 §3 的稳定性政策);该变更发生在 v0.11.3,已是既成事实,不属总纲 §0.9 的 v1.0 差异表。

⇒ 本章已结项;形态上的差距(仍在 `wlwl-std` 内编译、无独立 crate 边界、无独立分发产物)按标准库·系统册 §17 登记,零可观察行为差。

`callback` 形参是为真流式预留的占位:实现侧当前整收集为单块、返回整段文本(v0.4 起的既有形态);std 边界的函数值传递尚未对本包启用(ADR-0022 的 `Callable` 注入槽)⇒ 传闭包得 `E0030`;真流式随 P4-D1b-001 立项。

## 10 `agent` —— 代理(官方包)

`agent` 是**官方包**,与 §9 同一裁决:以原生(R2)形态静态编入 `wlwl` 二进制,提供代理任务、工具描述、工具调用、模型选择与上下文存取共五个成员。

导入路径**必须**写 `"agent:task"`(或包名 `agent`)。`IMPORT("wlwl:std.agent", [...])` **不再解析**,报 `E0040`;`IMPORT("wlwl:agent", [...])` 同样不解析,理由同 §9。`agent` **不是** `wlwl:std.*` 命名空间。

裸名 `TASK` 与类型名 `TASK` **不**构成运行时冲突(语言核心册 §2.1):类型名活在类型位置,函子活在值位置。改名(`IMPORT("agent:task", ["TASK": "AGENT_TASK"])`)是为阅读清晰,不是为了消歧义。

### 10.1 成员表

| 签名 | 语义 | 失败 | 复杂度 | 层 |
|---|---|---|---|---|
| `TASK(name, prompt, opts?) -> STRING` | 构造代理任务并返回一段描述文本;`name` 命中内置任务名时用对应的系统提示,否则用通用提示并给 `W0052`。⚠ **不发起**推理请求,也**不发起**任何网络请求 —— 它只在本进程内拼装提示文本 | 元数错 → `E0022`;类型错 → `E0030`。**无其它失败** | — | R2 |
| `TOOL(name, description, params_schema?, returns_schema?) -> DICT` | 描述一个工具,返回工具描述字典(`name` / `description` / `params_schema` / `returns_schema` / `v`);两个 schema 形参**必须**是 `DICT` 或 `NULL` | 元数错 → `E0022`;类型错 → `E0030` | — | R2 |
| `CALL_TOOL(tool, params) -> DICT` `[stub]` | 同步调用已注册工具;`tool` **必须**是 `TOOL` 的返回值,`params` **必须**是 `DICT` 或 `NULL` | 元数错 → `E0022`;类型错 → `E0030` | — | R2 |
| `MODEL(name) -> DICT` | 选择模型,返回模型描述字典(`name` / `provider` / `model` / `capabilities` / `v`) | 元数错 → `E0022`;类型错 → `E0030` | — | R2 |
| `CONTEXT(key, value?) -> v` | 上下文存取:给 `value` 则**写入并返回 `NULL`**;不给则**读取**,不存在时返回 `NULL` | 元数错 → `E0022`;类型错 → `E0030` | — | R2 |

本包五个成员的复杂度列一律是 `—`:**单次调用的代价由外部推理服务与网络决定,规范不约束上界**。本语言侧的开销只有参数校验与结果构造,不构成可观察的复杂度承诺。

**`CALL_TOOL` 带 `[stub]` 标记**(一致性册 §4.4)。该标记的含义是:

- **在公共面内**:该成员的**存在性**、**名字**、**签名**(元数与形参)、**失败口径**;
- **不在公共面内**:该成员的**返回值形状** —— 下面 §10.3 列出的桩回包字段集合是**暂定的**,实现侧**可以**在不递增主版本号的前提下替换为真实实现。

桩状态**必须**由**专用字段**(`mocked: true` + `error_code: NULL`)表达,**不得**挪用网络码。去掉 `[stub]` 标记是一次**破坏性变更** —— 那一步把当时的返回值形状冻结进公共面。

### 10.2 共享失败口径

本包全部失败都是**原生诊断**,不产生 `ERR` 值:元数错 → `E0022`,实参类型错 → `E0030`。`ERR` 的产生与消费规则由语言核心册 §8.6 承担,本册不复述。

⚠ **本包没有发起推理或网络请求的成员**:`TASK` 只拼装系统提示并返回描述文本,`TOOL` / `MODEL` / `CONTEXT` 只在本进程内构造与存取 ⇒ 推理侧(`E0080`–`E0083`)与传输侧(`E0090`–`E0094`)**在本包不适用**;本包唯一的成员特有诊断码是 `CALL_TOOL` 的 `E0082`(工具错误)。⇒ 官方包册 §9 的推理成员才承诺这两组码。

**网络错误码语义**(供 §9 的推理成员与实现侧对照):`E0090` 网络不可达、`E0091` DNS 失败、`E0092` TLS 错误、`E0093` HTTP 4xx、`E0094` HTTP 5xx。

⚠ `CALL_TOOL` 的失败码是 `E0082`(工具错误),`E0090`–`E0094` 是**网络码**,二者不是一回事。

下表中 `E0090`–`E0094` 五行列出的是**网络码的含义**,**在本包不适用**(本包没有发起网络请求的成员)。

| 失败形态 | 预期诊断 |
|---|---|
| `TASK` 的实参个数不在 2–3 之间 | `E0022` |
| `TASK` 的 `name` 或 `prompt` 不是 `STRING` | `E0030` |
| `TOOL` 的 `name` 或 `description` 不是 `STRING` | `E0030` |
| `TOOL` 的 schema 形参既不是 `DICT` 也不是 `NULL` | `E0030` |
| `CALL_TOOL` 的 `tool` 不是 `DICT` | `E0030` |
| `CALL_TOOL` 的 `params` 既不是 `DICT` 也不是 `NULL` | `E0030` |
| `MODEL` 的 `name` 不是 `STRING` | `E0030` |
| `CONTEXT` 的 `key` 不是 `STRING` | `E0030` |
| `TASK` 的任务名未命中内置任务名 | `W0052`(警告) |
| `MODEL` 的名字缺少 `provider/` 前缀 | `W0052`(警告) |
| 网络不可达 | `E0090` |
| DNS 失败 | `E0091` |
| TLS 错误 | `E0092` |
| HTTP 4xx | `E0093` |
| HTTP 5xx | `E0094` |

### 10.3 值形状与边界

**`TOOL` 的返回值**:

```json
{
  "name": "STRING",
  "description": "STRING",
  "params_schema": "DICT | NULL",
  "returns_schema": "DICT | NULL",
  "v": "STRING"
}
```

**`MODEL` 的返回值**:

```json
{
  "name": "STRING",
  "provider": "STRING",
  "model": "STRING",
  "capabilities": ["STRING", "..."],
  "v": "STRING"
}
```

**`CALL_TOOL` 的返回值**(工具执行器未接线时的桩回包):

```json
{
  "ok": false,
  "mocked": true,
  "error_code": null,
  "message": "STRING",
  "params": "DICT | NULL"
}
```

`params` 回显传入的参数;`message` 说明「工具执行器未接线」且**不含版本承诺**(措辞不冻结)。

⚠ 这个字段集合是**暂定的** —— 它是 `[stub]` 标记所指的「不在公共面内」那部分(一致性册 §4.4):实现侧**可以**把桩回包替换为真实实现,替换**不**构成破坏性变更;**去掉** `[stub]` 标记才是。

⚠ `error_code` 是 `NULL`,**不是** `E0093` —— `E0093` 在本章是「HTTP 4xx」的**网络码**,拿它表达「mock 状态」是**语义挪用**;桩状态由 `mocked: true` 这个**专用字段**表达。

**`CONTEXT` 的返回值**:给 `value` 则**写入并返回 `NULL`**;不给则**读取**,命中返回 `STRING`,未命中返回 `NULL`。「没设」返回 `NULL` 与「设为空串」是**两件事**。

**`MODEL` 的 provider 与 capabilities**:provider 来自名字里的 `provider/` 前缀;没有前缀时 provider 为 `"unknown"`,并给 `W0052`。capabilities 按模型名前缀推导:

| 模型名前缀 | capabilities |
|---|---|
| `gpt-4` / `gpt-3.5` | `chat` / `function_call` / `json_mode` |
| `claude*` | `chat` / `vision` / `tool_use` |
| `text-embed*` | `embed` |
| 其余 | `chat` |

**`TASK` 的返回值**:`STRING`,一段描述文本。命中内置任务名时用对应的系统提示,未命中时用通用提示并给 `W0052`。

**实现注(非规范)**:参考实现(`Laffinty/wlwl` 基线 `46b153b`)的内置任务名是 `summarize` / `translate` / `extract` / `classify` / `rewrite`;未命中时使用通用助手提示。

### 10.4 示例

```wlwl
IMPORT("agent:task", ["TASK": "AGENT_TASK", "TOOL", "CALL_TOOL", "MODEL", "CONTEXT"]);
PRINT(TOOL("t1", "desc"));                            // [description: desc, name: t1, params_schema: NULL, returns_schema: NULL, v: 0.4.0]
PRINT(MODEL("openai/gpt-4"));                         // [capabilities: [chat, function_call, json_mode], model: gpt-4, name: openai/gpt-4, provider: openai, v: 0.4.0]
LET(r, CALL_TOOL(TOOL("t1", "desc"), ["city": "Beijing"]));
PRINT(r["ok"]);                                       // FALSE
PRINT(r["mocked"]);                                   // TRUE
PRINT(r["error_code"]);                               // NULL
PRINT(r["params"]);                                   // [city: Beijing]
CONTEXT("k", "v");
PRINT(CONTEXT("k"));                                  // v
```

### 10.5 本章特有条款

1. **`CALL_TOOL` 在工具执行器未接线时返回桩回包**,不执行工具:回包的 `ok` 为 `FALSE`、`mocked` 为 `TRUE`、`error_code` 为 `NULL`。桩状态**不得**用网络码表达。
2. **`CONTEXT` 是「取或存」,不是「存」与「取」两个成员**:一个形参写、一个形参读。
3. **`MODEL` 的 provider 由名字里的 `provider/` 前缀决定**;缺前缀时 provider 为 `"unknown"` 并给 `W0052`。
4. **裸名 `TASK` 与类型名 `TASK` 不构成运行时冲突**(语言核心册 §2.1);`IMPORT` 时改名是为阅读清晰。

### 10.6 设计依据

**本节为非规范的追溯材料,不构成一致性要求。**

本包由 `wlwl:std.agent` 降级为官方包,前缀取 `agent:`,与 §9 同一裁决:成员面(名字 / 语义 / 错误码)一字未改,变的是可见面;形态上的差距与登记位置同 §9。

`CALL_TOOL` 的桩形态裁决:桩状态用**专用字段**(`mocked: true` + `error_code: NULL`)表达,**不得**挪用 `E0093` —— `E0093` 是网络码,借它表达「这里是 mock」既语义错,也与本章成员表自相矛盾。`message` 的措辞不冻结,契约只钉形状与「不含版本承诺」。

`CONTEXT` 收成单成员:一个形参写、一个形参读;「没设」返回 `NULL`,与「设为空串」是两件事。
